# 独立对局内核设计：B1、B2 与 B3

当前实现覆盖B1/B2/B3-1～B3-9与[CONFIG-1](../batches/CONFIG-1-mechanism-parameters.md)。下文早期批次的30ms、5秒等为基线值，现由显式参数初始化；当前格式与约束见[配置v2目录](../interfaces/configuration-v2.md)。包内来源文件保持不可变；配置由离线 Python 工具提取，运行时通过 `ConfigCatalog::load` 启动读取外部清单、校验、展开地形并缓存。清单默认 `config/catalog.json`，可显式指定。配置原文 SHA-256 参与每局身份；运行期间不读取原文件。同进程可共享 `Arc<ConfigCatalog>` 和 PVE cells，World 独立。详见 [配置加载规格](../batches/B3-1-config-loading.md)。

`world` 使用 Rust 类型管理玩家、动作、弹道、目标和资源，所有字段对宿主隐藏。`engine` 管理六类入口、顺序、幂等历史、外部业务责任和冻结输出。`runtime` 是自调度线程与有界 mailbox；Node 阻塞不停止内核逻辑。每个 Runtime 当前拥有一个实例，独立运行时相互隔离。

同一线程依次处理输入和回执；不在等待数据库时持有世界访问权。每个配置固定步依次处理激活/绝对终局、状态到期/身份清理、周期效果、移动、AI、动作提交、弹道、自然恢复、撤离完成和结算意图。伤害中断先于同一步撤离完成，因而同刻受伤不会错误撤离。已生成的弹道保留攻击快照，不重复运行技能因子。

资源、动作、请求、输出使用不同身份。输入严格校验身份后按序号执行，保存有界请求结果；相同 ID 的不同载荷拒绝，超出历史范围的旧序号拒绝。World 释放后冻结业务请求仍可核对，不能以回执复活 World。

发布历史记录独立 readiness epoch 和单调的发送结果。进入后台撤销旧 epoch，新快照不会撤销同轮已经 sent 的旧快照；发送失败只替换最新的一份全量，不能以迟到回执改变已经确定的结果。无参数输入和回执使用严格空结构 schema，防止反序列化忽略多余字段。

外部账本把原责任与查询/对账请求分开。自动尝试最多三次，查询未决或财产写入拒绝时只生成一份关联对账请求。对账提交证明验证原冻结载荷的 revision/提交身份后只应用一次，并同时解除未完成查询；已知提交后的负面查询不能产生新写。单个 B1 实例的业务目录、尝试次数、查询和对账身份均有有限上界。

单人 Draining 不再推进逻辑时间或生成周期快照；普通输入拒绝，等待 I/O 不持 World 锁。关闭保留四个输出槽位来冻结责任和释放 World，避免普通输入背压使 close 无法完成。对账不能履行时保持显式未决；自动期限见 B2-2，本地进程崩溃责任恢复由 B2-3 补齐。

运行时 mailbox 64、输出 256、输入/发布历史 128；B1 原始业务和查询类型有限。输出接近容量时封存实例，不无限缓存。此 profile 是验证配置，尚不构成生产容量证明。

生产调用只有六类。`replay` feature 提供验证用固定时钟；普通构建无宿主推进时钟入口。`kernel-host --verification` 仅在该 feature 下启用加速时钟；逻辑步和规则时长仍与实时模式一致，验证不代表实时容量达标。

当前进程通道绑定使用 JSONL，Node 执行 I/O，Rust worker 独立推进。本地持久责任账由 B2-3 提供；NAPI/库 ABI、生产客户端紧凑协议和全部模式 schema 在后续批次落实。

## B2-1 连接恢复

Engine 将当前连接与不可变 Create 分开保存，避免换代破坏原 create 的幂等身份。宿主生命周期消息仍通过 submit_input 的有限 Action 进入同一顺序队列；认证 principal、前驱、generation+1 和请求身份在 Rust 中校验。成功换代清空旧发布资格、推进 readiness epoch，并以新连接发布完整状态，不重建 World 或重复入场事务。

ConnectionLost 与 Reconnect 调用既有后台保护行为，清移动、中断预提交动作和撤离；已提交冷却保留。Rust 维护 30 秒逻辑恢复期限，重复断线不延期，当前新代 sent/Foreground/ready 后清除。到期走原幂等 close，资产责任仍在 World 外。完整快照新增普攻/技能/后摇截止时间，浏览器据逻辑时间显示冷却。

Node 只认证所有者、分配后继连接并传递生命周期事实。所有浏览器命令和 SSE 带连接身份，在会话队列内校验，旧页不能把输入重新绑定到新代。重连 HTTP 请求有界去重；页面卸载不发起自动重连，传输失败立即进入恢复并关闭旧 SSE，使宿主尽快报告断线。原事件、账本和冻结结果按有界数据保留，Draining/Closed 仅恢复视图。B2-1 本身只提供进程内恢复；后续 B2-3 补持久资产责任，仍不持久恢复 World。

## B2-2 I/O 期限

Runtime 每轮用自身 Instant 单调经过时间调用内部 poll_io，先处理到期责任再处理本轮命令；它与 Engine.tick 的玩法逻辑时间分离，加速玩法不改变 I/O 等待。Operation 保存本次 5 秒期限及查询发起时的原 attempt，合法重试才重新计时。Draining 另记 15 秒 World 保留期限，Frozen I/O 在 Closed/Faulted 后仍可收尾。

静默读取退休为未知读取；写入超时仍是未决，通过原业务 ID 查询并关闭 World。查询超时进入唯一人工核对；无证明不转成成功。旧查询负结果不能跳过新尝试，已转人工后的负结果也不能启动新写或撤销责任。输出容量不足时先走保留槽位关闭 World，I/O 期限保持待处理，空间可用后继续，不丢弃冻结债务。

Preparing 允许认证换代，World 未建立时只受 I/O 期限约束；建立后设置初次/恢复的 30 秒逻辑就绪窗口，未激活超时补偿入场。H5 故障模拟只控制存储是否执行、是否返回和延迟返回，不推进 Rust 时钟或改变奖励。规则、库存和查询/补偿金额仍来自冻结原请求。


## B2-3 本地事务与恢复

Engine 在责任变更的冻结输出上携带 I/O 检查点，包含不可变请求与已知证明，不序列化 World。恢复通过原 Create 能力一次性校验并建立 Closed 实例；失败时保留未初始化状态。共享修为金额函数用于正常终局与恢复载荷校验，防止两处公式漂移。

Node 在 drain 后，先用 SQLite 事务保存整批最新检查点、请求登记和唯一事件，再逐条执行 I/O；事件与余额视图必须在这之后对外可见。库存事务将原业务幂等记录和资产增减一起提交，人工核对的原修正与 Reconciled 证明也在同一事务。SQLite 使用独占连接、WAL、FULL 同步，避免第二进程同时操作或旧进程迟到写。重启只对已退出进程的未提交尝试建立 fence；不存在提交记录本身不能充当事实。

启动恢复所有当前责任后才监听 HTTP。无持久终局的中断局核实并补偿原入场，已冻结终局按原金额收尾，已转人工继续等待原凭据。重启只更新 HTTP 连接代与显示结果；旧快照只作只读展示，不进入新 World。正常发布视图最多每 250ms 保存一次，业务/事件检查点立即提交，避免每个 30ms 快照触发同步写盘。

持久账本按验证实例隔离；旧实例记录保留，新局仍从固定 100 库存开始。生产跨局账户、远程存储隔离、多机接管、磁盘容灾与容量验收不在此批签收。SQLite/检查点意外损坏或配置身份不符时失败封闭，不清空重建资产。

## B2-4 有界调度

会话用 OrderedQueue 替换无界 Promise 链，执行中和排队任务共同计入 64 上限；普通输入与 ACK 只占用其中 56 个，控制任务保留 8 个。错误释放额度，不阻断后续命令；不通过优先插队改变输入顺序。HTTP 连接、消息体和超时另有上限。

IoScheduler 与会话控制队列分开。持久保存请求后，调度其冻结副本执行；最多保留 32 项、执行 8 项、每会话执行 2 项，选择首个可执行项以避免单会话阻塞队首。完成后先保留回执，再在会话队列中送回 Rust；控制队列满、Native 输出满或暂时写盘失败都可在之后继续。异常只映射 unknown，实际未结束的远程写不释放槽，不假装取消。

worker 发送 drain 响应失败时将批次归还 Engine。此时 worker 尚未继续执行命令或 tick，Engine 输出为空，能在原容量内恢复原身份。数据已成功交给调用方后，宿主必须负责持久提交，不能只保留易失内存。

生产适配入口只接收认证身份和冻结 BusinessRequest，不接触 World。当前 SQLite 仍同步执行，验证非阻塞调度使用可挂起/抛错/迟到的参考传输；不据此签收同步驱动隔离、远程存储事务或生产容量。

## B3-1 地图 PVE

首个切片使用迷雾森林全部逻辑格及妖狼原模板，单人固定三狼布局。`export_b3.py` 验证原始资料包 manifest 后导出独立配置；B1 文件不修改。Create 在未初始化时选择已内置配置，错误候选不部分初始化；跨场景恢复必须带回原恢复载荷。

World 保留统一的准入、准备/保护、连接恢复、终局与外部责任接缝，新增内部 Arena 管理地图单元、多个怪物、技能弹道、剑印、资源 itemId 与额外背包。B1 仍走冻结测试场规则；没有 Node 玩法接力或宿主 World 引用。固定 ID 遍历、稳定 A* 邻居/平局规则与同局 RNG 保证可复现。

导航按完整圆形足迹校验，网格 A* 最多展开 16384 项；不存在合法路径时拒绝，不能穿墙走直线。到达路点后才换向，避免拐角提前切换导致卡墙。地形可走、弹道、视线分别判断，速度倍率参与每步位移。玩家 Move/Stop/后台撤销导航，怪物独立处理警戒、呼救、记忆、回防和归位。

妖狼技能与被动由此切片实现其依赖：巡锋弹道/剑印、锁定引导自疗预算、普通伤害吸血、暴击/闪避和自然恢复。死亡取消未提交能力，已发射弹道保留独立寿命。怪物一次性掉落和光球有独立身份与 5 分钟期限，5 秒巡检，不补充。

其他物品逐项记账，死亡按实际非空堆叠格抽取并冻结每项 kept/dropped。SQLite 同事务保存主库存、其他物品、修为和幂等凭据；旧账本没有 items 字段时按空对象读取，不重置既有余额。冻结责任恢复不创建 Arena。

H5 使用跟随视口与可见地形分块缓存，避免每帧遍历整张 65536 格地图；输入仍反算同一世界坐标。启动时锁定场景/操作，避免异步初始配置覆盖用户选择。完整地图机关、原遭遇编排、正式客户端、生产库存和容量不在此切片签收。


## B3-2 普通储物袋

静态普通袋规则/点位放入不可变PVE配置，实例代、开启和重生截止时间仅由Rust Arena持有。OpenChest在同一顺序队列内检查生命/ready/距离/遮挡/施法/撤离与代，准备完整掉落后一次提交；地面容量/落点失败恢复RNG，不能半开箱。ID包含袋身份、代和奖池槽位，重生仅由现有模拟时钟推进，关闭后停止。

箱状态进入完整PveView，旧场景空数组不输出。公开Snapshot继续内联；新增箱列表使OutputBody超过Clippy默认变体差值，显式保留内联类型并以现有有界输出队列约束存储，不添加每次发布的额外Box。

责任恢复仍不恢复World。每个物品上限为冻结击杀的怪物最大产量，加上本配置箱数×有界重生轮数×每轮最大产量；轮数被玩法终局时长约束。CONFIG-1已移除原单堆叠前提，按总容量、逐物品数量和完整堆叠/尾格重建可行选格数，核验配置死亡比例。配置/正文/摘要和库存幂等证明继续按旧契约校验，不能靠重开袋履行旧责任。


## CONFIG-1：机制与参数分层

新schema2配置明确mechanism_version和注册能力，Catalog以严格类型/范围/引用/交叉关系/资源预算替代数值指纹。Parameters与MonsterCombat等结构只在启动时准备，PVE持有共享只读参数和格子。World维护当前HP、背包、箱代和截止时间；Engine维护冻结资产/证明。旧schema1仅由legacy模块按历史支持指纹与冻结默认值解释，不读取新版调参覆盖旧义。

玩家/怪物移动、自然回复、弹道、AI、掉落、死亡与服务期限都从配置消费。运行调度随所选配置步长切换，I/O仍使用独立真实时钟。多堆叠恢复按各物品full/tail格的可能损失计算可行选格数集合，跨物品合并后检查选格总数；零比例/零收益不再靠固定三杀或正修为反推唯一击杀数。所有重试与核对保持原冻结数量。

Node将原raw/hash持久保存，再使用Rust返回的规范化配置供H5展示，包括旧v1的显式参数。H5先加载原会话版本再恢复快照，避免不同地图/上限混用；场景目录动态读取，数量、技能身份/成本、HP/MP、范围/时间与终局断言取配置和权威结果。自动脚本只提交有限玩家意图，投射物飞行期间目标死亡的竞争按权威NO_RESOURCE处理。

CONFIG-1阶段为单模板；B3-4新增多个模板复用同一AI机制，仍有弹道/自疗两种能力角色，不提供任意技能图。未知能力明确拒绝。参数范围、遗留算法/协议常量和宿主工程上限见[目录](../interfaces/configuration-v2.md)。

## B3-3 分层交互与容器

World内部interaction模块提供LayeredProgress，持已完成层、当前层已提交进度、活跃时点与中断原因；不拥有奖励或持久资产。容器各代持有独立进度，一名角色最多一个活跃实例。配置选择即时/分层机制，原配置不变；分层通过能力版本2显式声明，守护通过版本3声明，未知能力拒绝。

OpenChest先验证身份/代/距离/互斥，未解封则启动时钟并停止移动，解封后才进入原原子落地路径。进度在战斗伤害之后推进；正伤害释放本步交互，因此同刻不能先解封后吃伤害。主动移动先校验路径，合法后才中断；原Leave在Arena暂时取出World期间也显式中断，避免遗留活跃状态。Engine close通过World封装取消并动态保留一个额外输出槽，继续保证关闭与冻结责任所需容量。

层完成不触碰RNG/背包/修为，开箱容量失败保留解封并回滚RNG。重生重建进度，旧代取消不影响新代。产量恢复上界包含每轮最低破解时长；新配置上线不改变旧责任的seal/奖池/金额。重启仍不创建World。

H5仅显示SealView、有限输入与事件；无本地进度推进。开始/取消/开启门禁与条形进度来自权威快照；自动流程解封后显式再开，不把解封当作已获得物品。

## B3-4 混合实例与代守护

Catalog在启动校验后把基础/额外模板准备为只读Arc映射。Monster持有自身模板引用、稳定ID、启用标记与可选GuardianBinding；HP/MP、移动/归位、近战/弹道/治疗截止时间、碰撞半径和掉落均按实例模板消费。旧单模板原文与实例ID保留；协议附加字段仅版本3输出。

Arena构造时为所有箱预留max_count槽位，与静态怪物共同受32上限约束。箱代状态包括planned_count、guards_ready、retry_at、blocked_reported及槽位索引。活跃模拟首次冻结概率/数量；后续只重试确定性候选点，验证自身足迹、直线路径和与玩家/活怪/本组的间距。所有计划点齐备才原子启用，受阻无半组怪物或收益；按ai_decision_ms重试，事件每代去重。

OpenChest在原代校验后先检查pending/存活绑定守护，再进入原分层/落地路径；归位不视为死亡。hurt_monster对已死/未启用实例不重复记账，kill_credit、drop_table和drop_orb控制三种独立奖励。守护死亡只释放资格，仍由玩家显式开箱、拾取；解封/未拾取物不进入资产。

箱成功开启后仍从原时点计重生；新代禁用旧槽位，清理其施法/治疗/路径、所属弹道及玩家未提交目标锁定，随后建立新代绑定。已经发出的玩家空间弹道沿用原碰撞规则。槽位容量固定，不随代累积；地面资源ID包含产生它的守护实例身份，避免跨代混淆。

恢复按冻结时间估算各模板静态数与守护有限代数。不计分模板物品不依赖击杀积分，计分模板在已冻结击杀数范围内取逐物品最大可能产量，再加原容器上界；成长上界也使用有界计分种群。所有原守恒、死亡选格、容量和证明校验保留，World仍不恢复。H5脚本等待真实存活实例/待生成计划，不能用“计分击杀=初始点位数”判断战斗结束；实时页面显示本箱本代资格。

## B3-5 一次性区域遭遇

配置声明区域、怪物实例、必杀目标和奖励箱关系；Arena在构造时为每组预留固定Monster槽位，未启用实例HP=0/enabled=false，不参与快照、目标选择、碰撞或AI。所有槽位仍计入32预算，终局计分与资源产量也纳入全部遭遇实例；同World运行期间不增加Vec容量或复用遭遇身份。

encounters模块持dormant/spawning/active/completed、槽位、retry_at和一次受阻标记。权威移动先推进，再按步检查触发；前台/ready/存活/非保护且不在撤离引导才允许触发/生成。固定点位整组检查地形、各自半径、玩家/现存活怪避让，全部可用才原子启用，不使用随机流。触发后离开仍等待重试，受保护时暂停遭遇状态推进。

战斗之后检查指定实例的真实死亡；不计分目标也能完成，其他怪/组与归位不贡献。最后目标死亡且玩家仍可操作时一次完成，解锁绑定箱。完成不改箱代、RNG、背包、掉落或积分；原OpenChest在代校验后增加EncounterLocked门禁，解除后复用原守护/分层/落地链。箱重生保持一次性遭遇完成，敌人尸体和已经发出的弹道仍沿用各自生命周期。

H5读取权威阶段/目标数显示触发圈与箱锁，前往区域和一键流程只提交有限玩家意图。自动战斗同时等待守护pending和遭遇spawning，不能用零个初始敌人判断任务已完成。刷新同一World不重建状态；持久恢复继续使用原raw/hash与混合种群上界，Closed无遭遇运行态重建。

Engine在World步结束后、发布任何该步事件前，按实际事件数加冻结业务/发布余量核验剩余输出容量。多个遭遇同一步触发可超过原固定16预留，超过容量时走既有QueueFull故障封存，冻结权威资产并回收World；不先部分发事件再触发断言。32/64容量与8遭遇同时触发有专属验证。

## B3-6 波次控制与旧单组兼容

EncounterConfig用旧单组或显式waves二选一，提供group/all_monsters/all_required的只读访问；旧原文不转换，旧DTO省略波字段。Catalog检查波能力、严格结构、各波目标/模板、波ID和全局怪物ID、间隔/总时长、同波间距与全部未来实例预算，地图检查覆盖后波自身半径/路径。

Arena为每一波分配独立预留槽位，保存总槽位和分组索引、当前波、完成波数、绝对ready_at及本波受阻标记。先安排再到期整组生成；最后指定实例死亡后一次提交本波完成，并安排下一波。后波只在之后的prepare阶段生成，零间隔不递归；最终波才解除整个遭遇箱锁。

旧敌人、尸体、资源和已提交弹道继续原生命周期，不删除或重新绑定槽位，跨波同坐标也不能让旧死亡/目标锁定冒充新实例。前波非必杀敌人可阻挡后波，清障后按原波恢复；待生成重试不重新安排deadline、不消耗RNG。保护期间逻辑时间继续，prepare/advance的资格门禁暂停生成与推进，恢复同一World沿用原时点。

混合种群、逐物品和成长恢复上界汇总全部波次一次性产量。Engine继续对World步实际事件批量检查输出空间，波事件峰值超容量走冻结资产的受控封存。H5只展示权威wave和截止时间，自动玩家等待Waiting状态、生成受阻时让位，不以当前场景暂无活怪判断遭遇完成。

## B3-7 每实例Boss阶段

共享Arc模板保存只读Boss阶段表，Monster持boss_phase与boss_epoch；普通怪使用原combat间隔/概率，Boss通过统一访问器读取当前阶段覆盖值。正伤害完成且HP>0后按整数乘法选最深满足阶段，不额外抽随机数；一次伤害至多一个阶段事件。致死沿原取消施法/治疗、掉落/计分与波目标完成链。

切换只改索引，已有next_attack、next_decision、casting、heal、recovery和技能CD/成本保持。进入returning仍按原机制取消未提交施法/治疗；只有原home完成分支调用Boss重置，满血/phase0/epoch+1并按初始间隔重排近战，灵力和技能CD不返还。阶段能力与kill_credit/drop_orb/drop_table解耦。

视图与事件走原有发布/重放路径，额外事件仍受Engine实际输出长度预算封存保护。静态/遭遇/守护统一构造，守护新代使用新身份并重新初始化阶段。阶段表不扩大实体/资源/恢复产量，重启不保存World阶段；原版本raw/身份和Closed责任继续恢复。

## B3-8 积分账本与恢复

Arena以BTreeMap记录实际死亡的template_id→次数，最多base+16种额外模板；仅机制7的首次HP归零更新，不抽RNG或改变原掉落顺序。只读模板提供有效分值，root是缺省值，kill_credit=false强制0；旧World.kills保持计分击杀语义。快照由Rust派生实际数/计分数/积分和撤离/死亡预览，不提前发修为。

终局把有序模板次数及汇总冻结到CommitSettlement.scoring，原资产转换按累计积分一次floor，结算事件转发相同摘要。恢复先校验模板/次数/生成预算和总数/积分/修为，再以各模板真实次数校验物品产量；不通过修为猜测击杀，支持0积分/0系数和非计分物品。旧机制正文省略scoring，原checkpoint序列化与哈希保持，继续旧校验。配置能力、分值和全生命周期加权成长预算在启动验证；变更不重解释既有raw/hash责任。

新事件继续受实际输出长度预算保护，故障封存同样冻结新积分摘要；有限摘要不增加实体/资源预算。H5仅渲染Rust状态、预览和冻结结果，重启中断退款没有已结算积分面板。

## B3-9 锁点范围技能

共享模板保存AreaSkill，只读配置；Monster独立持area_cast/area_ready/area_sequence，不改旧两槽数组。既有AI决策先检查新能力；条件满足才抽其概率，启动时锁定玩家中心、扣成本并排CD，停止施法者移动/新动作。无area模板立即回退，不改原AI随机序列。范围技能与原casting/heal互斥，普通伤害和阶段切换保留已提交圈。

每步先原玩家移动，再按deadline判定一次固定圆/玩家足迹相交与blocksProjectiles效果通路；施放门禁使用blocksVision。先移除活动圈再调用原hurt_player，避免重复结算或致死取消重入。判定后进入后摇，本步不启动新动作；技能伤害/取消不产生击杀积分或掉落。原命中含0伤害会中断撤离，封印仅正伤害中断；阶段、积分与资产规则独立。

归位、死亡、保护/接管、终局和代替换清除活动圈，不返MP/CD；新守护代从新ID/序号1初始化。多圈保护/关闭取消聚合为≤32身份的一条事件，World.close_interaction_event_budget分别计封印/圈的事件空间；tick事件峰值仍以实际长度封存与回收。终局结算兜底清圈，预警不保存进Closed责任，H5只根据权威状态和连接/保护状态绘制等距椭圆，不在倒计时归零时本地扣血。

## B3-10 目标依赖、调谐和消费账

配置装载期验证有界遭遇DAG与主目标依赖闭包。Arena.prepare_encounters先采样未完成前置，再沿原整组/波次状态机推进；完成仍由指定实例实际死亡决定。Arena持有attuned/attune_finishes/中断原因，每局最多一个调谐，与原分层破解互斥并复用所有interrupt_unlock生命周期入口。正伤害先取消，再在战斗结束后执行到期检查；扣费和背包修订一次提交，参数来自不可变配置。

结算从已完成遭遇、单次调谐、主箱状态生成map_progress。内存背包保存剩余量，冻结构建时把原成功消耗加回looted得到累计拾取；根物品沿原World.looted记录不额外加。死亡抽格采用剩余量。恢复验证配置成本、完成集合及击杀下界，再用扣除消耗后的数量做容量/死亡校验；已耗尽物品也须有冻结行。主箱只开一次，不消耗新的代身份，预留/掉落/分数/输出峰值仍受原预算控制。

## B3-11 同组有限治疗与直接接触来源

可选SupportSkill为只读模板，实例持有cast/used/ready/sequence；Arena持有当前玩家的全局打断冷却。目标使用既有encounter_id或GuardianBinding，稳定ID及Boss epoch防止跨代误用。比例用整数交叉乘法排序，开始固定目标与总预算；AI原决策优先支援，再回退范围与旧技能。准备/引导与移动/其它施法互斥。

PendingAction.accepted_at由权威输入时钟产生，随玩家Shot.manual_started传播；怪物/非直接命中没有该来源。hurt_monster_contact在闪避/免伤过滤及实际HP应用后，只对存活施法者检查打断；致死走成员死亡清理，0伤害合法接触仍可打断。玩家弹道全部处理之后才advance_supports，因此同刻命中/死亡先于治疗。一次一跳、首跳提交、余数均分、严格目标重验；准备取消未提交，已提交取消不回滚。后台/关闭/归位/成员死亡/守护代替换覆盖所有入口，批量失效/资源取消和关闭聚合有界。

机制10玩家路径在原静态地形A*中加入当前中途活怪足迹；目的地内目标保留接近约定。动态阻挡使路径不可得时回退原静态接近，逐步碰撞始终权威，不通过穿怪解决拥堵。旧版本、怪物AI路径与无能力时的随机消费保持。

## B3-12 锁定扫掠与一次反击

每个怪物至多一个HeavyCast，与支援、圆形范围、旧施法/自疗及后摇互斥。World先执行玩家真实移动和直接弹道，再推进重击，避免同刻杀死施法者后仍释放攻击。重击冻结起点/方向/实例epoch/伤害，准备后一次提交MP/CD，之后按累计逻辑时间扫掠圆形前锋；接触记为命中，即使实际伤害为0。视线、步行与弹道阻挡各按原地形语义。

Arena只保存一个CounterWindow；正常躲避完成按稳定怪物ID顺序授予，不覆盖/延长已有有效窗口。冻结目标槽位/ID/epoch与开启时atk计算的追加原始伤害。原动作接纳时间证明主动输入，合法直接命中取走窗口后，普通伤害和独立追加物理伤害调用同一apply_monster_damage路径；追加没有新的闪避/暴击或派生回调，致死仅计分/掉落一次。普通先致死则追加0仍消费一次。

后台、归位、成员死亡/换代、终局与关闭清理瞬态，准备取消不扣费、提交后保留成本/CD。关闭预留一个聚合清理事件，拒绝不部分变更。恢复层不保存战斗窗口，不新增数据库业务。范围与验收见[B3-12](../batches/B3-12-heavy-counter.md)。

## B3-13 整组复位与稳定收益槽

Encounter持有单调round、可选reset_at及按保留槽位索引的死亡总数/最后死亡轮次。玩家移动后，先判返回/脱战/到期，再进入本步生成、AI、旧弹道和治疗。计时期间整组回防并暂停自然回复，单个成员不再自行回满或重置阶段；取消计时保留本轮状态，到期重建全部槽位并回Dormant，按原净空和波次间隔重新入场。

PendingAction与玩家Shot保存接纳时各遭遇轮次，旧动作对新轮目标不参与碰撞/结算，未换轮的其它目标仍可命中。复位清除本组敌方弹道、支援/范围/重击/反击与来源剑印层。稳定ID保留，epoch递增，能力序号继续单调，首次收益账本跨轮保留，死亡/完成按当前槽位真实状态推进。地面资源保留，重复恢复光球ID带轮次，物品奖池只抽首次死亡。

已有ScoreSummary继续冻结收益击杀，reset_progress补充实际死亡及本轮完成证据；两者按模板首次记录和原非复位生成上界交叉核对，复位能力不会放大物品/成长上界。Node继续提交Rust给出的原正文，不判断轮次或奖励。关闭预留有界计时取消事件，输出拒绝无部分写入，故障封存后不再生成新轮。范围与验收见[B3-13](../batches/B3-13-encounter-reset.md)。


## SDK-5-5 周期效果边界

状态容器持有周期计划和游标，World按计划时刻与实例ID顺序消费，Runtime仍只有原固定步时钟。首个注册效果为physical_damage；配置提供间隔、时长、ATK比例及refresh/ignore，World读取来源/目标身份、施加时有效ATK和执行时DEF/护盾。周期计划不包含地图ID或宿主回调。

周期跳复用物理伤害、护盾、HP阶段、死亡和掉落路径，绕过主动接触触发与伤害随机数；HP损伤才中断相应交互/撤离。所有临时计划随状态生命周期清理，资产检查点不承载战斗时钟；重连继续同World，重启只恢复冻结责任。约束与顺序见[PD01～PD10](../batches/SDK-5-5-periodic-damage.md)和[周期接口](../interfaces/periodic-damage-v1.md)。HOT或其它周期策略需另注册与验收。


## SDK-5-6 共享周期队列与HOT

同一个状态周期队列现在注册physical_damage和max_hp_heal两种有限效果，按计划时刻、效果优先级（DOT先HOT）、实例ID排序。HOT在自身提交时冻结基础maxHp比例，执行时读取当前HP缺口；满血/零量记录0，死亡/失效状态先移除。实际回复只改变HP，不走主动接触、伤害或支援打断路径，所有临时状态沿原回收边界清理。接口与验收见[周期治疗](../interfaces/periodic-healing-v1.md)及[HT01～HT10](../batches/SDK-5-6-periodic-healing.md)。
