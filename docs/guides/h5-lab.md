# H5 对局验证台

本工具用浏览器操作Rust内核的B1/B2/B3与CONFIG-1已实现切片。H5 只发送操作、绘制冻结状态与事件；Node 执行网络和受控库存 I/O。移动、碰撞、攻击、弹道命中、掉落、撤离时序、连接代/保护/离线期限与结算均由 Rust 内核裁决。

B2-2 已补外部业务超时：基线自动I/O等待5秒、结算World最多保留15秒；CONFIG-1可由params.runtime配置。两者按真实经过时间计时；「加速」只加速玩法和逻辑重连窗口。业务始终未知时会显示关闭但待核对，不把未知结果显示为成功。

## 启动

需要 Rust/Cargo、Node 22；无需安装 npm 依赖。在工程根目录运行：

```sh
npm run h5
```

打开 [本地验证台](http://127.0.0.1:4173)。默认只监听本机回环地址。端口可通过 `npm run h5 -- --port 4174` 更换。

## 手动验证

选择「实时 · 手动操作」，点击进入试炼，再点击场景以获得键盘焦点。

| 操作 | 控制 |
|---|---|
| 移动 / 停止 | WASD 或方向键按屏幕方向移动；松开停止。手机尺寸下按住触屏箭头移动，抬手停止 |
| 普攻 | Space 或普通攻击按钮 |
| 断金手 | Q 或技能按钮；鼠标指向决定方向，未指定时面向可见目标；按钮显示 Rust 给出的剩余冷却 |
| 拾取 | E 或拾取按钮；请求最近可见资源，资格/距离仍由内核判断 |
| 撤离 | R 或申请撤离；激活后逻辑时间 180 秒开放，107 距离内进行 5 秒读条 |
| 保护与恢复 | 保护暂停 / 恢复前台；窗口失焦、切后台也停止移动并提交保护输入；恢复后重新确认本轮快照与 ready |
| 终局 | 放弃本局按死亡处理；关闭并结算立即释放世界并保留必要的冻结结算责任 |

右侧可观察入场扣除后的仓库 95、局内材料数量、一次扣费/结算次数、未决责任和 World 存活状态。事件栏显示真正发生的提交、伤害、拾取、外部请求和回收；动画仅作展示，不计算命中。

## 等距地图

场景使用 2:1 菱形等距视角；`web/isometric.js` 统一正反投影和视口适配。地面世界坐标先变换为 `u=x−y, v=(x+y)/2`，再缩放、平移到画布。鼠标位置反算为世界点，减去权威角色位置形成瞄准方向；键盘与触屏的屏幕方向也先反算为世界方向，再由内核归一化。

地图边界、网格、障碍足迹、角色脚点、掉落和指向线共享同一套变换。地面圆形范围显示为椭圆；角色标记保持直立，障碍显示高度只参与绘制，不改变碰撞；角色、掉落和分段障碍按脚点深度排列。窗口缩放和手机尺寸下重新计算适配，不改变地图距离。地面网格使用画布缓存，保留实时同步与平滑显示。

B1 使用测试场，B3-1 使用迷雾森林逻辑格子，碰撞由 Rust 根据地面足迹与地形判定。地图从启动清单读取，二维地面通过 H5 等距投影显示。地形高差、坡道和多层通行尚未交付；其后续接入遵守 [PRD §3.7](../../PRD-367-independent-rust-match-kernel.md)。

SDK 0.172.0 起上述 2:1 视角仅用于正交权威格网的显示投影。配置声明 `pve.isometric_grid` 时，世界坐标本身就是菱形布局：`projectionFor` 选择恒等 `plain` 投影，`toWorld`/`tilePolygon` 按内核 `to_world` 给出地块顶点，地面圆形显示为正圆，键盘与点击直接沿世界轴。协议 6 双席参考页（delta）两种模式都支持，等距契约见 [世界几何](../interfaces/world-geometry-v1.md)。

## 快速闭环与故障

点击「一键验证闭环」，浏览器作为脚本玩家按公开接口完成：创建/准入 → 加入/快照/ready → 移动 → 普攻 → 断金手 → 拾取材料/光球 → 等待开放 → 撤离读条 → 原子结算 → 关闭。

此模式使用 Rust 已有的加速验证时钟，同时加速整场模拟；没有浏览器 tick、阶段推进或世界字段修改接口。结束时核对账本与Rust权威结算一致、一次入场/结算、World和未决责任归零；固定102/30或三杀45只在具名基线验收脚本中断言。请保持页面在前台。

外部业务选项：

- 正常存取：本地 SQLite 事务按原业务身份执行，余额和幂等凭据原子落盘。
- 模拟结算回执丢失：宿主已提交但报告 unknown，Rust 查询同一业务 ID，只应用一次。
- 模拟存储拒绝：停止在明确未决状态，仓库仍 95，结算次数仍 0；点击核对后按原冻结意图提交，不重算奖励。也可先关闭 World，再核对责任。

另可选择读取/扣费/结算一直不响应、扣费/结算成功但回执完全丢失、查询不响应和补偿不响应；Rust 会自行超时、查询和保留核对责任。读取延迟 1 秒用于验证异步准入及中途刷新；结算延迟 6.5 秒用于验证 World 关闭后的迟到提交。人工先核对后迟到的原写入也按同一 ID 去重。

「关闭并结算」可取消正在运行的自动操作。存在未决财产责任时禁止创建新局；先核对完成，再开始下一次验证。每次新实例使用独立测试账本，初始仓库重置为 100。

## 接口和资源

本地 API 只接收有限操作，身份/对局/连接由宿主绑定；浏览器不能指定战斗属性、扣费/奖励金额或世界补丁。浏览器按原序号/请求身份提交操作，快照应用并绘制后回传确认，再提交 ready。

状态通过 SSE 提供，输入和应用确认通过同源 HTTP 提供；Node 的轮询只取冻结输出，Rust 自调度。每个浏览器所有者最多一个验证实例，全局最多八个；发布历史、未确认快照和响应缓冲有上限。不同浏览器所有者不能读取/操作对方的实例。

实时模式每个 30ms 逻辑步发布状态，画面在相邻已收到的位置之间插值，不预测命中或推进世界。场景角落显示实际接收的同步频率。输入与快照确认使用独立的浏览器发送队列，界面更新合并到动画帧，账本仅在变化时推送。一键加速验收不会改变下一局手动操作的时钟选择。

## 刷新和断线恢复

刷新页面会恢复同一 MatchKey 和同一 Rust World，保留角色位置、背包/修订、战果、掉落和已提交技能冷却，不再次扣入场费用。短暂断网后页面自动恢复，自动验证脚本会停止，可手动继续。恢复后必须收到新代完整状态并就绪，才重新开放操作。

断线由宿主报告给 Rust，角色停止移动并受保护，未提交动作和撤离读条中断。对局时间和冷却继续推进，HP/灵力按原规则自然恢复。断线或新连接未完成 ready 最多保留 30 秒逻辑时间；超时执行原有死亡结算/未激活补偿并回收 World。加速模式同样加速这个窗口。

同一浏览器的新标签页接管当前局后，旧页显示「已由新页面接管」并停用操作；活跃局换代后，旧连接的输入、确认、关闭、核对和替换新局请求均被拦截。当前页的连接代显示在页脚。关闭状态和待核对责任也能刷新恢复，核对不会再发一次奖励。

HTTP 输入、确认、关闭和核对携带 `connection`；SSE URL 绑定连接 id/generation。`POST /api/sessions/:id/resume` 只接收原连接与 requestId，由同源所有者认证后换代；重复同一请求不再次换代。替换一局还需提交 `previousConnection`，避免旧页关闭接管后的对局。

账本默认保存在 `.local/h5-lab.sqlite`，可用 `npm run h5 -- --state /绝对路径/lab.sqlite` 指定位置。重新启动后，原浏览器恢复结果或待核对责任；未持久冻结终局的中断局，确认已扣费后按原入场请求退还物品和寿元（基线5份玄铁/1年），战斗现场关闭。已冻结终局按原金额收尾；待核对仍须处理，不因重启变成成功。

同一状态文件只允许一个宿主进程；运行测试时使用独立临时文件。保留 SQLite 及其 WAL/SHM 文件，不要在运行中移动或替换。每局仍使用独立的初始 100 份玄铁。此处完成本机进程退出后的责任恢复，生产库存服务、多机接管、战斗热恢复和现有生产客户端接入仍待后续验收。范围见 [B2-3](../batches/B2-3-durable-responsibilities.md)，专项命令为 `python3 scripts/verify_durability.py`。

## 并发与慢外部服务

宿主按有界队列接纳输入，超限返回 QUEUE_FULL；未接纳的请求不会执行。普通输入与 ACK 共用 56 个位置，总 64，并为关闭/回执等控制任务保留空间。慢客户端积累超过 128 个未确认发布时会断开，并按已有换代规则恢复。

外部业务在独立调度中执行；慢远程 Promise 不堵住本局关闭或另一局的控制队列。核对按钮仅确认请求已提交，仍以内核确认、账本与未决责任状态判断完成。本地 SQLite 的同步磁盘操作仍可能阻塞 Node；远程驱动隔离和真实库存服务须另验。`python3 scripts/verify_flow_control.py` 可复现并发、慢写、迟到写和错误凭据场景，见 [B2-4](../batches/B2-4-flow-control.md)。

在“场景”选择“迷雾森林 · 三只妖狼”，再进入或点击“一键验证闭环”。首次加载和恢复期间控件会等待初始化完成。默认仍为原测试场，旧验收可继续使用。

刷新恢复同局怪物/物品/冷却；服务重启只恢复结果或责任，战斗中断仍按原入场补偿规则处理。当前为固定三狼单人布置，地图宝箱与机关尚未启用。批次范围及验收见 [B3-1](../batches/B3-1-map-pve.md)，运行 `python3 scripts/verify_b3.py` 可复现。


## 修改地图配置

清单默认 `config/catalog.json`，也可用 `npm run h5 -- --configs /绝对路径/catalog.json`。将 `b3-1.json` 复制为同目录中的新文件，修改地形格子、通行/速度、出生/撤离点或三只怪物点位，并将清单 `active["b3-1"]` 改为该相对文件名。保留原导出文件可继续执行来源哈希校验。

仅换图时可直接运行 `node adapters/h5/server.mjs --configs /绝对路径/catalog.json`，无需重编译；`npm run h5` 也会检查构建，但地图没有编译进二进制。先用 `./target/debug/kernel-host --configs /绝对路径/catalog.json --catalog` 检查有效性。地图需符合当前格式、足迹和 PVE 连通性要求；技能、掉落和结算规则暂保持现有批次，未支持的机制会拒绝。

修改原文件不会影响已启动服务，重启后新局采用新地图。H5 持久保存旧版本，已有结果和待核对责任继续显示/使用原地图；运行中的战斗仍遵守中断退款边界。配置专项运行 `python3 scripts/verify_config_loading.py`，限制见 [规格](../batches/B3-1-config-loading.md)。

## CONFIG-1 参数验证

场景菜单从启动目录读取；HP/MP上限取Rust快照，技能身份/耗蓝/CD、拾取/撤离范围、开放/读条时长和重连期限来自该局配置。恢复旧结果时先加载原版本配置再应用快照。自动PVE按配置实例数量战斗/开箱/拾取并与权威结算核对，不要求固定三杀/45修为。配置应提供可完成的验证布局与足够背包；自动脚本不是任意难度配表的通关保证。

复制已有schema2文件、修改参数/ID并更新catalog，直接用现有 `kernel-host --configs ... --catalog` 检查，重启Node采用新参数即可。完整字段/单位/范围和启动示例见[参数目录](../interfaces/configuration-v2.md)。原导出基线仍可独立核验，旧raw/hash保留用于历史责任恢复。

`python3 scripts/verify_parameters.py` 使用同一个二进制验证1怪/5怪/不同格边、技能身份与成本、零成长真实物品、跨堆叠结算提交前后强杀、死亡策略/堆叠换版和旧schema1责任；专项截图与报告在 `artifacts/parameters/`。此工具仍使用每局独立测试库存，当前全局8个所有者是宿主工程上限。

## B3-3 分层封印

选择“迷雾森林 · 封印容器”，靠近后F启动/继续，Escape或“取消破解”取消；移动、正伤害和连接保护也中断。层数、当前层进度和中断原因来自Rust SealView；已完成层保留，当前层按配置比例保留。全部解封后再F开启，奖励先落地，E拾取后才进入结算。

一键流程会先完成战斗，再逐箱破解、显式开启、拾取并撤离。完整原玉匣的守护/优先领取另批交付，本场景是使用来源封印时长与奖池的独立测试容器。刷新同一World会中断且保留配置允许的进度，需要再次启动；进程重启只恢复Closed资产/结果，不恢复破解现场。

运行 `python3 scripts/verify_b3_3.py` 验证24项新增Rust边界与13项浏览器/进程检查。规则和U01～U08见[B3-3](../batches/B3-3-layered-container.md)，结果与截图见 `artifacts/b3-3/`。

## B3-4 守护容器

选择“迷雾森林 · 守护容器”。面板显示每箱的代、待生成或剩余守护数；待生成/守护存活时开启按钮禁用，公开操作同样由Rust拒绝。击败该箱本代全部守护者后，F开始破解、全部解封后再F开启、E拾取，最后撤离。守护归位或击败别箱守护不能解锁当前箱。
