# SDK 性能收尾：微基准确立、容量架构事实与 25 分钟长稳（0.184.0）

2026-11-12，SDK 0.184.0。接 [流式序列化优化](perf-streaming-2026-11-12.md)，补齐性能闭环的测量基座与长稳数据。非 R6.3 验收（profile/阈值仍待宿主登记）。

## 微基准与回归门禁的载体

- **载体确定为 Node 真实协议栈**（release kernel-host + `TwoMemberHost` + SQLite 账本闭环），指标为输入 RPC 往返、drain 耗时、积压、CPU、RSS——即 [A/B 验证](perf-streaming-2026-11-12.md) 的既有口径。同机复跑即回归对比；本机当前基线即该文三档表。
- 尝试过 Rust 进程内直驱（公开 API `Runtime`/`Client` 完整走 create→准入→join→foreground→ready 握手）：握手全部打通（ready 恰需 full 发布令牌 + foreground），但激活一击后宿主线程把 Fault 原因吞掉（`catch_unwind → fault`），进程外无法取得错误文本，取证成本超收益——已删除该 harness，登记为后续可选工作（如需进程内微基准，先给 runtime 加 fault 原因透出）。

## 容量架构事实

**一个 `kernel-host` 进程 = 一个对局**（`Runtime` 单 `Session` 单 World）。容量扩展靠进程数：

| 进程数 | 总玩家 | CPU 均值 | RSS 合计 | drain p99 |
|---|---|---|---|---|
| 2 | 16 | 7.3% | 18.6MB | 15.1ms |
| 3 | 24 | 8.9% | 27.5MB | 10.4ms |
| 5 | 36 | 14.2% | 46.0MB | 13.4ms |

近线性、单进程远未饱和（sample 显示引擎线程 99% 时间在等待）。crate 层面 `Runtime` 是普通结构体，宿主可在单进程内聚合多实例——当前无适配器演示，属可选后续；对正式容量验收（16/24/36 玩家、2 小时）无阻塞。

## 25 分钟长稳（3 房 × 8 席，30ms 节拍持续输入）

| 指标 | 结果 |
|---|---|
| 时长/迭代 | 25 分钟、48,815 轮（节拍零丢失） |
| 输出 | 351,486 条全部即时排空，无积压增长 |
| RSS | 启动峰值 29.2MB → 稳态 **15.4MB 平坦**；30 秒中位趋势从 21.4MB 单调收敛，后 8 分钟逐点 15,536/15,424KB（回归斜率为负，无泄漏迹象） |
| CPU | 均值 3.7%（满施法 NPC + DOT + 穿透技能持续负载） |
| inputErrors | 112,870 次全部为灵力耗尽后的 cast 业务拒绝（非系统错误） |

## 饱和吞吐（补充测量，同机同日）

去除 30ms 玩法节拍、客户端全速提交 move + 每发一 drain（串行往返，无并发流水）：

| 档位 | 输入 QPS（零拒绝） | 输入 p99 | drain p99 | 输出/s |
|---|---|---|---|---|
| 1 进程（8 席） | **≈3,370** | 0.27ms | 2.6ms | 293 |
| 3 进程（单驱动线程轮转） | 2,073（合计） | 0.39ms | 3.8ms | 827 |

单进程 3,370/s 的上限来自**客户端串行往返**（p50 往返仅 0.074ms，即驱动自身节拍 ~0.3ms/发含 pump），不是内核服务端极限；3 进程合计下降正说明瓶颈在驱动线程轮转而非各内核。输出速率受 30ms 步进天然封顶（每步产出一批），不随输入速率增长。语义上每席有效输入上限为 1/step（≈33/s·席），3,370/s 已是超饱和压力。测试脚本为临时件已清理。

## 结论与剩余

当前合成负载下：计算余量巨大、输出路径已优化、内存无泄漏迹象、容量随进程近线性。剩余性能工作仅有两项——真实 Socket 传输层压测（需 R6.1 环境）与正式 R6.3 长稳档（需宿主 profile/阈值登记）。驱动脚本为临时件已清理，方法与参数在本文与上述证据中可完整复现。
