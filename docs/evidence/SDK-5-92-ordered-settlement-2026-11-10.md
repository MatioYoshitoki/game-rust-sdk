# SDK-5-92 末次入场与顺序转换验收

SDK 0.170.0，机制 105，配置 schema 7，协议 6。 [验收范围](../batches/SDK-5-92-progression-modes-and-privacy.md#gp03-末次入场与顺序转换) · [接入契约](../interfaces/settlement-progression-v1.md#末次入场与顺序转换)

冻结宿主提交 `356ce494f5e40ea1a3859a4991dc10acf3e131aa` 的 `applyLifespanCost` 按费用和剩余量取小，并增加等量累计值。`failDaoTrial` 仅处理激活的状态，清空进度、执行扣减，再由终局流程检查耗尽。旧服的奖励公式从区域档位读取标准费用，SDK 保留该默认口径并开放实扣量选项。终局扣减上限 200 从包外资料读取，其他余额、地图及条件使用合成输入。SDK 将耗尽标记在终局提交，未激活场次可完整补偿原扣款。

| 验收路径 | 实测结果 |
|---|---|
| 末次入场 | 标准费用 2，A 的剩余量 1→0，累计 18→19。同席的实扣量通道请求 2，标准费通道请求 4，耗尽标记随终局提交。零余额入场被拒绝。 |
| 终局顺序 | B 标准扣费后剩余 50、累计 20。命中结果和余额条件后，实际扣减 50，累计 20→70，清空资格和进度，再设置耗尽标记。最终进度读取转换后的总量。Rust 另验不匹配的结果、附加条件和空步骤。 |
| 回执与冲突 | 真实 Rust 双席、Node 与 SQLite 验证 B 核心回执丢失后重启，两席各结算一次，附属事实只追加一次，未决责任归零。Rust 拒绝重排步骤后重算摘要的检查点。SQLite 后一步前值冲突时整笔拒绝。 |
| 未激活补偿 | 另一个双席房间在激活前关闭。两席分别退还实扣 1 和 2，恢复累计值及战备，无结算和耗尽标记。 |

Rust 默认与全特性各 120 项、Node/H5 共 242 项通过。格式、Clippy 全目标全特性、最小宿主编译和真实内核构建通过。

实际转世选择与历史封存、生产账户和地图组合仍由宿主接入验收。
