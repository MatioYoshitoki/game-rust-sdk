# B2-4 并发、背压与 I/O 适配验收

日期：2026-11-03。状态：本地受控范围通过。规格和生产接入约束见 [B2-4](../batches/B2-4-flow-control.md)，[机器报告](../../artifacts/flow-control/verification.json) 绑定本轮源码 SHA-256。

## 改动与结果

- 会话从无界 Promise 链改为有界 FIFO：总 64，普通输入/ACK 最多 56，保留 8 个控制位置；超限在执行前拒绝。错误释放额度，后续关闭不受失败命令影响。
- 外部 I/O 从控制队列中分离：总保留 32、并发 8、每会话并发 2。挂起写不阻止其他会话或 Rust 超时/关闭；异常只返回 unknown，由原业务查询/核对收尾。没有通过本地超时伪装远程取消。
- Rust 排空结果的接收者已断开时，原输出批次归还 Engine，保持 ID 与检查点。正常接纳之后由宿主落盘的责任不变。
- 并发重复创建、业务事实和拾取保持一次业务效果；慢客户端超过未确认发布上限时断开换代，无二次准入。
- 核对按钮在异步请求提交后只提示已提交，不提前显示核对成功；最终以 Rust 回执确认和账本为准。

## 本轮验证

| 层次 | 执行结果 |
|---|---|
| 新增 Rust | 5 项通过：排空接收者断开、16 线程重复创建、8 身份竞争、16 线程重复回执、输出饱和后资产责任收尾 |
| 队列/I/O | 7 项通过：控制保留、错误释放、慢请求隔离、异常未知、不变载荷/在途去重、饱和重调度、取消时保留仍在执行的槽 |
| 真实 Rust/HTTP/Chromium | 8 项通过，页面异常 0；见下表 |
| 完整 Rust | 默认/all-features 各通过相同的 99 项测试（61 原有 + 8 重连 + 16 超时 + 9 恢复 + 5 并发），唯一测试数为 99；Clippy `-D warnings` 通过 |
| B1 | 原 12 条 Node 链、2 项 JSONL 协议检查、独立回放、来源包和冻结配置通过 |
| H5 | 4 项等距坐标测试、9 项浏览器功能/性能检查通过，页面异常 0 |
| B2-1/2/3 | 6 项重连浏览器、12 项超时浏览器、19 项强杀/重启验收及 6 项 SQLite 存储测试全部重新通过 |

| 新浏览器场景 | 观察到的行为 |
|---|---|
| 重复拾取 | 96 个 fetch 请求共用原 requestId/sequence，仅一次材料拾取；最终仓库 99、修为 3，一次结算 |
| 同所有者开局竞争 | 16 个请求仅一个创建成功；并发中或缺少新局前驱身份的请求拒绝，无第二次扣费 |
| 挂起结算与迟到写 | 另一局仍可运行和结算；原局超时释放 World，人工核对后迟到旧写仍只结算一次 |
| 挂起读取 | provider 未完成时可先关闭；读取迟到不建立入场或 World |
| 已提交后抛错 | 异常为未知，查询取得原提交证明；不重复发奖 |
| 错误提交凭据 | 错误 revision 未完成资产，超时转核对；匹配证明后才成功 |
| 提交前抛错 | 没有权威未提交证明，保持未知待核对；最终入场/补偿各一次、仓库 100、寿元扣除归零 |
| 客户端不 ACK | 超过 128 项未确认发布后断开换代；准入仍一次，关闭后一次结算 |

浏览器 fetch 受连接池限制，本轮重复拾取场景的实际会话队列峰值为 6；不将 96 个请求称为 96 个同时执行的服务端任务。满队列拒绝、控制保留与 I/O 饱和由确定性单元测试验证，不据此声明生产吞吐量。等距实时样本中位同步间隔约 31.3ms、p95 60.7ms，按键到权威位置约 47.8ms、无长任务，均在既有验收门槛内；样本见 [性能数据](../../artifacts/h5/performance-isometric.json)。
