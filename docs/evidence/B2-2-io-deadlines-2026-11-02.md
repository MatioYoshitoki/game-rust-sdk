# B2-2 外部业务超时受控验收

日期：2026-11-02。结果：**16 项 Rust 边界与 12 个真实浏览器故障场景通过，页面脚本异常 0**。规格见 [B2-2](../batches/B2-2-io-deadlines.md)，完整实测值和源码 SHA-256 见 [机器报告](../../artifacts/io-timeouts/verification.json)。

实际运行 `python3 scripts/verify_io_timeouts.py`。使用真实 Rust kernel-host、公开 HTTP/SSE 和受控存储；没有推进内部阶段或任意改写世界。自动 I/O 期限使用真实 5 秒服务时间，结算 World 保留使用真实 15 秒，玩法加速不缩短它们。测试服务已退出。

| 浏览器场景 | 实际结果 |
|---|---|
| 读取始终无回执 | 约 5 秒终止准入；仓库 100、入场 0、未决 0，没有角色激活 |
| 延迟读取时刷新 | 读取延迟 1 秒，准备阶段换代后接续原准入；只扣费/激活一次，随后可正常关闭 |
| 扣费无响应 | 超时后 World=0、仓库仍 100、责任待核对；人工履行原意图后仅一次扣费和一次补偿，最终仓库 100 |
| 扣费成功但回执完全丢失 | 约 5 秒查询到同一提交并补偿；仓库 100、寿元责任 0，不重新创建角色 |
| 关闭后补偿也不响应 | 补偿继续有独立期限，约 10 秒进入核对；证明后归还原 5 个材料和寿元，未决 0 |
| 结算始终无响应 | 约 5 秒回收 World，冻结仓库 95/未付奖励；未决期间不能新开局，核对后仓库 99、修为 3、结算 1 |
| 结算成功但回执完全丢失 | 约 5 秒查询原提交，仓库 99、修为 3、结算 1，无人工修正或重复发奖 |
| 6.5 秒迟到结算 | 5 秒时已关闭且明确待核对；迟到原提交履行一次冻结结算，未决归零，World 不复活 |
| 人工先证明、原写入后到 | 人工证明后再执行迟到原请求，仍按同一 ID 去重；实际结算 1、SettlementApplied 事件 1 |
| 结算与查询均无回执 | 5 秒释放 World，查询再等 5 秒后只提出一次人工核对；原写入尝试没有自动递增 |
| 拒绝后人工一直不处理 | 约 15 秒回收 World，未决责任继续保留；之后仍可核对并只发一次冻结奖励 |
| 创建成功但客户端未连接 | 使用现有加速玩法时钟验证 30 秒逻辑就绪窗口；未激活入场补偿，仓库 100、入场 1、补偿 1、激活 0 |

Rust 测试另外验证 4999/5000ms 边界、玩法 tick 不消耗 I/O 预算、Draining 玩法时间冻结时照常超时、关闭后补偿、无效回执与时钟回退、旧查询不能跳过当前尝试、进入人工后的迟到负结果和准备阶段连接隔离。输出背压测试证明：自动等待和人工等待中的 World 均使用保留槽位先回收，I/O 请求在空间恢复后继续，不依赖宿主及时取输出来释放 World；准备阶段也能先关闭再退休读取。一个普通 Runtime 实测在无宿主时钟/阶段调用下自行超时静默读取。

最终回归：`verify_b1.py` 默认和 all-features 各通过相同的 **85 项 Rust 测试（61 + 8 + 16）**，Clippy `-D warnings`、12 条 Node 成功/故障链、2 项 JSONL 检查、独立回放与来源/冻结配置校验通过；`verify_h5.py` 原 9 项浏览器检查和 4 项等距坐标测试通过；`verify_reconnect.py` 原 6 个重连浏览器场景通过。
