# SDK-5-92 限时存活与分波清敌验收

SDK 0.158.0，机制 105，配置 schema 7，协议 6。验收使用合成输入。 [范围](../batches/SDK-5-92-progression-modes-and-privacy.md#gp05-限时存活与分波清敌) · [接入契约](../interfaces/publications-v6.md#限时存活与分波清敌)

| 验收路径 | 结果 |
|---|---|
| 限时存活 | 截止时按就绪且可参战的存活席位判定。两席受保护时失败。满足最低人数时，未达标一席的失败阶段冻结，达标席进入下一阶段。 |
| 波次 | 成员与旁观视图只在开波后出现本波目标。未开启目标的定向攻击被拒绝，守护宝箱仍锁定。实际击倒第一波后才开始下一波的等待。 |
| 截止优先 | 末波未清时，截止同刻完成前摇的技能无法补交伤害。结果只冻结一次，原阶段无法跨到后续阶段。 |
| 解码一致性 | Rust 复用真实成员目标全量与增量，拒绝换代全量改写对抗标记。Node/H5 成员和旁观解码接受正常波次变更，拒绝波次倒退。 |

普通 Node 宿主使用真实 Rust 进程与 SQLite 跑完两局。通关局一席在存活阶段失败，另一席清除首波、波间重连、继续清除末波。重连前后开波时间和阶段截止相同，失败席的阶段与结果保持原值。胜方获得 9 奖励，核心回执丢失后查询确认，附属事实只追加一次。超时局末波仍存活，两席均失败，实际首波击杀按配置保留 2 奖励。两局各席入场和结算均一次，未决责任归零。

186 条成员发布和 98 条旁观发布通过协议 Schema，分别含 22 和 7 条全量。旁观在等待与开启时收到对应波次状态。

Rust 默认与全特性各 94 项、Node/H5 共 231 项通过。格式、Clippy 全目标全特性、最小宿主编译和普通二进制构建通过。 [Rust 模式回归](../../src/world/two_members/match_mode_contract_tests.rs) · [Node 解码回归](../../adapters/node/replication.test.mjs)
