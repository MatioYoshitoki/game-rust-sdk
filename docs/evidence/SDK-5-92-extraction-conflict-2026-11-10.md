# SDK-5-92 撤离局对抗与零费用准入验收

SDK 0.157.0，机制 105，schema 7，协议 6。验收使用合成输入、普通 Node 宿主、真实 Rust 对局和 SQLite。 [批次范围](../batches/SDK-5-92-progression-modes-and-privacy.md#gp05gp06-撤离局对抗与零费用准入) · [接入契约](../interfaces/publications-v6.md#撤离局成员对抗)

| 验收 | 结果 |
|---|---|
| 零费用 | 三席的可信资产余额均为空。准入没有费用、战备或年龄变更，各提交一次带修订的空明细。A 的准入回执丢失，宿主查询原凭据后正常进场。Rust 与 SQLite 专项测试也验证未准入时迟到的提交及空明细补偿。 |
| 撤离对抗 | B 拾取 2 件物品并开始撤离。A 的定向施法实际打断读条，随后通用弹道击倒 B。B 走独立死亡结算，A 领取原遗物中的 2 件并成功撤离，C 继续在同一 World 战斗。未启用对抗时成员目标被拒绝。 |
| 来源与持久化 | A 的成员伤害和击倒未增加 NPC 积分。C 对原生 NPC 实际扣血 10 和 5，并取得一次 NPC 击杀，获合成奖励 25。重启后三席账本依次为物品 2、空余额、奖励 25，均仅提交一次核心结算。 |
| 发布 | 成员全量与增量保持固定对抗标记，成员目标校验实体代次。13 条实际全量和 63 条实际增量通过成员 Schema。旁观收到 28 帧，公开伤害可见，遗物详情、库存和成长字段未出现在旁观帧。 |
| 重启 | A 的核心结算回执丢失，旧进程查询阶段停止。重开 SQLite 和 Rust 进程后查询同一核心操作，附属事实只追加一次，待处理责任归零。 |

Rust 默认和全特性各通过 90 项，Node/H5 通过 230 项。格式检查、Clippy 全目标全特性、普通二进制构建与最小宿主编译通过。 [Rust 对抗回归](../../src/world/two_members/member_conflict_contract_tests.rs) · [Node 解码回归](../../adapters/node/replication.test.mjs)

该合成组合覆盖对抗、弹道、遗物、成长与隐私共存。具名场景的专属规则、D-05 与 G-03 正式数据、完整生产几何和真实网关仍按既有工作包验收。
