# DELIVERY-05 检查点反制与专属伤害验收

2026-11-10，SDK 0.151.0，机制 105，schema 7，协议 6。使用两组独立合成配置验证计时检查点的手动与自动反制。 [批次范围](../batches/SDK-5-92-progression-modes-and-privacy.md) · [接入契约](../interfaces/publications-v6.md#检查点反制)

| 验收 | 实测结果 |
|---|---|
| 资格与私有发布 | 开窗前、其他席位、错误目标代次、超距离和地图阻挡时，手动反制均被拒绝。有效窗口只给本人，阻挡解除后可继续使用。换代或到期后旧窗口无法结算。 |
| 时间与倍率 | 一级窗口在 30ms 开启，210ms 截止。升阶、保护和恢复就绪保留时点。成功提交时按二级计算 60 点原始伤害，经防御降至 30，护盾吸收 10，实际扣血 20。普通技能继续按自己的配置结算。 |
| 自动结算 | 双席同时达标时，首席扣血 40，次席原始伤害 50 并扣除剩余 25。击杀只归次席一次。普通伤害触发器的回灵未执行，手动请求无法重复触发自动模式。 |
| Node 双场景 | 手动场景普通技能实际打出 10 点，随后专属反制打出 60 点。精确重放成功请求没有再扣血，新请求重复使用被拒绝。自动场景复现 40 和 25 点实际伤害。两局四个席位各提交一次结算。 |
| 配置与协议 | 两个计时配置通过 Schema，错误模式和超范围等级表被拒绝。89 条真实全量或增量发布及 1 条真实反制输入通过 Schema。解码器拒绝同一窗口改时或在消耗后恢复。 |
