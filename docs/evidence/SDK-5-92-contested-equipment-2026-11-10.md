# SDK-5-92 局内装备竞夺与追猎验收

SDK 0.163.0，机制 105，配置 schema 7，协议 6。使用独立合成输入。 [需求与验收标准](../batches/SDK-5-92-progression-modes-and-privacy.md#gp05-局内装备竞夺追猎和撤离转换) · [接入契约](../interfaces/publications-v6.md#局内装备竞夺与追猎)

| 验收路径 | 结果 |
|---|---|
| 争抢与版本 | 两席提交同一节点修订时只接受一席。成功请求重放不推进修订或生成新追猎者。配置校验覆盖未知档案、重复追猎出生点、越界和非实例奖励。 |
| 实际普攻与预留 | 取得的档案改变实际普攻与冷却。宿主在持有期间换装后，永久装备修订递增，局内生效档案保留。持有时预留一个结算格，满格领取失败且节点和 NPC 状态无变化。连续取得两个节点时采用最近取得的普攻档案。 |
| 追猎与转手 | 追猎者只锁定有效持有者，仍可被其他席攻击。连接保护解除锁定，重入后用原实体代次恢复。死亡释放标记并产生可重领的掉落。重领后追猎者使用新实体代次，旧来源无法再伤害拾取者。未重领的追猎者在配置到期时消散。 |
| 发布与隐私 | 成员和旁观全量及增量均能还原节点标记。私有生效档案仅给持有者，未进入旁观或另一席的视图。Node 复制器与 JSON Schema 验证了最终实跑的 41 条成员帧和 22 条旁观帧。 |
| 资产与进程恢复 | Node 宿主使用真实 Rust 进程和 SQLite 执行双席对局。A 死亡结算零实例，B 拾取并撤离后入账一件。B 提交回执故意丢失，重启进程确认原交易，两个账户都只结算一次，未决责任归零。 |
