# DELIVERY-05 多资产成长结算验收

2026-11-10，SDK 0.145.0，机制 105，schema 7，协议 6。GP01 与 GP02 用独立合成输入验收。 [模块范围](../batches/SDK-5-92-progression-modes-and-privacy.md) · [接入契约](../interfaces/settlement-rewards-v1.md)

| 验收 | 实测结果 |
|---|---|
| 独立通道与取整 | 两席各击败一只怪物。撤离席两通道基础分为 13 和 9，申请发放均为 9。第一通道受上限限制发放 3。第二通道的两重倍率一次取整得到 9。死亡席按独立倍率申请 3 和 6，第一通道因原余额已高于上限而发放 0。 |
| 原子提交 | 撤离席在同一事务保留主物品和一件实例，并提交两种奖励。参考宿主余额不符时拒绝整笔提交，库存、奖励与修订均保持提交前状态。 |
| 未知回执和恢复 | 死亡席的持久提交成功后丢失回执。重启查询原操作并收尾。两席入场和结算各一次，入场费用余额均为 99，未决责任为零。最终两席主物品余额为 6 和 4，两种奖励余额分别为 100 和 20、101 和 6。 |
| 反伪造与安全重试 | 仅替换奖励行的前后余额并重算检查点摘要，金额仍自洽，但原准入事实校验拒绝该检查点。证明原事务未提交后，重试使用相同操作 ID 和冻结正文。 |

Rust 默认和全特性各 52 项，Node/H5 220 项。格式、Clippy、最小 Rust 宿主离线检查及历史开关下的源码编译通过。真实 Node 宿主使用协议 6 普通时钟。 [合成回归](../../src/world/two_members/settlement_reward_contract_tests.rs)
