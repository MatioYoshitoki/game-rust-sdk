# DELIVERY-05 结算附属事实验收

2026-11-10，SDK 0.146.0，机制 105，schema 7，协议 6。GP03 的附属事实与入场扣费恢复使用独立合成输入验收。 [模块范围](../batches/SDK-5-92-progression-modes-and-privacy.md) · [接入契约](../interfaces/settlement-facts-v1.md)

| 验收 | 实测结果 |
|---|---|
| 核心门槛 | 核心提交拒绝后只有核心核对请求。确认核心提交后生成一笔附属责任，内容按该结果的配置排序冻结。宿主拒绝缺少核心凭据的追加。 |
| 单独重试 | 第一次追加确认未提交后，第二次沿用原操作 ID 和正文。SQLite 模拟追加事务回滚时，核心库存、奖励和修订保持原结果。重复执行同一操作返回原凭据。 |
| 双成员与恢复 | 两局分别覆盖附属回执丢失和查询超时。第一席的事实已写入，恢复使用原凭据。第二席在写入前中断，恢复隔离旧尝试后只重试其追加。第一席的附属查询超时时，第二席仍能在同一 World 移动。 |
| 数量与修订 | 两局每席入场、核心结算与附属追加各一次。两席入场费用余额均为 99，奖励余额为 14 和 11，账户修订均为 2，恢复后未决责任为零。 |
| 冻结校验 | Rust 拒绝事实内容被篡改、关联核心缺少提交凭据和应生成的附属责任被删掉的检查点。10 个真实业务正文或回执通过 Schema 校验。 |
