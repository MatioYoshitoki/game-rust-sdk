# SDK-5-92 GP03 成长结算验收

SDK 0.155.0，机制 105，schema 7，协议 6。验收使用独立合成输入。规则与结果字段见 [验收范围](../batches/SDK-5-92-progression-modes-and-privacy.md#gp03-成长计算与核心事务) 和 [成长结算契约](../interfaces/settlement-progression-v1.md)。

| 验收路径 | 可复查结果 |
|---|---|
| 入场与补偿 | 剩余额不足时无入场请求。余额恰好用尽可入场，剩余 2→0，已用 18→20。未准入时收到迟到提交凭据，补偿沿用原扣款身份与反向前后量。SQLite 验证资产和战备只返还一次。 |
| 实际扣血 | Rust 战斗解析器验证全盾吸收、部分扣血、超杀、周期排除、单击与局内上限和两席独立计量。普通 Node 消费端通过施法意图实际扣除原生 NPC 生命 10 和 5，得到合成配置的 3 积分，另一席为 0。 |
| 撤离与死亡 | 同一 World 中 A 撤离、B 离场按死亡结算。A 的第一条转换命中，奖励 9→25→12，剩余 0→12，已用 20→18，另一个增长计数 1→2。B 保持已用 20、剩余 7、奖励 9、计数 1。两席各入场一次、核心结算一次，结束时待处理责任为 0。 |
| 仓库与区域 | 按项仓库已满时保留量 1、实存 0、溢出 1。Rust 验证两件局内实例按 ID 只实存第一件。SQLite 验证部分实存、实例分流和区域修订 7→8。旧区域修订、账户修订或余额冲突均拒绝整笔变更。 |
| 冻结与恢复 | Rust 拒绝改写区域后重算摘要的检查点。有效检查点获得未提交证明后保留相同操作 ID 和事务正文，以第二次尝试发出。普通 Node 丢弃 A 的首次核心回执，实际顺序为原结算、查询、追加附属事实。重连仍使用原入场，附属事实只追加一次。 |

持续回归见 [Rust 成长契约测试](../../src/world/two_members/settlement_progression_contract_tests.rs) 和 [Node 持久化测试](../../adapters/node/two-member-host.test.mjs)。普通 Node 路径使用 Rust `kernel-host` 与 SQLite 实际提交。单次运行的合成输入和数据库集中存放并在验证后清理。

Rust 默认与全特性各 85 项、Node/H5 共 226 项通过。Clippy 全目标全特性、最小宿主和启用历史测试代码的编译均通过。普通 Node 双席对局分别用正序和逆序加入，结算与待处理责任相同。历史数据包未用于本次合成验收。
