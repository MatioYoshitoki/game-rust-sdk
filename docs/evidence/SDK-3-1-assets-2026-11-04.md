# SDK-3-1 通用资产事务验收（2026-11-04）

先冻结 [AS01～AS08](../batches/SDK-3-1-assets.md)，再交付 crate 0.2.0 的协议 2 资产边界。[资产接口与运行方式](../interfaces/assets-v2.md)

schema 3 配置成本/收益资产 ID；Rust 冻结有明确用途、有限资产行和版本条件的 Admission、Settlement、Compensation。宿主按原事务一次执行，金额计算、数量守恒、玩法结果和责任生命周期仍由 Rust 裁决。协议 1 配置、请求和旧检查点继续按原义读取，旧责任不会转换成新资产事务。

新增 14 项 Rust 专项。默认与 all-features 执行同一组 626 项测试，Clippy `-D warnings` 通过；B1 的独立回放、12 项 Node 场景和两项 wire 检查通过。后续调整仅涉及 H5 配置加载，Rust 与 B1 输入哈希保持，专项显式校验后复用该 B1 结果。

真实进程验收通过 23 个资产结果阶段与 8 项协议 1 仓库外消费方：

- 完整战斗/拾取/撤离和死亡、激活后关闭；账户变更与 Rust 冻结事务逐项一致。
- 结果 Unknown 查询原证明、带 fencing 的原正文重试、入场拒绝和未就绪补偿；重复调用/存储执行/回执保持一次生效。
- 结算、入场、补偿在持久化前后强杀，连续两次重启保持同一业务 ID、原数量和一次提交；中断局只退入场，不重建 World。
- 被拒绝的结算保留待核对责任，授权核对完成原事务后未决清零，再次重启不重复发奖。
- 更换成本/收益 ID 和成本数量；冻结后再修改配置文件，恢复继续使用原文/原 hash，不改发新资产或重算奖励。
- SQLite 独立验证整批余额不足时原子拒绝，账户没有部分扣款。

恢复篡改专项覆盖资产 ID/数量、重复/乱序行、库存摘要、提交凭据、原入场关联和旧/新正文混用；重新计算检查点摘要仍不能绕过语义校验，拒绝后合法恢复仍可继续。

接入验收暴露验证宿主的全量配置启动开销：B1 Node 宿主现用独立 B1 清单；H5 单局只加载该局绑定版本，启动复用已经过 Rust 校验的配置，账本独有旧版本继续单独校验。运行时 I/O 期限保持。相关配置专项 93 项 Rust/10 项进程与浏览器、原持久化 9 项 Rust/6 项存储/19 项强杀重启、H5 9 项浏览器基线均通过，页面错误为 0。
