# SDK-2 接入契约与最小宿主验收（2026-11-04）

按 [本批八项标准](../batches/SDK-2-host-contract.md) 先更新需求，再交付 [SDK 接入指南](../guides/sdk-integration.md) 和 [独立 Cargo 消费方](../../examples/minimal-host/Cargo.toml)。指南明确六个公开调用、配置加载、宿主输出/回执/关闭责任、错误策略、开发期交付方式与版本兼容要求，并列出修为、入场年限、固定终局、能量/库存事实、具名机制 DTO 和游戏命名空间的现有耦合与迁移约束。

`python3 scripts/verify_sdk_2.py` 已通过，消费方复制到仓库外临时目录构建，仅以精确版本 path dependency 引用公开 SDK；普通调度时钟、不启用 replay。八项消费方验收覆盖：

| 场景 | 结果 |
|---|---|
| 正常接入 | 创建、读取、扣费、加入、收到全量并就绪、主动离开、死亡结算、关闭完成。重复调用/业务执行不重复扣费或发奖。 |
| 结算 Unknown | 先提交账户后隐藏回执，Rust 查询原 operation，返回同一 commit_id/revision，结算一次。 |
| 入场拒绝 | 不扣费、不结算，正常关闭并结束责任。 |
| 未就绪关闭 | Closed 首次明确携带待补偿责任，继续执行原入场补偿，库存和入场年限恢复初值，补偿一次。 |
| 全量发送失败 | 第一份全量 Failed，收到替代全量并 Sent 后才提交就绪，最终正常结算。 |
| 配置不匹配 | 错误 hash 创建拒绝且无业务输出，同一 Runtime 改用正确版本后完成闭环。 |
| 自有默认场景 | 仓库外清单仅 `training-yard` 别名，自有配置 ID，从加载结果取得精确 hash 并完成对局。 |
| 替换账户事实 | 修改初始属性、库存、revision、已有修为、入场年限和种子 JSON，消费方源码及二进制不变，账本按冻结请求结算。 |

八项最终均为一个 Closed、World=0、未决操作=0。默认与 all-features 两种构建执行同一组 612 项 Rust 测试，不将次数相加；根库和消费方格式检查、Clippy `-D warnings` 通过。机器报告含测试名、消费方账户与原业务凭据、源码/配置和消费方二进制 SHA-256。[机器证据](../../artifacts/sdk-2/verification.json)

本批没有更改内核玩法或资产协议，最小宿主以本地接收方和内存账本演示接入流程。生产持久化/鉴权、多游戏语义与隔离、正式包发布仍按对应门禁验收。
