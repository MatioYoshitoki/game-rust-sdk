# SDK 合成基线压测（非 R6.3 验收）

2026-11-12，SDK 0.183.0 release 构建。**合成 profile 短档参考基线**——不是 R6.3/I06 的正式验收：档期时长（120s vs 要求 ≥10 分钟/档、最高档 ≥2 小时）、profile 与数值阈值均未登记，通过与否不作判定。

## 方法

- **被测**：`target/release/kernel-host`（0.183.0，优化构建），每房间一个独立内核进程——参考部署形态
- **驱动**：真实协议 6 宿主栈（`adapters/node/two-member-host.mjs` 的 `TwoMemberHost` + SQLite 账本闭环），完整走 create → 装载 → 准入 → 就绪 → 输入流 → 输出排空
- **负载**：每房 8 席、12 只主动 NPC（1.0 施法率、DOT 弹道）、成员穿透弹道技能（CD 300ms）；30ms 节拍轮转提交每席 move/cast（25% 概率），发布自动回执
- **档位**：总 16/24/36 玩家 = 2/3/5 房 × 8 席，每档 120 秒
- 指标：输入 RPC 往返、drain 耗时（一个 30ms 节拍内排空全部输出的耗时）、积压峰值、内核进程合计 CPU%（ps 采样）与 RSS

## 结果

| 档位 | 房×席 | 输入往返 p50/p95/p99 (ms) | drain p50/p95/p99 (ms) | 积压峰值 | CPU 均值/峰值 | RSS 均值/峰值 |
|---|---|---|---|---|---|---|
| 16 玩家 | 2×8 | 0.35 / 0.56 / 0.78 | 4.9 / 9.5 / 13.1 | 23 | 9.1% / 11.1% | 22.1 / 23.8 MB |
| 24 玩家 | 3×8 | 0.29 / 0.41 / 0.59 | 4.0 / 8.1 / 10.3 | 25 | 10.9% / 13.9% | 31.7 / 33.9 MB |
| 36 玩家 | 5×8 | 0.29 / 0.38 / 0.56 | 4.2 / 7.9 / 10.1 | 25 | 19.5% / 23.1% | 54.7 / 58.0 MB |

每档约 3925 轮 30ms 节拍（无节拍丢帧）；输出量 65k/90k/163k 条；业务拒绝（灵力耗尽后的 cast）计在 inputErrors，非系统错误。

## 读数

- **30ms 步预算**：drain p99 ≤13ms（16 档最高），三档全部留有余量；输入 RPC p99 <1ms
- **扩展性近线性**：玩家×2.25（16→36）、CPU×2.1、RSS×2.6、drain p99 反而略降（更多进程分摊）——多房间进程模型在合成负载下没有超线性恶化
- **无积压失控**：峰值 ≤25 条输出/轮，publish 队列（容量 8）健康
- 单机（Apple Silicon 笔记本）短档下 36 玩家余量充足；正式 R6.3 的 2 小时长稳、阈值判定与目标机器仍待登记 profile 后执行

## 局限

120 秒短档观察不到慢泄漏与长尾抖动；NPC/技能密度是合成的中等负载；无网络（本机 JSONL 管道）；CPU 为进程合计的 ps 瞬时采样。驱动脚本为临时件（不落仓库），方法可按本记录复现。

正式 R6.3 启动条件不变：宿主登记机器 profile、实体/技能密度与数值阈值。
