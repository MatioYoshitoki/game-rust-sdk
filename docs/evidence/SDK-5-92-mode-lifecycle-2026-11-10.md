# DELIVERY-05 顺序模式生命周期验收

2026-11-10，SDK 0.153.0，机制 105，配置 schema 7，协议 6。验收使用合成输入和实际 Rust 进程、Node 宿主及 SQLite 账本。 [批次范围](../batches/SDK-5-92-progression-modes-and-privacy.md#gp05-模式生命周期范围与验收) · [接入契约](../interfaces/publications-v6.md#顺序模式)

| 验收 | 实测结果 |
|---|---|
| 顺序阶段 | 两席独立确认检查点后开启指定 NPC，实际击杀后都结算为胜。未达标、同席重复及旧阶段确认被拒绝。漏确认到期停在原阶段并结算为负。 |
| 复活与作用域 | 原生对手攻击打出致死伤害。倒地未启动结算，已发出的本席弹道清除。重连保留复活时刻，复活以实体代次 2 恢复 50 生命和 25 灵力。旧目标被拒绝，预算耗尽后按胜负结算。 |
| 截止与平局 | 断线后只重连的一席在原定时刻判负。另一局在相同时限内完成就绪，原截止后仍可参战。不同最大生命的席位按精确比例判平，资产账本保留库存。 |
| 事务 | 五局十席各有一笔入场和一笔结果结算。合作局丢失一笔提交回执后查回原操作，奖励与附属事实各提交一次。Rust 冻结账本回归覆盖模式结果重启后的原请求重试。 |
| 协议 | 259 条实际发布通过 Schema，含 35 条全量和 224 条增量。复活与提前判负时刻只出现在对应席的本人字段。解码器拒绝改写阶段时钟、复活预算和已冻结结果。 |

Rust 默认和全特性各通过 79 项，Node/H5 通过 224 项。格式、Clippy、最小 Rust 宿主离线检查及历史资料开关下的源码编译通过。 [Rust 模式回归](../../src/world/two_members/match_mode_contract_tests.rs)

原 S32～S38 的具名模式、观礼及原样输入继续按路线图复验。SDK 配置契约由宿主提供玩法内容。
