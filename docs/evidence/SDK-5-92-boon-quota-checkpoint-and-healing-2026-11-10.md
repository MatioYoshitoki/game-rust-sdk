# DELIVERY-05 共享加持、检查点和减疗验收

2026-11-10，SDK 0.150.0，机制 105，schema 7，协议 6。通过合成三席 World 验证共享来源，并用原生治疗事件验算减疗。 [批次范围](../batches/SDK-5-92-progression-modes-and-privacy.md) · [接入契约](../interfaces/world-boons-v1.md)

| 验收 | 实测结果 |
|---|---|
| 权威资格 | 开窗前领取拒绝。首席进度达标后，其他席仍须分别到达检查点。缺少局内材料保留两份额度，未进入读条。目录拒绝超座位数的份额、错用范围、缺失检查点和短于 World 步的读条。 |
| 占用与原子提交 | 每个共享来源同刻只允许一席读条。主动取消、受击、离距、进入保护和库存修订失效均释放占用，材料和份额保持。两个成功提交各扣一件局内材料及一份额度。首个成功成员重领被拒，另一未得益成员在额度用尽后被拒。 |
| 三席协议 | 四次读条后第三席、第二席依次取得两份加持。精确重放启动和已完成请求均未新增读条或消耗。断线席重连后保留检查点进度，重新就绪才领取。三席 SQLite 各提交一次结算，物品余额均为 4。 |
| 减疗 | 原始治疗 40，叠加两个加持减疗、普通减疗及正向受疗后恢复 20。强加持到期后恢复 28，普通减疗到期后恢复 32，替换移除最后一个加持减疗后恢复 44。 |
| 发布 | 151 条真实全量或增量通过协议 6 Schema。读条只向本人投影。显式空值、零份却可领取及超上限余额变体被拒，错误增量保留原快照。 |
