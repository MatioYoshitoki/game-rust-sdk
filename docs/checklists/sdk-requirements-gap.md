## 核对口径

来源为 [PRD §2.1 / §5](../../PRD-367-independent-rust-match-kernel.md)、不可变 [v1.1 行为基线](../../rust-match-kernel-v1.1/behavior.md)、[来源歧义](../../rust-match-kernel-v1.1/decisions.md)、[原始验收矩阵](../../rust-match-kernel-v1.1/acceptance.md)。当前能力以 [配置目录](../interfaces/configuration-v2.md)、[SDK 接入契约](../guides/sdk-integration.md)、[实际验收记录](independent-match-kernel.CHECKLIST.md)和下表所列 Rust 代码为依据。

分类单位是一个可独立验收的能力或内容切片，不是整个 F 域，也不是地图名。每个剩余工作 ID 只归一类；跨类的原需求拆分并列出依赖。

| 类别 | 判断条件 | 完成条件 |
|---|---|---|
| 配表即可完成（P） | 当前已注册机制和公开输入足以表达该切片；只需配置/离线导入和内容验证，不改 Rust 运行时 | 同一二进制加载配置，原规则的正常/拒绝/边界行为及终局收支均有证据；数据存在不算通过 |
| SDK 缺机制（M） | 当前缺少必要输入、运行状态、规则、输出或业务语义；或者来源语义尚不足以实现 | 先补有限规则与预期，再实现 SDK 能力并验收；来源不明也记在这里，不能假定可配表 |
| 缺接入验收（I） | 相关机制已有受控证据，剩余是原规格精确映射、实际消费、存储、传输、部署或容量证明 | 对声明的版本和真实边界执行并保存证据；若发现机制不符，回链新增 M，不能为通过而改期望 |

P 不表示内容已经制作完成；I 不表示原场景已经通过。一个原场景有 M 依赖时，先关闭 M，才能签收其接入部分。正式客户端/存储接入前再登记目标环境，当前无需寻找第二款游戏。

2026-11-07起按[6个交付任务](../plans/sdk-delivery-roadmap.md#后续6个交付任务)归并执行，同能力族的机制、配置、多人适配和接入验证统一交付。P/M/I子项及工作包继续用于完整性追踪，单个属性或投放入口作为任务内步骤推进。包状态逐批记录于下；最新口径见上方「0.185.0 执行状态」。

后续按[六阶段交付路线](../plans/sdk-delivery-roadmap.md)与[工作包清单](../plans/sdk-delivery-roadmap.json)跟踪。14类M、9类I、9类P均仍开放，已有能力为部分覆盖；25个工作包列出主要归属和最终关闭阶段；R1的3个规格路由包已完成，其余22包未完整关闭，不能据此推算整体完成率。[SDK-5-17逐项映射](../audits/sdk-5-17/README.md)已覆盖498内容/48场景/50向量；这是路由完成，I04/I05并未签收。历史artifacts由用户清理，报告可访问性及证据例外见[执行记录](../evidence/SDK-5-17-requirements-mapping-2026-11-05.md)。[SDK-5-18双成员闭环](../batches/SDK-5-18-two-member-loop.md)已实现有限双人PVE；R2三个工作包为部分实现，其余19包待实现，32类完整缺口仍开放。[本批证据](../evidence/SDK-5-18-two-member-loop-2026-11-05.md)。
