# SDK-5-7 通用受治疗修正最小闭环

2026-11-04；**先冻结规格后实现，HM01～HM10受控验收全部通过**。crate **0.10.0**、机制 **25**，schema4/协议3、单人PVE。复用定时状态，统一HOT、怪物预算自疗、支援治疗的实际结算；所有数值由配置初始化。

## 定义与聚合

1. 复用`timed_attribute_modifier`，新增`attribute:"healing_received"`。modifier_bps整数−10000～100000、duration_ms沿原范围，source_scoped及refresh/ignore沿原语义；本批禁止stack/max_stacks（含null）。允许原self提交和hit-target绑定，不新增友军/单位目标输入。
2. 仅机制25/schema4/PVE接受新选择器；旧版本、未知选择器/字段、混用heal_bps/damage_bps/shield_bps、stack及非法引用/范围/预算拒绝。原16定义、每绑定2引用、每实体32槽/全局128实例及容量整组原子预检保持。
3. 治疗执行时累加目标全部有效healing_received实例的modifier_bps，`multiplier_bps=max(0,10000+sum)`。不设额外正向玩法帽；工程上限由定义倍率及实例槽控制，宽整数计算。来源按source_scoped隔离或合并；refresh更新最新来源和期限，ignore保持原组。
4. 不改基础HP/ATK/DEF、HOT冻结量或引导预算，也不借用ATK/DEF的bonus_cap。读取派生倍率不施加/永久叠加状态。

## 统一治疗结算

- HOT每跳、怪物预算自疗每份、支援每份都经过同一个结算入口：沿原规则物化基础量/分配预算份额 → 执行时读取目标当前倍率 → `adjusted=floor(raw×multiplier_bps/10000)`一次 → 存活目标按当前缺口裁剪实际回复。不在计划预算和每跳两处重复乘。
- raw100/−5000→50，+5000→150；−5000与+2500相加为7500倍率、实请求75。总削弱≤−10000则0；0不套伤害保底。预算100分三份34/33/33，−50%逐份17/16/16；不先缩总预算再分配。
- 同一HOT或引导期间施加/到期会影响后续份额；原冻结量、周期次数/节拍/成本/CD不重算。截止同刻先过期，后按原周期排序；DOT同计划时刻仍先于HOT，致死不复活。
- 满血实回0，过量不转盾/灵力；不触发伤害/主动命中/吸血/反击，不打断交互/撤离/支援或回退Boss阶段，不额外消费随机数。沿各路径原有资格/中断/保护/归途规则，不将所有HP增加都归普通治疗。
- 原自然恢复、光球、归位满血、站位回灵/其它恢复不接入本批乘区，保留原行为。基础最大HP的HOT标尺与来源ATK等其它公式也不扩展。

## 生命周期与输出

来源/目标死亡、移除/换代、归位/整组复位、终局/关闭沿统一状态清理；后台不延长原期限，重连保持组/期限，旧连接拒绝。重启只履行原冻结资产责任，不恢复临时状态/World或重算原金额。

机制25视图新增可省略`healing_received_bps`（无修正10000），状态实例attribute为healing_received。新增`heal_resolved`事件：source/target身份、heal_kind(hot/self_channel/support_channel)、raw_heal、multiplier_bps、adjusted_heal(u64)、hp_restored。仅对实际合法治疗尝试输出，满血/零量可为0；HOT原periodic_heal_tick、MonsterHealed和SupportPulse的实际值与该事件一致。旧1～24不增加事件/字段或消费随机数。普通终局视图如保留则倍率回10000；重启Closed视图移除该临时派生字段。

Node/H5仅展示基础量、倍率、调整量和实回，不计算治疗或推进时点。0.10.0含公开DTO/枚举源码变更；六类Client、协议1～3、资产及恢复schema保持。来源behavior §4.1/4.3支持受治疗乘区；本批仅覆盖上述三条路径，不签收恢复强化、其它属性/控制/驱散、复杂治疗公式/叠层、友军目标、过量转盾、完整目录或生产接入。D-03/D-05不变。
