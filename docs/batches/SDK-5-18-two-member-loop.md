# SDK-5-18 同World双成员最小闭环

2026-11-05；范围与验收先冻结，现已实现并按TM01～TM13签收；见[执行记录](../evidence/SDK-5-18-two-member-loop-2026-11-05.md)与[机器证据](../../artifacts/sdk-5-18/acceptance.json)。来自[SDK-5-17逐项映射](../audits/sdk-5-17/README.md)，主要工作包R2.1、R2.2的双人切片，并提前完成R2.3必需的私有全量发布切片。实现起点为0.19.0/机制34；当前为0.20.0/协议4/schema5/机制35。

## 为什么先做这一批

原S01/S03需要共同激活，S18/S21需要同局竞争，S22/S40需要按接收者隔离，战斗/召唤/模式还依赖统一归属和身份。现有Create只含一个participant、World和资产责任均围绕一个成员；两个Runtime不能替代同World。先打通两个真实成员的各自入场、行动、收益和终局，后续机制才能复用正确的成员底座。

下一批采用同局双人PVE配置，不引入PvP、组队加成或友方治疗。两人相互不伤害，均可被NPC选中、受击、击杀NPC和拾取公共一次性掉落。当前整数物品的拾取原子性属于本闭环；装备实例、主动丢弃、遗物修订/私有开启、贡献优先期仍属R4.4。不得复制两份独立PVE世界后拼成同一地图。

协议4的首批能力清单冻结为：平面等高/零DOT地图；普通近战/直线弹道NPC；玩家普攻、方向普通首目标弹道，以及自身ATK/DEF状态技能（沿既有refresh/ignore/stack合法范围）；公共整数落地资源/光球拾取；既有有限积分成长与撤离/死亡结算。两槽可配置这两类玩家技能，完整移动/取消/前后台生命周期适用。

圆形/线形持续场、穿透/重复弹道、严格单位/地面技能、盾/DOT/HOT、复杂Boss/波次/遭遇目标/调谐/节点、容器交互等在新双人契约中暂不放行，对含这些能力的双人配置须在业务请求前明确UNSUPPORTED；老协议1～3继续支持原单人声明能力。后续逐类补齐多成员归属与组合验收后再放行，不能静默套用单人所有者或让宿主补逻辑。这个清单使本批集中验证成员底座，不要求一次迁移全部既有PVE组合。

## 有限公开契约与配置

保持六类SDK入口的职责；新增协议4/schema5/机制35，crate目标0.20.0。实现时先提交独立的双成员接口文档、严格wire schema和规范化样例，再写行为；这些版本只有实际发布候选通过后才成为sdk-info能力。协议1～3/schema1～4原Create和输出继续单人成立，不能改变旧字段含义或自动升级。公开Rust构造/源码消费变化要列迁移说明。

- CreateV4以`participants`数组替代单数participant/principal/connection三字段，每项为`participant_id`、`authenticated_principal`、`connection`；本批长度严格为2，且双方都是必需席位。空、1、3、重复成员/主体、非法/冲突连接、单复数字段混用及未知字段，全部在发任何业务请求前拒绝。单人仍走原契约。成员列表、配置/hash和seed创建后冻结，不接受局中追加/替换成员。
- 初始化配置提供每成员出生点、统一数值规则、NPC/掉落/撤离布局、部署期限/离线期限、发布/队列预算。出生点都满足同一碰撞规则，不能重叠；错误配置拒绝，不临时挤开。首批平面等高无DOT地图，H5采用既有等距投影。两套包外配置改变ID、主体、出生/撤离点、费用、物品和技能数值，不能在Rust按ID分支。
- EntityRef使用稳定ID和generation，ParticipantRef与owner关联；玩家/NPC身份空间无碰撞。输入已有participant_id、entity_generation、connection、request_id、sequence按成员验证，不共享序列或去重表。相同request_id/sequence跨成员合法；同成员重复不重复执行，过期代次/越权在改变费用/状态前拒绝。
- 事实、入场、结算、补偿、查询请求均显式携带participant_id并冻结主体、预期revision和原operation_id。宿主只依SDK事实/事务落库；不从连接猜归属，不在Node计算分摊/奖励或筛选World。操作身份含MatchKey/成员/用途并全局唯一，同一成员原请求重试保持身份。未经认证的浏览器不能发可信receipt/reconnect/close。
- PublicationV4带明确recipient/connection/publication_id。`self`包含本人完整受控状态和库存/动作/终局；`members`只含公开ID/代次、位置、存活/成员阶段与公开战斗展示；世界NPC、公共资源保持同一份。另一人的库存明细/revision、SP、冷却、凭据/主体、operation_id和业务金额不得混入公共成员/事件或另一份发布。事件按公开/本人私有显式分类，私有事件必须绑定recipient，不让宿主广播后再修补。
- 本批只做全量发布。每成员独立publication身份/连接回执/ready资格；必须`sent`且身份/连接一致才有已发送基线，enqueued不算。各自未发送上限与coalescing受配置约束，一成员慢发不能占满另一成员全部发布预算。无delta、观礼或第三种接收者；完整R2.3另批补齐。

## 准入、成员与World生命周期

先并行请求双方可信事实及资产，逐成员完成各自原子入场事务；未得到committed不能注入该成员库存、承认ready或开局。两人的最新全量实际发送且均ready、双方入场均成功后，只共同激活一次，activeAt一致。等待阶段不能移动/施放/拾取，不启动可获益AI战斗。不同成员IO允许交错，不能按回执到达顺序串用revision或仓库。

任一必需席位拒绝、缺席或部署超时，整局不激活：已确认入场成功者补偿一次；未知提交只查原operation，查到成功后再补偿，查到未提交才按冻结策略收尾。不能把未知当未扣费、先发退款或再生成扣费ID。World可释放，未决责任由不可变责任账接管；责任未收尾须明确pending，不能伪报零。

激活后成员有独立alive/offline/extracting/settling/terminal状态。A离线只停止A输入并按既有期限保留；A重连保留同局状态、重获本人全量和ready，旧连接隔离；不阻止B的时钟、输入、NPC战斗或发布。NPC使用统一合法目标集合及稳定距离/身份顺序选目标，原目标失效时按本批PVE资格重选，不复活终局成员；更完整仇恨/组织行为仍在R4.2。

A撤离核心提交成功后只让A退出可操作状态；A死亡/Leave/离线期限触发本人成员终局，清理其动作、状态/世界效果、归属临时计划及目标资格，保留本批既有来源退场即清理策略。来源死亡后计划继续是N10，留R3.4实现。B继续活动和独立结算，不能被A终局清掉。A核心提交未知时只能挂起A终局，B仍可活动；重复/乱序/迟到回执不得改写B的资产或撤销已确定结果。

首批死亡遵循既有整数物品损耗和结算，不声称原多人死亡遗物已具备。A放弃/死亡不得把其未定义的私有物品偷偷变成B收益。两人都终局，或绝对终局/可信close到达时，停止模拟、冻结每人各自未决责任并释放共享World；重复close仅一个关闭结果。另一成员或历史连接的迟到回执只能收尾对应账本，不重新创建成员/World，不恢复战斗现场。

## 结束范围

TM01～TM13全部通过才签收本批。R2.1在声明的双人PVE实体范围可签收；R2.2只完成双席切片，标准8席、模式16/24等容量、NPC保留席位及负载仍待后批；R2.3仅全量权限切片，delta/旁观仍待做。M01、M14及I01～I09不因本批通过而自动关闭。

不要求寻找第二款游戏，也不要求在本批接生产数据库或正式客户端。SDK-5-18执行时不得为了沿用旧DTO，把两人成员状态保存在Node；若契约与已冻结责任格式有无法兼容的变化，先补明确迁移/拒绝规则再实现，不能重算或静默改旧账。

TM12/TM13以实现开始时仍存在的源码、配置、归档和文档为保护基线。SDK-5-17中已登记由用户清理的历史artifacts保留不可访问标记；无需复原这些旧文件，也不能声称逐字节复核了缺失旧档。协议1～3兼容和单人回归须从保留源码重新执行，生成本批同源证据，不能用历史文件清理代替回归。
