# B3-2 单人普通宝箱闭环

日期：2026-11-03。状态：本批受控验收通过，见[执行记录](../evidence/B3-2-pouch-2026-11-03.md)。用户确认按“先需求、再 Rust、再 H5”的顺序补齐探索搜刮。

## 本批范围和来源决定

新增独立 `b3-2` 场景，沿用 B3-1 地图、三狼和现有资产链；B1/B3-1 配置原文保留。固定启用迷雾森林原 `chestSpawns` 前两个普通储物袋候选，经原投影反算、完整足迹和出生点连通校验后生成；属于本批双箱单人布置，不代表原地图全部宝物/数量政策。

来源为不可变资料包 `resolved-config.json` 的 `data/treasures.TREASURE_TYPE_REGISTRY.treasure-pouch`、交互范围与 `source-config.json` 的 `loot-tables.loot-chest-normal`。普通“散修储物袋” sealLayers=0、无守护、无成本、无开启优先期；因此本批直接开启，不添加虚构读条。玉匣的破解进度、守护、占用和竞争属于后续范围。本批中断验收检查开启前的生命周期门禁，不声称已交付封印读条。

- 开启范围为75世界单位，须有可通行连线；仅已激活、存活、前台、ready且无保护的角色可操作，正在施法/前摇或撤离读条时拒绝。开启成功停止移动与导航。
- `OpenChest{chest_id,expected_generation}` 只提交意图，Rust 原子检查箱状态和代、计算随机掉落并标记开启。相同输入幂等；不同请求不能重复开同一代；陈旧代不能领取新一轮。
- 奖励按“开箱落地→拾取入背包→终局结算”交付。必掉火灵1～2，独立30%玄铁1～2；整数数量含两端，0概率永不掉、1必掉，使用本局确定性RNG。奖励无直接仓库写入，不额外增加击杀/修为。
- 每份掉落具有箱ID/代/槽位组成的稳定身份。落点完整16单位足迹可走，距箱中心不超过75且与箱/入口连通。地面资源上限50；空间不足或落点失败时整个开启拒绝，箱状态、RNG、事件和掉落均不部分提交。
- 满背包拾取拒绝，地面数量/身份保留，不消耗箱新一轮。掉落沿用现有一次性资源寿命和清扫；不作为环境资源补刷。
- 普通储物袋按原300000ms逻辑时间重新出现。已开启期间显示冷却；到期后 generation+1，且只按本次成功开启时刻计时。World关闭后不生成新轮次，不因重复输入提前刷新。
- 刷新/短断线恢复箱代、开启状态、掉落与背包；旧连接拒绝。服务重启仍只恢复旧结果/冻结资产责任，不恢复战斗现场；未冻结终局的中断局沿用入场补偿。不可重新开箱来履行旧结算。
- 点位配置启动读取、校验、只读缓存和每局版本绑定沿用上一批。宝物规则/奖池本批固定，其他宝物类型、守护、未知字段和不支持机制明确拒绝。

H5 增加“迷雾森林·搜打撤”场景，显示普通袋、已开启/冷却与代，提供最近宝箱开启和前往宝箱操作。一键验证完成三狼、两个储物袋、拾取、撤离与逐物品资产核对；所有玩法判定由 Rust 处理。

## 验收标准

| 编号 | 必须成立 |
|---|---|
| S01 来源/配置 | 校验资料包哈希并可重复导出；两处点位与原候选对应，可站立可达；坏ID、重复ID、非法点、未知宝物/规则/字段启动拒绝；旧场景不变 |
| S02 开启准入 | 75边界、墙阻隔、无箱、陈旧代、未ready、保护/后台、死亡/关闭、施法/撤离期间正确拒绝，无掉落/奖励副作用 |
| S03 原子/幂等 | 同请求重复和不同请求重复均只生成一批；资源上限/落点失败不改箱、RNG或物品；开箱不直接入库、不增加击杀/修为 |
| S04 掉落/拾取 | 原概率与数量两端、稳定种子、合法足迹、唯一资源ID；满包/旧修订失败保留地面，成功拾取一次；新代身份不与旧代碰撞 |
| S05 重生 | 300000ms前不能再次开，到期仅增加一代，陈旧请求不能开启新代；重复查看不延长/提前计时；关闭后不重生 |
| S06 终局 | 三杀+双箱正常撤离修为45、死亡11；逐物品守恒，仓库仅按冻结结算增加；未拾取地面物不进入资产；World与未决责任最终归零 |
| S07 恢复/故障 | 刷新/断线不重新开袋；旧连接无权；结算拒绝、回执丢失、SQL提交前后强杀、人工核对、重复重启按原ID/多物品载荷一次收尾；未冻结终局仍只补原入场 |
| S08 回归/视图 | H5展示与实际箱状态、代、冷却一致；一键流程使用公开输入；原B1/B2/B3-1/配置专项重新通过且绑定最终源码，保留等距和实时性能验收 |
