# SDK-5-3 通用属性修正（ATK/DEF）

2026-11-04；**先冻结规格，再实现；AT01～AT10受控验收通过**。基于SDK-5-1/5-2的定时状态、来源分组、refresh/ignore/stack和清理，增加有限属性选择器，先支持ATK与DEF。目标crate **0.6.0**、机制 **21**；仍为schema4/协议3、单人PVE、现有主技能提交/弹道命中绑定。

## 配置与计算

- 新定义使用`mechanism:"timed_attribute_modifier"`和必填`attribute:"atk"|"def"`；沿用duration_ms、modifier_bps、duplicate_policy、source_scoped及stack的max_stacks。属性名是机制注册枚举，数值由配置提供，不开放任意字段写入或脚本。
- 旧`timed_defense_modifier`保持隐式DEF，禁止携带attribute（含null）；旧机制1～20禁止新机制/attribute和attack_bonus_cap_bps。新机制缺attribute、null、未知属性、非PVE/schema错配拒绝启动。原配置原文与哈希保持。
- status_rules新增`attack_bonus_cap_bps`整数0～100000；有ATK定义时必须配置，不接受null。DEF继续使用原defense_bonus_cap_bps。原16定义、每绑定2引用、每实体32实例/全局128预算与每层倍率-10000～100000保持。
- 两属性共用计算：`effective = floor(base × (10000 + clamp(Σ(本属性modifier_bps × stacks),-10000,该属性正帽)) / 10000)`；单层按1。分属性汇总、一次取整，ATK/DEF互不串入，宽整数计算，基础账户/模板不改写。有效ATK允许0，原普通伤害minimum_damage规则保持；守方境界防御常数不随临时ATK变化。

## 读取边界

保留既有攻击计划的物化边界，只把当时基础ATK替换为有效ATK，不增加命中时二次倍率：

| 路径 | 读取有效ATK一次的时点 |
|---|---|
| 玩家普攻/主技能弹道 | 提交；主技能self绑定整组成功施加后读取，因此本次自增攻影响本次弹道。取消/容量失败不扣成本或发弹道。 |
| 怪物弹道 | 提交；self绑定成功施加后读取。 |
| 怪物近战 | 本次近战释放。 |
| 范围攻击 | 原范围释放/判定时刻。 |
| 重击 | 原预警计划创建时刻；保持原准备期已冻结语义。 |
| 借隙/返剑反击 | 反击窗口创建时刻。 |
| 限时站位/直接命中窗口的成功与失败攻击量 | 原预警创建时刻；回复灵力/百分比治疗等非ATK量保持原义。 |

物化后的在途弹道、重击、窗口预算不因后续ATK施加/失效/来源死亡而重算，亦不复活来源。尚未提交的弹道读取提交时状态；同刻先到期再处理动作，DEF仍在真实伤害时读取。击中后才给目标施加的减攻不改变本次已冻结攻击量，影响其后续计划。来源/目标失效、真正归位/整组复位、终局/关闭的取消规则保持。

## 输出与范围

- 新通用属性实例输出attribute；旧DEF实例省略attribute，旧19/20状态JSON保持。机制21的玩家/怪物视图增加effective_atk，DEF沿旧字段；旧机制省略effective_atk。旧事件承载同一StatusView，不增直接状态操作入口。
- Node/H5仅转交意图/存储证明和展示属性、有效ATK/DEF、来源、层数与截止。六类Client、协议1/2/3、资产/结果正文和恢复schema1保持。
- 同World重连保留实例及绝对截止；重启只恢复冻结资产责任，Closed视图清除临时属性状态，不恢复World或按新数值重算责任。
- 本批不扩展SPD/HP/暴击等属性、控制/盾/DOT/HOT、多技能槽、多人与新地图/第二游戏。来源behavior §4.2/4.4支持派生属性与冻结攻击来源；本批读取边界是有限SDK策略，不声称等价迁移全部86状态。D-03/D-05继续保留。
