# CONFIG-1：核心机制与配置参数分层

日期：2026-11-03。状态：MC01～MC08在本批受控范围内通过，完整回归与最终源码绑定完成。实施优先级高于新增封印玉匣玩法。参数单位、范围、来源、消费者、工程上限和调参方式见 [配置v2目录](../interfaces/configuration-v2.md)。

## 产品决定

Rust 实现可复用的核心机制，玩法数值由外部配置在启动时初始化。新增同一种机制的怪物、技能或宝物，以及调整其数值，应只需要修改配置；新增一种机制才需要增加 Rust 实现和能力验收。

参数配置包含数值和内容声明：模板ID、引用关系、地图点位、采用哪种已实现机制等，也属于初始化数据。配置声明只选择、组合已经实现且可校验的机制，不能靠写一个新类型名使未知机制生效。

原资料包继续作为规则与基线数据来源。数值冻结仅用于可复现的验收样本，不作为新格式引擎拒绝其他合法参数的实现方式。B1/B3-1/B3-2基线已导出为显式schema2；schema1原文归档保留其历史解释，仅用于已有版本兼容。

## 分类准则

| 类别 | 判定 | 例子 | 归属 |
|---|---|---|---|
| 核心机制 | 决定如何执行、如何转换状态、何时提交和怎样维持不变量 | 碰撞/路径、动作前摇与提交、命中/伤害链、概率抽取、拾取和堆叠、容器每代一次、可打断交互、死亡分配、幂等/结算/恢复 | Rust类型、算法和状态机；通过独立行为测试验收 |
| 玩法参数 | 在同一机制内改变量级、时长、概率、次数和容量 | HP/攻击/防御/身法、尺寸/速度、射程/警戒/牵引、CD/耗蓝、吸血/回血比例、掉率/数量区间、封印层数/每层时长、重生/撤离时间、死亡损失比例、堆叠和背包容量 | 启动配置，经过类型/范围/交叉约束检查后进入只读Rust结构 |
| 内容声明 | 描述本局有哪些对象、采用哪些已实现机制及相互引用 | 怪物/技能/物品模板、奖池、生成数量/点位、技能槽及施法条件、容器类型、已实现的中断/进度策略 | 配置数据；引用必须能解析到已注册的内容/机制 |
| 运行状态 | 随一局输入、时间和外部提交事实变化 | 当前HP/MP、技能截止时间、背包、掉落、仇恨、开箱进度/代、结算是否已提交 | 由Rust实例维护；配置只提供初始值或计算参数 |
| 运行参数 | 影响服务调度、资源预算和外部等待 | 逻辑步长、输出频率、队列容量、I/O期限、重连期限、导航搜索预算 | 独立运行配置或受限构造参数，与玩法配表分层；初始化校验工程边界 |
| 数学/协议常量 | 表达算法、单位和编码语义，本身不承担调参职责 | 秒与毫秒换算、概率归一化基数、圆周常量、浮点容差、整数编码范围、协议版本/合法状态转换 | 代码定义；有设计意义的阈值不能借此留在代码中 |

公式的算法和执行顺序属于机制；可调系数、倍率、上限、分段阈值和舍入策略中已支持的选择属于配置。需要全新算法时实现并注册一个明确机制。禁止把任意表达式或脚本当作数值配置执行。

示例：容器“未开启→交互→解锁→领取→重生”的状态机由Rust提供；是否采用已实现的分层解锁、层数、每层时间、触发概率、奖池、重生时间从配置取得。普通储物袋采用即时开启；未来玉匣采用已实现并验收后的封印机制。当前尚未实现的封印/守护能力继续明确拒绝。

## 本次实施范围和顺序

1. **参数目录与schema**：以现有B1/B3-1/B3-2全部已实现机制为范围，登记每个可调参数、单位、类型、合法范围、默认来源及消费者。提取强类型运行结构，配置源保持可携带。
2. **参数消费迁移**：当前功能逐模块从已校验配置取值，移除重复的玩法常量。保持原基线参数的行为与资产结果，不同时扩展封印/守护/多人等新机制。
3. **能力与引用校验**：按机制类型/版本和明确能力检查，允许同机制合法数值变化。未知机制、字段、缺失引用、非法概率/区间、溢出、不可达点位等启动失败。
4. **通用边界与恢复**：支持配置范围内实体数量、堆叠/容量、掉落和结算变化；修正恢复对固定三狼、单堆叠、固定轮数等隐含假设。工程安全上限有名称和理由，不伪装成玩法规格。
5. **H5与多配置验收**：沿用同一二进制，加载多套合法参数验证真实行为；旧对局/旧结果/旧资产责任继续绑定原配置版本。
6. **再扩展新机制**：完成本次后，封印玉匣按通用可打断交互、分层解锁、守护资格等机制增量实现；层数、时间、概率、属性和奖励以配置提供。

仍沿用“启动读取→校验/预处理→只读缓存→每局绑定版本”。本次不增加运行中改写活跃World的入口。角色属性可由配置模板、配置公式与可信持久角色事实共同初始化；持久库存、已提交资产和连接事实遵守现有I/O契约。

## 验收标准

| 编号 | 必须成立 |
|---|---|
| MC01 清单完整 | 每个现有玩法可调量有单位/来源/范围/消费者；遗留常量逐项注明是算法/协议常量、运行参数还是待迁移玩法参数 |
| MC02 同二进制调参 | 修改合法HP、伤害系数、CD、范围、回复/吸血比例、奖池概率/数量、容器重生、撤离时长等，重启后实际Rust行为相应变化，二进制哈希不变 |
| MC03 内容复用 | 同一种已实现机制可配置不同怪物/技能/容器实例及受支持数量，实例状态隔离；增加内容不新增专用玩法分支 |
| MC04 能力边界 | 未实现机制、缺字段/未知字段、悬空引用、非法概率、反向区间、非有限值/溢出/超资源预算明确失败；合法参数不因偏离旧批次数值而被拒绝 |
| MC05 通用资产 | 多堆叠、不同容量/掉落数量和合法重生次数下，拾取、死亡、撤离逐物品守恒；失败无部分提交、重复输入不重复收益 |
| MC06 版本恢复 | 旧配置A创建并冻结的责任在配置B上线后仍按A核对；旧结果/画面一致；不重算金额、不创建World、不重复发奖 |
| MC07 H5正确 | 展示和自动验证读取当前配置及权威状态；固定三狼/45修为等仅作为具名夹具预期，不成为通用运行条件 |
| MC08 原基线与新参数矩阵 | 当前146项Rust及原真实进程/浏览器回归保持通过；另有不同参数、数量、堆叠与边界组合的机制验收，报告绑定最终源码/配置/机制版本 |

## 实现边界与证据

已实现的怪物AI模板、玩家主技能、怪物弹道/预算自疗和普通容器角色可更换ID、参数及实例数量；单份配置仍只有一种怪物模板和两个固定能力角色，不表示任意技能图或多AI模板注册表已交付。当前HP/MP、背包和箱代仍由Rust维护。旧版兼容解释层保留历史数值，新schema2无数值指纹白名单。
