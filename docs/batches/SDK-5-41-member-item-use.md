# SDK-5-41 局内恢复道具

对应 R3.1/M02 的主动道具使用。目标 SDK 0.43.0，协议 6，schema 7，机制 58。同一 PVE World 的 1～8 名成员可拾取指定的堆叠道具并主动用于自己。最小闭环为击杀、拾取、受损、使用一份道具恢复生命和退出结算。

对局可声明 `member_item_use: {"pill_healing":{"heal_hp":40}}`。配置为 1～16 个已注册物品，每个只声明 1～1000000 的整数恢复量。字段限机制 58。未配置时返回 `UNSUPPORTED`。每次使用一份，恢复量由 Rust 按当前生命缺口截断。该切片使用固定即时恢复，并沿用现有生命上限与存活资格。

`use_item` 提交 `item_id` 和本人最新 `expected_revision`。Rust 校验成员可操作、配置、库存修订、实际持有量、本局净拾取份额和生命缺口。成功时扣一份、加一次修订、恢复实际生命并向本人发出 `item_used`。事件带原请求 ID、物品 ID 和实际恢复量。满血、未知物品、只持有战前带入份额或库存耗尽时拒绝。失败保留生命、背包和修订。重发相同请求不会再次消费。使用和丢弃共用本局净拾取份额。

背包和生命继续走本人 full/delta。同局重连保留已提交的结果。退出时 `looted` 为拾取扣除主动丢弃和已使用的净额。战前带入仍单独记录为 `carried`，终局损失仍按剩余背包计算。财务恢复继续使用已冻结的结算责任。

| ID | 验收 |
|---|---|
| IU01 | 机制门禁、配置形状、已注册物品与恢复量边界，未配置和旧版本兼容。 |
| IU02 | 受损后扣一份并实际恢复，生命缺口截断，原请求 ID 和本人修订各一次。 |
| IU03 | 满血、无份额、未知物品、错修订、保护或断线拒绝，生命和库存原子保持。 |
| IU04 | 重复请求、重连、私有事件和 full/delta，丢弃与使用共用份额，净额结算与金融恢复。 |
| IU05 | 普通 Node 与真实 H5 验证四人拾取后使用，八人转移后由同伴使用，所有成员完成结算。 |
| IU06 | 同候选 Rust 和 Node 回归、格式与 Clippy、空缓存离线交付和机制 57 包外回归。 |
