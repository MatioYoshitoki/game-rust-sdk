# SDK-5-45 局内双恢复道具

对应 R3.1/M02。目标 SDK 0.47.0、机制 62、schema 7、协议 6。原始物品注册表中的玉泉散 `pill_mana` 会一次恢复自身气血和灵力。本批验证这两个效果能由一次局内用药提交。样例使用固定恢复量，原配方的最大属性比例和品质倍率留在后续数值适配范围。

机制 62 的 `member_item_use` 条目可同时配置 `heal_hp` 与 `restore_spirit`，沿用两个字段现有的整数范围。机制 60 和 61 继续要求两字段互斥。用药只针对使用者，沿用本局净拾取份额、背包修订与独立或共享冷却的校验。

两个属性分别按实际缺口截断。只要有一项恢复大于零，就扣除一份道具、递增一次背包修订并启动一次已有冷却。两项均无恢复时返回 `INVALID_STATE`，背包、属性和冷却不变。本人收到一条 `item_used`，双恢复条目发布两个实际值，某项已满时该值为 0。已有单效果条目保留各自的事件字段语义。

| ID | 验收 |
|---|---|
| DR01 | 机制 62 接受双恢复和旧单效果配置，旧机制拒绝双恢复，非法量或空效果仍拒绝。 |
| DR02 | 两项有缺口和仅一项有缺口都成功，按各自缺口截断。两项均满时不产生消耗、事件或冷却。 |
| DR03 | 单次成功只提交一份消耗、一次库存修订和一次冷却。过期修订、冷却期内和重复请求不重复提交。 |
| DR04 | 双恢复事件与库存变化仅本人可见。重连保留冷却，结算只入账实际剩余的净拾取量。 |
| DR05 | 普通时钟 Node 和 H5 各跑通四人和八人场景，验证双恢复和仅一项实际恢复，H5 同时显示有配置的两个恢复值。 |
| DR06 | Rust 和 Node 回归通过。同一交付包在空 Cargo 缓存下离线构建，机制 61 共享冷却样例可在新宿主运行。 |
