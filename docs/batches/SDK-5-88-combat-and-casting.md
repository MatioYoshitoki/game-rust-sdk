依据原 `skill-cast-lifecycle.DESIGN/INTERFACE` 的阶段移动及资源契约，补齐以下已确认行为：准备/引导阶段可配置有效新移动中断；预持、重复方向、单独回中和配置阈值内噪声不打断；无效导航/受控制拒绝的输入不得取消施法。引导可选择自由、减速或锁定移动，默认仍锁定，冻结的伤害预算不因移动重算。真实蓄力可选择提前松手排到最短蓄力时点，松手后锁定瞄准；原提前取消默认保持。

## 记录盾、结束效果与条件消费闭环

本组仍属于DELIVERY-01/R3.2～R3.3。来源依据为资料包source-rules文档52的坤甲功阶段表、文档53的统一护盾/accumulatedValue契约及source-config的factor_cultivation_guard参数；不以技能ID选择算法。记录基数显式选择“护甲/适用减伤后、统一护盾吸收前的来袭量”或“该盾实际吸收量”。前者是观察账，不移除原伤害；各来源记录独立、有界，不能把记录再当作额外吸收。

`combat_rules.shield_records`按盾定义绑定冻结记录上限（固定量+已解析来源威力比例）、护盾存续减伤、refresh时reset/preserve、depleted/expired/consumed三种结束策略、反击比例/种类/元素/半径/目标上限，以及可选结束后的持有者状态和反击命中状态。来源威力在施加时读取有效ATK、技能威力增益和配置威力点；盾与记录仍为一个状态身份。完整永久装备派生仍归R5.1。

反击只在本次伤害/死亡清理后执行；来源和持有者都须存活且非保护/返回。主动驱散、退出、死亡、复位、关局不释放记录。每个结束实例先消费，再最多释放一次；派生反击仍经过共享伤害与护盾链，但不再生成记录或触发同类派生/被动。自然到期不是破盾，分别由配置开关控制。候选按距离/ID/代次稳定选择并重验敌对、半径、视线和资格，每步结束/命中预算受限，拒绝明确且不重试重奖。

触发可配置最小事实量、本人/对方生命阈值、概率及一个由触发者本人施加的指定状态要求（本人或本次对方、最低层数、消费层数）。先筛选条件，再计数/ICD/按动作去重；只有满足阈值和效果容量时才消费并开始ICD。缺状态、容量不足或概率失败不消费；容量失败保留就绪计数供下一动作尝试。部分消费不重置状态期限，整份消费使用明确的consumed结束原因。一次动作的多目标/多段不能反复消费同一奖励门槛。

## 状态处置与致死保护（SD01～SD09）

仍在SDK-5-88内实施，不另拆交付批次。来源为factor-system的状态所有权契约、cultivation-combat-identity中的祛毒/封禁与续命规则。新增显式状态政策表：增益/减益、可驱散、可转移、拦截的可驱散类别均由配置声明，不根据ID、描述或属性正负推断。未登记的状态不允许通用驱散/转移。转移是额外的有类型原语，不能据此签收未知special或原功法全量行为。

驱散/转移接入既有有界触发器，选择owner/other、类别及最多16个实例，按到期、创建、实例ID排序。转移保持实例ID、原来源、层数和绝对到期时间；容量、重复身份或封禁失败时整组不动，状态消费与效果预检共用同一预览。首轮转移仅允许非周期、非护盾、非控制的数值/移动状态；不重新采样或赠送时长。驱散使用cleansed原因，不触发记录盾反击。拦截只影响新施加/刷新，不删除已有状态，拦截载体到期后自然恢复。

致死保护按战斗profile配置，每个实体代最多成功一次。仅在正常伤害经过减伤和统一盾后将致死时，先预检附带自身状态，保留不超过当前HP的配置生命，再按最大HP比例走既有受疗链，并施加配置状态。失败不消费保护。直接、周期及派生伤害共用此入口；保护、免伤或完全吸收不消费；HP费用、强制终局不走保命链。伤害/吸血/击杀只认实际HP损失，不把阻止量计为伤害。重连不重置，实体换代才获得新生命周期。

## 目标计数与动作总量（AT01～AT10）

本组继续归SDK-5-88。来源为combat-engine原规则中的逐目标判定、整个action的afterAttack.damage累计及终态一次收益。新增`counter_scope=owner|target`，缺省owner保持旧行为；target以另一实体的kind/id/generation隔离进度、ICD和动作去重，每个来源/触发最多配置数量的目标计数器，不能淘汰仍有效目标后重领奖励。

## 状态窗口累计与结束恢复（WR01～WR10）

仍属SDK-5-88。来源为cultivation-combat-identity的道种结束伤害比例恢复及岁流结束生命/灵力恢复契约；本组只签收通用窗口，不签收两套功法全部吸血、种子、净化等行为。`status_windows`按状态定义配置，使用已有状态身份、期限、来源和移除原因，不创建第二个计时器。载体为来源隔离的refresh/ignore数值/复合状态或HOT；盾、DOT、控制、叠层载体及窗口状态转移装载拒绝。

## 周期与到期状态净化（LC01～LC10）

## HOT双资源恢复与治疗余量分配（PR01～PR10）

仍归SDK-5-88/DELIVERY-01，依据cultivation-combat-identity的回岁长息每秒恢复生命/灵力及满生命转灵力契约。本组补通用资源恢复与预算分配，不按功法ID分支；不签收原功法所有投放和模式组合。

`combat_rules.periodic_recovery`按HOT定义绑定可选spirit公式和overheal_spirit转换，至少一项。spirit为`fixed + floor((选定ATK×source_attack_bps + 持有者maxSpirit×target_max_spirit_bps)/10000)`，沿用同一HOT的source/target、snapshot/live采样策略。金额宽整数饱和至u32；公式各项、数量和引用装载校验。仅HOT可绑定，仍使用原实例、周期、跳数、refresh/ignore及退出清理。

转换配置包含bps（1～10000）和when（full_before_tick/any_excess）。机制105统一配置模式下成员和NPC自身HOT都先按受疗倍率和当前缺口恢复HP，只计算一次受疗，旧配置保留原路径；full_before_tick按恢复前有效最大HP/当前HP判定。基础回灵先执行，受当前maxSpirit、缺口及回灵封锁约束；再用本跳HP余量执行转换。转换实际回灵A，消耗治疗预算ceil(A×10000/bps)，其余HP余量才交给原过量转盾。转换先floor、实际量再钳制，消耗预算使用宽整数；空缺口、封锁或不合条件不消耗转换预算，余量可继续转盾。没有将同一治疗预算同时全额转灵力和转盾的路径。

顺序为HP治疗→基础回灵→余量回灵→剩余转盾→净化；结束仍按净化→窗口恢复，周期回灵不会改变窗口原始公式。灵力不乘HP受疗倍率；HP受疗为0不影响独立基础回灵，但没有可转换的HP余量。保护/归位跳过本跳实际收益，仍推进原跳数，不在重连后补发；来源/持有者失效、死亡、退出/复位/关闭完整清理。

PeriodicView新增可选raw_spirit，只在配置双资源规则的HOT出现；snapshot在施加/refresh取值，live在执行时更新。私有periodic_spirit_tick报告原来源/持有者、跳数/原生时刻、raw_spirit、基础与转换的实际回灵、hp_excess、conversion_bps/eligible、spent_heal、remaining_excess及原生outcome。仅既有合法观察者接收；Node/H5消费权威金额和采样元数据，不自行结算。

增加有界 base_modifiers 和显式 stack_counter 配置。计数器初始化值可为 0，最大值由配置给出；重复应用使用既有 Refresh/Ignore，Refresh 重置为初始化值。原 Stack 重复策略及其最小一层行为保持。固定部分与按层部分按同一实例合成，再沿既有属性聚合和上限结算。

新增只调整既有、本人来源计数器的有类型触发效果；不在载体缺失时创建状态。增量、目标和是否刷新期限通过配置选择，缺省保留原截止及记录账。消费到 0 保留显式计数器和固定效果，普通 Stack 消费到 0 仍移除。释放、驱散、死亡/退出及关闭均清理整个实例。

层数实际跨越配置门槛时可产生一次有界原生事实，供有限的净化/自身普通状态/回灵等叶子消费；停留在满层不反复触发，禁止递归调整层数或派生传播。与已有窗口记录、受疗、减伤、吸血、同刻顺序和来源资格组合；Node/H5 只消费原生结果。
