# SDK-5-2 定时DEF状态叠层

2026-11-04；**先冻结规格，再实现；SK01～SK10受控验收通过**。在[SDK-5-1](SDK-5-1-timed-status.md)的状态生命周期上增加stack，关闭M03的又一有限切片。仍为单人PVE、一个玩家主技能、现有施法提交/弹道命中触发；不新增地图、其它属性、控制、吸收盾、DOT/HOT、多人与第二款游戏。

## 规则与配置

1. 目标crate **0.5.0**、机制 **20**，使用schema4/协议3。旧机制1～19、协议1/2/3、资产/结果正文与恢复schema1保持。新增公开状态DTO字段和事件按0.x次版本处理，原0.4.0包及其配置样例保持原文。
2. `duplicate_policy:"stack"`必须声明`max_stacks`整数1～128；modifier_bps继续表示**每层**DEF修正，duration_ms表示整组时长，原范围和最终DEF合计帽保持。max_stacks是配置数值，128是工程上限。机制19拒绝stack/max_stacks（含显式null），refresh/ignore不接受max_stacks，不静默变成叠层。
3. 首次合法施加建立一层；重复施加每次加一层，夹到max_stacks。包括封顶时，每次合法重施均保留instance_id、把applied_at_ms设为当前逻辑时刻、expires_at_ms设为当前+duration_ms。**所有层共用期限，到期整组移除**；不提供逐层计时/独立叠加/保持旧期限等其它策略。
4. source_scoped=true沿用来源身份分组，各来源独立层数/期限/上限；false同定义合并，每次重施更新为本次来源，整组层数归最新来源，包括封顶重施。该来源失效则整组清理，保留原有限来源失效规则。跨目标、实体代、遭遇轮次不合并。
5. 有效DEF仍从基础值推导：每实例贡献`modifier_bps × stacks`，再对全部实例求和、按原正向帽及-10000下限夹制，最后乘基础DEF并一次取整。refresh/ignore贡献仍为一层。不能按每层取整后累加，也不改写永久属性。
6. `[start,end)`、先到期后同刻命中沿用；截止同刻再施加为新实例的一层。重复request_id/同次弹道/传输回执不能加层或延寿。封顶仍是一次真实施法/命中，原成本/CD/伤害保持；不因added_stacks=0退款或重复发奖。
7. 层数不占新实例槽，不增加独立定时器；满槽仍可给已有合并键加层，新的来源组仍按容量原子预检。整组绑定失败时不部分加层/刷新/改来源；self与命中两种失败语义沿SDK-5-1。

来源[behavior §4.4 / D-11](../../rust-match-kernel-v1.1/behavior.md)明确加层、上限与来源分组，未完整规定所有来源状态的计时细节。本批显式定义上述SDK注册策略，不把它标为全部86状态的等价迁移，不改写原v1.1包，也不裁定D-03/D-05。

## 输出和宿主

- 仅stack实例输出`stacks`、`max_stacks`；旧refresh/ignore省略这两项，机制19的状态JSON保持原形状。modifier_bps保持每层量。
- 新实例沿用status_applied；重复stack发`status_stacked {status,added_stacks}`，包括封顶时added_stacks=0。读取快照不加层/延寿。
- Node/H5展示层数/上限、来源、截止和Rust给出的有效DEF，不计算叠层或伤害。六类调用与浏览器操作白名单保持，无设置层数/直接施加状态入口。
- 前后台/同World重连保留真实层数、实例、来源和绝对期限；到期、目标/来源失效、归位/复位、终局/关闭整组清理。进程重启仅恢复原资产责任，Closed视图移除临时状态，既不恢复层数，也不按新配置重算冻结结果。
