# B2-1：同一进程内的连接恢复

日期：2026-11-02。状态：受控验收通过，见 [实际执行记录](../evidence/B2-1-reconnect-2026-11-02.md)。范围：用户已授权第二批的第一小步——刷新/短暂断线恢复同一局。完整 B2 的持久责任账、服务重启后资产恢复、通用外部 I/O 超时和并发容量审查继续按后续小步交付。

后续 [B2-2](B2-2-io-deadlines.md) 已完成自动 I/O 期限和初次就绪窗口，并把连接换代延伸到尚在等待准入的 Preparing 阶段。本文是 B2-1 的原始分批范围，当前剩余主要为持久责任恢复和生产接入审查。

## 行为与边界

- 重连沿用 MatchKey、角色实体代、World、随机状态、资产责任和入场提交；不调用 create、不加载新角色、不再次扣费。原 create 请求的幂等身份保持不变。
- 宿主认证同一 principal 后，使用原 `submit_input` 提交有限生命周期消息 `Reconnect{previous_connection,authenticated_principal}`。Input.connection 是唯一后继连接：generation 必须恰好加一，前驱必须仍为当前连接。H5 不允许浏览器通过普通操作接口提交该生命周期消息。
- 新连接到来即撤销旧连接和全部旧 ready 资格。新连接先应用完整状态、确认 sent、提交 Foreground 和当前恢复轮的 CombatReady，才能恢复玩法；迟到输入、ready、发送回执和旧页面操作均不能控制新连接。
- SSE 断开由宿主提交 `ConnectionLost{}`。Rust 停止移动、取消尚未提交动作和撤离读条，并进入原有保护状态。已提交技能的费用、冷却、背包和战果保留。位置不重置；HP/灵力仍按原规则自然恢复；对局时间、冷却截止时间继续推进，恢复不会重置撤离开放时间或绝对终局时间。
- Rust 为断线和新换代连接未 ready 设置 30000ms 逻辑保留窗口。重复断线不延长窗口；确认 ready 后移除该窗口。超时走原有 close：已激活按死亡冻结结算，未激活补偿入场，释放 World，未知资产责任继续保留。计时由 Rust 完成；加速验收时钟同样加速该窗口。
- 页面收到完整的权威冷却截止时间，显示剩余技能冷却。浏览器只能做视图投影/插值，不能修改角色状态。掉线期间自动操作停止，恢复后可手动继续。
- 同一浏览器所有者的新标签页会接管当前局；旧页提示已被接管并停用操作，不自动互相抢占。HTTP 输入、确认、关闭、核对和 SSE 均携带连接身份。重连请求按 requestId 有界去重，并校验原前驱，避免丢回执时再次换代。
- Draining/Closed/Faulted 只恢复结果或冻结责任视图，不创建新 World。没有服务重启后的战斗热恢复承诺；本轮仍是受控内存账本。
