# SDK-5-43 灵力恢复道具

对应 R3.1/M02。目标 SDK 0.45.0，协议 6，schema 7，机制 60。同一 PVE World 的 1～8 名成员可消耗一份本局净拾取的堆叠道具，立即恢复本人灵力。

`member_item_use` 的每个条目配置一个恢复属性。机制 60 新增 `restore_spirit`，取值为 1～1000000 的整数，`heal_hp` 继续用于生命恢复。两种属性可配置在不同道具上。每个道具可按机制 59 的规则配置 `cooldown_ms`。

`use_item` 继续提交物品 ID 和本人库存修订。服务器将恢复量截断至当前灵力缺口。灵力已满时返回 `INVALID_STATE`，库存和冷却保持原值。成功后扣一份、推进库存修订并启动已配置的冷却。本人 `item_used` 在灵力恢复时携带 `spirit_restored` 实际值与 `hp_restored: 0`。本人快照继续提供实际灵力、背包和冷却。

沿用按成员和道具独立计时、转移、请求幂等、同局重连、离场清理与剩余净量结算。验证范围覆盖四人房拾取后用技能消耗灵力再恢复，以及八人房转交给队友后由队友恢复。

| ID | 验收 |
|---|---|
| IS01 | 机制门禁、已注册道具、恢复值边界与单属性配置，兼容机制 59。 |
| IS02 | 技能消耗后恢复，按缺口截断，成功扣一份并发布实际值。 |
| IS03 | 满灵力、冷却、重复请求和过期库存修订的原子行为。 |
| IS04 | 转移、成员隔离、重连和结算只入账剩余净份额。 |
| IS05 | 普通 Node 和 H5 跑通四人使用和八人转移后使用。 |
| IS06 | Rust、Node 回归及同候选离线交付，验证机制 59 兼容。 |
