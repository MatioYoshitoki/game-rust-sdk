# SDK-5-48 恢复道具附带自身状态

对应 R3.1/M02 和 R3.2/M03。目标 SDK 0.50.0、机制 65、schema 7、协议 6。机制 65 的 `member_item_use` 可选 `on_use_self_statuses`，配置 1～2 个互不重复、已登记且允许自身施加的状态 ID。复用现有气血与灵力恢复、属性修正、吸收盾和自身持续治疗。自身持续伤害、免疫、驱散和新增状态类型留在状态机制范围。

用药先校验本人库存、修订、冷却，并计算实际恢复量。至少有一项实际恢复时，预检整组状态的容量，再一次提交恢复、消耗、库存修订、冷却和自身状态。恢复均为零时返回 `INVALID_STATE`，整组状态容量不足时返回 `CAPACITY`。失败时所有上述状态保持原值。现有状态的刷新、忽略、叠层、到期及退出清理规则适用。附带状态的强度与时长由引用的定义提供。

同一请求重试沿用原结果。本人通过现有私有用药事件、状态事件与快照读取结果。同局重连保留状态截止和冷却，结算按剩余净拾取量执行。样例以原资料的恢复加状态组合为依据，四人房验证气血恢复与攻击修正，八人房验证灵力恢复与防御修正。

| ID | 验收 |
|---|---|
| SR01 | 验证版本门禁、合法引用、1～2 个去重状态、自身持续伤害与非法引用拒绝。 |
| SR02 | 实际恢复和附带状态同一次提交。满值、修订冲突和状态容量不足时完整拒绝。 |
| SR03 | 成功只扣一份、递增一次修订、启动一次冷却。重复请求不再次施加。 |
| SR04 | 本人状态和实际属性变化正确，队友收不到私有事件。状态可到期，同局重连保留时限，退出按净量结算。 |
| SR05 | 普通 Node 和 H5 跑通四人和八人样例，从击杀拾取、恢复和状态生效，到到期与结算。 |
| SR06 | Rust 和 Node 回归通过。同一交付包可在空 Cargo 缓存离线构建，机制 64 品质恢复样例可在新宿主运行。 |
