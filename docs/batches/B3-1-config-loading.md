# 地图配置启动加载与版本固定

日期：2026-11-03。按用户确认，采用启动读取、校验、预处理、只读缓存和每局版本固定。先补配置加载能力，再继续后续玩法。

## 范围

Rust 从外部清单读取现有 B1/PVE 格式，计算原文件 SHA-256。加载期间检查结构、文件大小、地图单元、地形能力和点位足迹；PVE 另用实际导航校验出生到撤离/怪物点的可达性。RLE 总量/索引校验通过后才展开。每份相同 id/hash 只解析和展开一次；同进程 Runtime 共享不可变目录与 PVE 数据，World 独立。

每局 Create 精确绑定 configId/hash。文件修改不改变已加载数据，服务重启采用新版本，不热更新活跃 World。H5 将启动配置复制到自有快照目录，之后创建的 Rust 子进程也使用同一快照；查看已有对局时按该局版本读取，渲染缓存随版本失效。

配置原文与哈希持久保存在 SQLite `config_versions`；重启恢复旧资产责任时使用原版。源清单附带原始 B1/B3-1 归档，供首次升级已有账本时补全旧版。坏配置、缺少当前责任所需旧版、损坏版本均在 HTTP 监听前失败，不重置资产或猜测规则。

当前 H5 仍是每局独立 Rust 进程，进程间各有缓存；本步不改变进程模型，不据此宣称战斗吞吐量提升。存储恢复仍只恢复 Closed 资产责任/结果，不恢复战斗现场。

## 清单和操作

```json
{
  "schema_version": 1,
  "active": {"b1": "b1.json", "b3-1": "forest-custom.json"},
  "archives": ["versions/old-forest.json"]
}
```

清单引用须为包内相对 `.json` 文件，禁止绝对路径、`..` 与逃出包目录的符号链接。清单最多64KiB，每个文件最多1MiB；当前清单支持1～16个active，必选b1；b3-1/b3-2及自定义别名可选；归档最多30项，active与archives合计最多32项。超限启动拒绝，不自动删掉旧责任数据；长期运营的版本保留/归档迁移另行交付。

地图修改建议复制 `config/b3-1.json` 为新文件，并更新 `active["b3-1"]`，保持来源导出文件可独立核验。

```sh
./target/debug/kernel-host --configs /绝对路径/catalog.json --catalog
node adapters/h5/server.mjs --configs /绝对路径/catalog.json
```

使用同一现有二进制即可换图。`npm run h5 -- --configs ...` 也支持，但会照常先检查 Cargo 构建。库端使用 `Arc::new(ConfigCatalog::load(path)?)` 和 `Runtime::with_catalog(catalog.clone())`；启动加载错误交给调用者处理。默认构造器首次从 `MATCH_CONFIG_MANIFEST` 或 `config/catalog.json` 加载一次。

本步允许地图ID、边界/格子、调色板通行/阻挡/速度、出生/撤离点与三只怪物点位改变。PVE 尺寸4～512格、32单位格子、平面高度40，速度0～2（可通行格必须大于0），调色板最多64项，怪物点位仍为3个。B3-2追加普通储物袋点位（最多8个），宝物规则固定，见后续[B3-2规格](B3-2-pouch.md)。B1 校验点位足迹，不提供自动寻路。支持范围之外的地形伤害、高差、技能、掉落和结算规则会明确拒绝；新增机制要先实现并另验。规则指纹由当前支持的批次语义确定，不从编译内嵌地图读取。

以上数值限制为该批次初版的历史范围；CONFIG-1已升级新格式为schema2：格边4～128、平面统一高度0～10000、地形速度0～10、怪物0～32、容器0～16，并开放已实现机制的合法参数。新格式不使用数值指纹；字段和当前限制见[配置v2目录](../interfaces/configuration-v2.md)。未知机制仍拒绝，旧schema1按历史语义解释。

## 验收标准

| 编号 | 场景 | 必须结果 |
|---|---|---|
| C01 | 同一目录重复引用、多个 Runtime 共享 | 两份基线解析一次，PVE展开一次；共享配置/格子；删除源文件后仍可创建与排空输出 |
| C02 | 错哈希/非法包/坏地图 | 精确拒绝；错误RLE、索引/巨量计数、边界、点位、速度和未支持规则不能进入运行期 |
| C03 | 服务启动后修改原文件，再创建新局 | 当前服务与新 Rust 子进程继续使用启动快照 |
| C04 | 修改地图后重启、二进制不变 | 新哈希/地形被采用，新局绑定新版；不要求重新编译 |
| C05 | 旧版待核对结算遇到新版配置 | 旧局图与旧哈希一致，原 operationId/金额不变，World不复活 |
| C06 | 旧版核对、重复强杀重启 | 仅一次发奖，库存/逐物品/修为和原冻结责任一致 |
| C07 | 缺失/损坏旧版本或非法新地图 | HTTP监听前失败，已有资产内容原样保留 |
| C08 | 读取其他所有者的旧局配置 | 返回404 |
| C09 | 回归与测量 | 原B1/B2/B3完整回归并绑定源码；记录加载/缓存访问微测量，不替代正式容量 |

运行 `python3 scripts/verify_config_loading.py`。首次专项为7项新增 Rust 测试、9项真实进程/浏览器检查（B3-2再增加3项配置测试，当前共10项）；机器报告在 `artifacts/config-loading/verification.json`。完整执行结果见 [本步验收记录](../evidence/config-loading-2026-11-03.md)。
