# SDK-5-88 同模块：有条件的单位激活与状态组合

2026-11-09，CB01～CB24，继续归 DELIVERY-01 / R3.1～R3.3。先冻结范围和验收，再在隔离候选中实现，不改动正在复验的 0.98.0 运行时。

原吞元阶段配置要求：先按本人的已有层数放大本次当前资源夺取预算，再消费三层，同时向自身和严格绑定目标授予五秒的独立攻防修正；圆满自身状态另有吸血。资料的“偷取攻防”实际参数是自身攻防各提高 5%、目标各降低 5%，并非转移目标的绝对属性点数。本组不新增按功法 ID 执行的分支。HP 夺取采用哪条管线仍等待已提出的产品裁定，测试中的显式策略不代替原内容选择。

## 配置与执行范围

1. 可信技能资格增加可选的熟练阶段行上界，与既有下界组成闭区间。索引来自已有可信成长输入，未提供记录不能冒充零阶段；原经验到阶段派生仍保留 R5.1 归属。
2. 增加严格敌对单位技能的原生提交事实，携带真正绑定的目标身份和动作分类。保留旧 SkillCommitted 的自身上下文。单位即时效果、单位弹道及定向引导在同一事务提交点产生新事实；方向/地面/自身技能不伪造目标。NPC 尚无对应目标技能入口时不声称覆盖。
3. 增加有界的自身/对方状态组合效果。一个触发条件只消费一次，预检考虑消费后的状态、双方身份、状态政策、控制替换、重复策略及两端容量；组合全部可用才产生收益。失败不消费条件、不启 ICD，已经合法提交的主技能及费用继续按原事务处理。状态复用已有实例与生命周期，无通用脚本或回调。
4. 当前资源夺取增加按本人来源状态层数的可选倍率。来源、状态、每层倍率、加成上限及 multiply_base / add_current_bps 乘区均由配置初始化；从当前合法层数采样，以宽整数合成后一次取整。预算在提交或触发消费前冻结，后续消费/换槽/层数变化不改本次预算；同一预算分配给原引导跳数，不每跳重算。即时、引导和命中触发沿相同金额口径执行。

严格装载将拒绝 null、未知字段、无效引用、非法阶段区间、不受支持的状态组合及超过资源 100% 的最高倍率。配置缺省保持旧行为。组合效果不加入结束/门槛/终结的派生叶子集合，不能借它绕过既有递归边界。

## 同批补齐：既有数值状态的持续时间刷新

原阶段表另要求“击杀将吞元时长刷新至 10 秒”。现有 ApplySelfStatus 对 Stack 会新增一层，不能当成仅刷新时长。本组一并补齐有类型的 refresh_status_duration：只操作本人来源、指定持有者的既有非周期数值状态，缺失/过期不创建；保持实例、层数、原施加时刻、来源分类和记录，仅把绝对截止设为“当前时刻 + 配置时长”。时长可显式提供，省略时取定义基准时长；沿实时有害缩时，最短 1ms。控制/免疫标记、护盾及周期载体不在本操作范围，派生叶子维持原允许列表。

消费后的预览必须仍有该实例；普通 Stack 被整份消费后不能借刷新重建，显式计数器消费到 0 可保留并刷新。已到期、来源/持有者无效、状态政策拦截时不消费条件或 ICD。读数、恢复或财务责任不因延长状态重复发放。
