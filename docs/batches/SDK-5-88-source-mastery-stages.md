# 功法阶段配置与身炉化生验收

本组属于 DELIVERY-01。SDK 通过 `combat_rules.self_statuses_by_mastery` 为同一个自身技能选择提交状态。表按技能 ID 索引，行按可信熟练度的零基索引递增。提交选择满足下界的最后一行，该行完整替换 `on_commit_self_statuses`。无可信记录或未达到首个下界时，使用技能显式声明的默认状态。技能 ID、费用、冷却、装备校验和发布共用原路径。状态选择同时用于请求预检和提交重验。

冷加载拒绝非自身技能、缺省状态列表、空表行、重复或乱序下界、成长模型不可表示的下界、重复或无效状态引用。每个技能最多 16 行，每行 1～2 个状态。状态继续受既有自身施加限制。客户端沿用原输入，阶段索引由可信 `CombatBuild` 提供。

使用原 `cultivation-combat-profiles` 的五行和 `cultivation-combat-identity.DESIGN` 的累计阶段规则验证身炉化生。五个阶段使用同一技能 ID 和同一份房间配置。原阶段表明确初始道种为 1，最多 3 层。使用原技能表和施法生命周期的瞬发、1800000 灵力、80 ms 后摇和 60000 ms 冷却。数值与状态定义进入样例配置。

| 验收项 | 预期 |
|---|---|
| 阶段 1 | 12 秒，固定吸血 15%、减伤 20%。有效直接动作结束时叠 1 层。 |
| 阶段 2 | 12 秒，额外吸血为每层 3%。当前动作使用已有层数，随后叠层。 |
| 阶段 3 | 12 秒，首次跨到 3 层时清除 1 个可驱散负面。继续命中保持上限且不再净化。 |
| 阶段 4 | 15 秒，多次有效接触的同一动作也只叠 1 层。叠层保留原绝对期限。 |
| 阶段 5 | 15 秒，自然到期按窗口记录的实际伤害恢复 10%，上限为到期时最大生命的 20%。退出清理不发放恢复。 |
| 多人与失败 | 同一 World 的两个可信阶段选中各自载体。重复输入不多扣费。选中载体放不下时不扣费、不启冷却、不改状态。旧配置沿用原状态列表。 |

宿主在 `Create` 的座位中写入 `combat_build.powers["yishen-weizhong"].mastery`，取值 0～4，样例成长模型为 `mastery-demo`。通过 `kernel-host --configs <清单路径> --catalog` 验证冷加载。[独立目录清单](../../examples/combat-host/mastery-stages-catalog.json)

按原 `afterAttack` 分类记录直接伤害，叠层沿用主动窗口的绝对期限。SDK 0.104.0 的样例启用整次动作结束吸血，验证多接触合计、统一取整和先吸血后叠层。熟练经验到阶段的推导、圆满常驻基础属性、参悟分支和正式游戏接入按原工作包验收。[多段动作吸血验收](SDK-5-88-action-life-steal.md)
