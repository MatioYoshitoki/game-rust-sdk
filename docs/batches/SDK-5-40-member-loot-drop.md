# SDK-5-40 局内战利品丢弃与再拾取

对应 R3.1/M02 的丢弃动作及 M10 的共享整数物品转移。目标 SDK 0.42.0，协议 6，schema 7，机制 57。适用同一 PVE World 的 1～8 名成员。最小闭环为击杀并拾取战利品、主动丢到地面、同局成员拾取、退出时按最终持有量结算。

机制 57 可在对局配置中声明 `member_loot_drop: {"max_active":8}`。数量上限为 1～50 个同时存在的玩家丢弃实例，并纳入原有 World 地面资源预算。实例沿用既有地面资源寿命和固定步清理。普通 NPC 资源仍按各自规则产生。未声明时丢弃动作返回 `UNSUPPORTED`。

`drop_item` 提交 `item_id`、正整数 `quantity` 与本人 `expected_revision`。Rust 校验成员资格、版本、背包修订、可丢数量、地面预算和落点。可丢数量等于该物品本局净拾取量，也受本人实际背包约束。落点使用成员当前权威位置，要求完整玩家足迹可走。所有校验成功后一次建立公共资源并扣本人背包，背包修订只加一次。失败保留资源、背包和修订。宿主复用请求 ID 与连接代次规则。

资源沿用 `resource_spawned`、`pickup`、`resource_taken` 和 full/delta。玩家丢弃物允许本人或同局成员拾取，仍受容量、修订、有效期和距离校验，并额外要求拾取者与落点之间的玩家足迹直线可通行。两个成员争抢只允许一次获益。未拾取的丢弃物到期消失。同局重连保留已提交的库存和资源。重启继续只恢复既有金融责任。

使用既有结算结构。启用本能力时，`looted` 表示本局净拾取量，成功拾取增加、主动丢弃扣减。带入数量仍用 `carried` 表示。死亡损失按丢弃后的实际背包计算，`dropped` 继续记录终局损失。各物品满足 `carried + looted = kept + dropped`。现有资源总量校验与财务恢复可继续校验净值。

| ID | 验收 |
|---|---|
| LD01 | 机制与配置门禁，严格输入，旧版本与未启用对局兼容。 |
| LD02 | 正常丢弃一次生成公共资源并扣本人库存，重复请求幂等。同局拾取只成功一次，退出结算守恒。 |
| LD03 | 错修订、带入份额、超量、地面配额、阻挡、越距、容量、过期均拒绝或清理，失败无部分变更。 |
| LD04 | 成员隔离、重连、私有背包和公共 full/delta 投影。已提交结算可按原金融责任恢复。 |
| LD05 | 普通 Node 与真实 H5 跑通四人转移和八人竞争，所有成员完成结算。 |
| LD06 | 同候选 Rust/Node 回归、格式与 Clippy、空缓存离线交付和机制 56 包外回归。 |
