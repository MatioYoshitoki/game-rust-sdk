# SDK-5-60 多人自身技能即时治疗

对应 R3.3/M04、原行为规格 §4.3 及 `factor_heal` 的自身 `onSkillCast` 切片。目标 SDK 0.62.0、机制 77、schema 7、协议 6。多人 PvE 成员沿用 `CastSelf` 和 `self_status` 技能机制，在技能定义内声明 `self_heal`。本批支持治疗型技能单独绑定这一效果。其治疗量配置为固定 `amount`（1～1000000）或自身最大气血万分比 `max_hp_bps`（1～10000），二者必选其一。可选 `overheal_shield` 沿用已验证的显式转盾配置和刷新吸收盾规则。

治疗仅在技能成功提交时执行一次。先扣本次气血和灵力费用并登记冷却，再以此时的最大气血和有效受治疗倍率计算治疗，向下取整并按扣费后的缺口裁剪。满血照常提交并发布实际回复 0，显式开启转盾时才处理溢出。状态槽不足只拒绝转换盾，保留本次气血回复和技能提交。取消、保护、资源不足或退出导致未提交时没有治疗与护盾。

本人先收到 `action_committed`，再收到 `heal_resolved`（`heal_kind: self_skill`），如有转盾则沿用 `shield_granted` 或容量拒绝事件。沿用现有私有发布和同一动作的去重及冷却，不增加调用或客户端数值计算。

| ID | 验收 |
|---|---|
| IS01 | 机制 77 接受固定值或最大气血比例，支持有无显式转盾。拒绝旧机制、非自身技能、同时绑定提交状态、非法金额及非法盾引用。 |
| IS02 | Rust 验证气血费用先扣、受治疗倍率、向下取整、实际回复上限、显式溢出转盾和本人事件顺序。 |
| IS03 | 验证满血且未配置转盾时只提交一次且实回 0；取消和资源不足没有治疗；状态槽不足保留回复并只拒绝盾。 |
| IS04 | Node 和 H5 在普通时钟四人和八人房施放、验证本人治疗和授盾、同房隔离、到期、退出结算。四人满血样例基础 100、实回 0、授盾 50；八人先扣 160、按最大气血比例治疗 300、实回 160、授盾 70。 |
| IS05 | 同一交付包通过仓库外空缓存离线接入、机制 76 自身 HOT 转盾兼容复验、Rust 和 Node 回归。 |
