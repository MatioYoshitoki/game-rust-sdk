# SDK-4-1 交付包与独立接入验证

本批先冻结范围与验收，再实现。交付现有 SDK 的本地分发包，使用现有样例和接入方配置验证独立使用。

## 交付范围

- crate 升为兼容补丁版本 0.3.1，协议 1/2/3、配置 schema 1～4、机制版本 1～18 和恢复 schema 1 保持。增加无需配置即可查询的 SDK 支持信息，不新增 Client 方法或玩法能力。
- 建立明确 Cargo 源包文件清单，生成实际 `.crate`，包含源码、锁文件、独立说明和回归所需数据；排除工作区历史资料、运行账本、构建缓存和验收产物。回归数据标明用途，游戏配置仍由接入方提供。
- 生成本地 `.tar.gz` 交付包：已验证 Cargo 源包及展开源码、锁定的第三方依赖源、当前平台普通时钟 JSONL 二进制、Rust 最小消费方、Python 持久参考宿主、独立示例配置、支持矩阵、文件摘要及使用说明。
- Rust 消费方只引用包内 SDK；JSONL 宿主只依赖包内二进制及 Python 标准库。流程显式传配置和账户事实，状态写到调用方目录。原便捷默认入口继续兼容，交付流程不依赖它们。
- 支持信息包含 crate 版本、协议/配置/机制映射、清单/恢复版本、已注册策略和编译时加速特性。二进制准确声明目标平台；源码和供应的依赖可供接入方自行构建，其他平台由对应门禁验收。
- 本批为本地工程交付，不发布 registry/npm，不新增游戏、生产库存、远程认证或跨机接管。编译需要本机 Rust 工具链，参考持久宿主需要 Python 标准库 SQLite。

## 验收标准

| 编号 | 通过条件 |
|---|---|
| DL01 | 通过 Cargo package 产生并验证真实 `.crate`，文件清单明确，无工作区绝对路径引用/本地数据库/target/历史资料等非交付内容；记录源包和整包哈希。 |
| DL02 | 查询包内普通二进制的 SDK 信息无需配置文件；支持矩阵与编译版本一致，加速功能关闭。配置错误/缺失、版本错配明确拒绝，不能静默改用 SDK 回归场景。 |
| DL03 | 交付包在仓库外独立解压，以全新 CARGO_HOME、离线模式和包内第三方源构建 Rust 消费方；仅引用包内 SDK，不读取原仓库或用户 Cargo 缓存。 |
| DL04 | 在验证副本删除 SDK 回归配置及嵌入测试用 JSON 后，普通消费方仍能从无 config 目录启动，显式加载接入方自有别名/id/hash/事实，完成创建、入场、输入、结算、关闭。 |
| DL05 | 包内普通时钟 JSONL 二进制与持久宿主完成协议 2/3 的战斗/拾取/终局闭环；Unknown 查询、原正文重试、未就绪补偿、激活后关闭、拒绝与授权核对按原契约处理，资产只生效一次。 |
| DL06 | 包内真实宿主在结算前/提交后及活跃局强杀，连续两次重启按包外状态中的原配置/结果/金额/业务 ID 恢复；外部配置改动不重算旧责任，最终 World=0/未决=0。 |
| DL07 | 从交付源包执行默认和 all-features 同一组原 643 项 Rust 测试、Clippy 与 JSONL 严格/超长行检查；协议 1/2/3 原配置与冻结责任保持。 |
| DL08 | 独立说明、目录职责、工具链/平台及版本兼容要求可核对；校验摘要能发现包文件缺失或修改；证据记录构建命令、工具链、平台、供应依赖和独立消费结果。原 20 份场景及协议 2/3 示例配置 raw/hash 保持。 |

入口：`python3 scripts/package_sdk.py` 构建；`python3 scripts/verify_sdk_4_1.py` 执行独立验收。完成后再更新执行记录和完成状态。
