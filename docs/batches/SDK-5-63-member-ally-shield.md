# SDK-5-63 指定友方吸收护盾

对应 R3.1、R3.3/M02/M04 及原行为规格 §4.2、§4.4、§5.1。目标 SDK 0.65.0、机制 80、schema 7、协议 6。新增 `ally_shield` 技能机制，沿用 `cast_unit` 指定同一 World 的另一名成员。技能 `shield_status` 引用一个 `absorption_shield` 定义，采用 `refresh` 和 `source_scoped: true`。射程、护盾比例、持续时间和聚合上限从配置读取。

接受和提交重验目标代次、存活、就绪、保护、射程和视线。目标状态容量不足或目标失效时不扣费、不开始冷却。成功提交时按目标最大气血计算申请量，并与目标已有护盾共享上限。同来源刷新保留实例 ID，按原护盾规则补足并重置期限。不同来源分别保存余额，新授予只裁剪本次来源。收到伤害时沿用已有护盾消耗顺序，先吸收再扣气血。

护盾状态只进目标的私有快照。授予及生命周期事件发给来源和目标，吸收明细发给承伤目标。来源退场清理它施加的盾，目标退场清理挂在其身上的盾，继续沿用原有到期和耗尽规则。

| ID | 验收 |
|---|---|
| AS01 | 机制 80 校验友方盾引用，拒绝旧机制、非盾定义、非来源分组或非刷新策略。 |
| AS02 | 验证严格友方身份、提交重验和目标状态容量，失败时费用与冷却保持。 |
| AS03 | 验证目标最大气血、同来源补足、不同来源共享上限、按序吸收及来源或目标离场清理。确认快照与事件归属。 |
| AS04 | Node 和 H5 在四人、八人房用普通时钟验证显式选人、目标获得护盾、NPC 来袭先消耗护盾、退场清理及每人结算一次。四人来源先退出，八人目标先退出。 |
| AS05 | 同一交付包通过仓库外空缓存离线接入、机制 79 友方 HOT 兼容复验、Rust 和 Node 回归。 |
