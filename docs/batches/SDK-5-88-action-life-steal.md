# 动作结束吸血验收

延续 DELIVERY-01。原战斗设计要求多段攻击在整次 delivery 结束时按累计实际扣血结算一次吸血。`combat_rules.basic_attack` 和已注册伤害技能的 `combat_rules.skills` 可配置 `life_steal_timing: "action_end"`。缺省或 `"contact"` 沿用每次接触结算。NPC 和周期伤害继续使用接触结算。

SDK 以原生动作 ID、来源和实体代次归集实际扣血。动作中还有弹道、区域或引导时只记账。最后一个计划结束后，先按配置的基础吸血与当时来源状态计算比例，再在同一动作的终态叠层等效果之前治疗一次。统一治疗链在此刻读取受疗倍率和生命缺口。护盾吸收、过杀、闪避、周期与派生伤害均不计入。这个采样时点使动作结束前获得或到期的状态按结束时的有效值处理。

| 验收项 | 预期 |
|---|---|
| 多段取整 | 多目标分步扣血，前段不治疗。最后一段结算时按实际扣血总和取整一次，之后才增加道种层数。 |
| 伤害基数 | 护盾、目标死亡和来源代次分别核对。已经造成的实际扣血在目标死亡后仍计入。 |
| 生命周期 | 中断引导保留已提交计划的伤害，等子计划结束。来源死亡、退场或保护时清理账本，重连不补发旧收益。 |
| 容量 | 共用 `max_pending_action_totals`。触及上限或安全整数边界，丢弃该动作的终态累计，原扣血保留，后续接触不能补算部分收益。 |
| 兼容 | 冷装载拒绝未知取值、空值、NPC 和周期 `action_end`。现有接触模式、治疗事件和客户端输入保持原口径。 |

身炉化生样例用当前层数产生 18% 吸血。四次各扣 5 点的接触分步发生，在动作结束时回 3 点生命，随后道种从 1 层变为 2 层。完整武器投放、位移、回灵与冷却时序沿各自原工作包验收。

本地复验使用 `cargo test --offline --locked --lib action_life_steal`。SDK 0.104.0 的原始条目哈希、Rust 回归和包外宿主结果保存在[验收记录](../evidence/SDK-5-88-action-life-steal-2026-11-09.json)。
