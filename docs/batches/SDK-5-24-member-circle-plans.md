# SDK-5-24 多人圆形区域计划

2026-11-05；实现前冻结GA01～GA12。起点0.25.0/协议6/schema7/机制40；目标0.26.0/协议6/schema7/机制41。固定1～8必需成员PVE，以既有ground_circle和ground_field验证SDK-5-23统一实体/关系/伤害入口；同一个区域计划承接单次或有限周期，复用ContactBudget，不按地图或成员复制伤害逻辑。完整R2/R3/M02/M03/M04/M05/M14仍开放。

## 范围与配置

复用cast_ground{skill_id,position:[x,y]}与原ground_circle/ground_field字段。接受/提交重验有限世界坐标、严格可行走落点（不吸附）、中心射程和视线；来源资格、共享准备/后摇、独立技能CD沿原规则。提交前失败或容量/灵力/整组self状态不足，原子无扣费/CD/授状态/计划。提交付费/CD一次，self绑定先施加，再冻结有效ATK；中心不跟随来源或目标，NPC按实际位置参与每次接触。

ground_circle提交后等待warning_ms，一次结算；warning=0也最早下一固定步，不能同提交步伤害。ground_field等待预警后再等待tick_interval_ms首跳，计划截止点排除，最多128跳；按计划时刻、区域创建顺序补跑，稳定不漂移。字段duration_ms/tick_interval_ms/contact_policy必须配置，复用每跳目标上限、总成功接触预算和repeat_interval_ms（0=每身份一次，正数含等号；以scheduled_at_ms计时）。目标历史含完整生命代次，预算最多128成功，闪避不消耗，HP全盾吸收仍消耗且施加原命中附带。单次圆形按中心距离平方、稳定ID/代次处理当前合格目标，每身份一次。

members新增可省略area_capacity：仅机制41必须给1～8整数，旧版本拒绝此字段，旧JSON不修改。单次/持续共享全World容量，准备可并存，提交时争抢空位失败不付费；方向/单位弹道和自身技能不占区域槽。按配置的容量、最大目标数/预算与成员数校验输出工程预算，超预算在I/O前拒绝；容量×单区最大总接触次数不得超过128份全World历史额度。半径、比例、时长、绑定、重复策略、技能槽和全部数值由配置初始化。

## 统一战斗与生命周期

圆半径含目标足迹，圆心→目标的弹道遮挡有效；来源→落点视线仅接受/提交检查。接触通过统一hostile资格及当前代次，当前DEF/盾、既有倍率/随机/状态/实际HP/死亡/归功与掉落链；直接接触不因多目标重复付费，不能伤友方或归途NPC，DOT不重复触发这些接触。死亡/离开/同ID新代不回用旧历史，真实NPC复位允许新代作为新目标。攻击量只在提交冻结，防御/护盾在每次结算读取。

来源后台或同World重连中断未提交准备，保留已提交区域/预算/绝对期限，不重授/补费；来源settling/死亡/退出/断线超时立即清其区域，不等待金融回执，其他7席继续。绝对终局/Close清全部计划；已付成本不退。单次完成、到期、命中预算耗尽、来源失效各仅结束一次。重启只Closed金融责任，不恢复区域/周期/盾/World/发布基线。

## 发布与权限

SnapshotV4新增可省略areas数组：机制41始终输出（含空），旧机制省略、null拒绝。SnapshotDeltaV6的areas为存在时完整替换数组，空数组明确清空，省略不变；不把None解释为清空旧字段。公开计划用World生成的全局id和来源EntityRef，不暴露私有输入request/action ID、冻结攻击/绑定/灵力/CD或状态ID。字段包括技能、圆心/半径、创建/激活/截止/下一计划时刻、完成/总跳数、有限接触预算与目标历史；均为Rust战斗事实。

公开AreaStarted/Tick/Ended沿EventV4广播上述计划身份/计划时刻与合法目标身份；本人准备/ActionCommitted沿原私有事件，保留输入关联。Rust投影后再diff，Rust/JS客户端验证来源/位置/时序/跳数/预算/历史、唯一计划ID与原子基线；坏帧不污染缓存。旧DTO可选字段省略，公开Rust字面量补Option字段；六类Client、协议、金融/恢复DTO不变。
