# SDK-5-29 施法阶段移动

对应 R3.1/M02 及原施法生命周期设计 §6.3。起点 SDK 0.30.0，目标 SDK 0.31.0、协议 6、schema 7、机制 46。适用固定 1～8 成员 PVE 和现有七类技能的固定准备、提交和后摇。

每个技能可选配置 `cast_movement` 对象，其中 `preparation` 和 `recovery` 都必须是完整策略。策略为 `{"kind":"free"}`、`{"kind":"locked"}` 或 `{"kind":"slow","speed_bps":5000}`。减速比例是 1～9999 的整数基点，万分之一为一基点。省略整个对象时两个阶段均自由移动。非自由策略要求对应阶段时长大于零。显式 null、缺少阶段、未知策略、额外字段、非法基点及旧机制中的该字段均在加载时拒绝。机制 46 继承多技能槽与生命成本。

沿用 Rust 权威步进顺序。准备策略在动作接受时冻结，并作用于提交步的移动子阶段。随后从成员当步实际位置重验目标和计划并提交。成功提交后，已冻结的后摇策略作用于之后的移动步，截止时间相等时恢复自由速度。拒绝提交不启动后摇。减速乘入现有地形移动预算，继续使用地图导航与碰撞。锁定期间位移为零，也不消耗导航路径。Move、Navigate、Stop 仍按原顺序修改最新意图。取消准备后立即解除准备策略。取消输入无法缩短已提交后摇。

保护、后台、失联和重连中断未提交准备并清除旧移动意图。重连保留已提交后摇的策略和原截止时间，重新就绪后使用新连接输入。成员退出和死亡清理准备及移动，同行成员继续。SDK 使用原位置、准备时间、后摇时间和私有提交事实发布结果。宿主复用现有输入与等距 H5。蓄力、引导、再施放以及按新移动打断属于后续切片。
