# SDK-5-91 局内资源、实例物品与竞争

DELIVERY-04 覆盖 R4.3、R4.4。SDK 提供可复用的资源和库存机制。宿主提供奖池、位置、物品定义及具体数值。先验证多人 World 的资源供应、容器和堆叠库存，再接入实例身份、贡献优先期与死亡遗物。

| 验收 | 可判定结果 |
|---|---|
| RL01 奖池 | 固定条目确定执行，独立概率与分组概率覆盖 0 和 1，组内无放回，数量包含两端。未知物品和越界配置在装载时拒绝。 |
| RL02 环境补充 | 使用宿主提供的候选点和本局实际放置的共享容器锚点。落点经足迹与通行检查。预算不足或阻挡时保留本次抽样，拾取或到期清空后再按配置补充。恢复校验使用本局最大供应量。 |
| RL03 容器 | 普通成员和参战 NPC 共用占用、守护校验、读条、落点、预算和费用事务。竞争、取消、保护和退场释放占用。私有和隐藏容器按接收者发布，完成后原地按配置刷新。 |
| RL04 部分拾取 | 实际可容纳的数量入包，余量留在原资源。满包和版本冲突不改库存或资源。重复请求幂等，其他成员可继续拾取余量。 |
| RL05a 一次性掉落与竞争 | 怪物模板可绑定统一奖池。落点或独立预算暂时不足时，冻结同一抽样并重试；每次击败最多投放一次。贡献按实际扣血累计，召唤伤害归其所有者，平局按参与者 ID，回巢恢复时清零。掉落公开可见，优先期内只有贡献最高的在场成员可拾取，期满或该成员终局后公开领取。多人恢复账本按一次性来源数量校验供应。 |
| RL05b 实例与遗物 | 独立实例跨地面、库存与终局保持身份和宿主定义的品质，不可堆叠。遗物生成须原子提交库存转出与合法落点，失败保留原库存；公开投影与近距授权内容分离。重复领取按请求复用结果，过期修订拒绝，部分领取保留余量。跨成员转移前后，终局及重启恢复后的资产数量与实例所有权守恒。 |
| RL06 整体验收 | 用包外双成员和参战 NPC 场景验收资源、库存与终局守恒。原物品及宝物数据由宿主接入。 |

### RL05b 本次范围

- 统一奖池按宿主声明生成单件实例，每件占一格。奖池、地面、本人库存和结算保持同一实例 ID、物品定义和品质。结算按实例身份提交，恢复拒绝跨席位重复实例、越界供应和定义不符。
- 遗物从本局获得的合格库存中按宿主的死亡抽选规则转出。宿主可排除物品，实例需显式允许转入遗物。携带入场库存、装备位和接入方既有实例数据留在原资产账本。单个死亡席位最多生成一个遗物，空匣也保留到关局。容量不足或足迹无合法落点时，保留原库存并继续结算。
- 遗物公开位置、死者身份、余堆数、最高品质和修订。内容通过有视线和距离约束的开启动作私发。取单条或全部使用遗物和库存修订；重试按原请求去重。重连需要重新开启。部分领取只提交实际装入的资产，自动席位使用同一开取动作。
