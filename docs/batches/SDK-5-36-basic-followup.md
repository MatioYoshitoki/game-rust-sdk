# SDK-5-36 普攻冷却跟进

对应 R3.1/M02 及原手动动作契约中「已越过攻击点可在当前普攻冷却缓存下一击」。目标 SDK 0.38.0，协议 6，schema 7，机制 53。范围为同 World 1～8 成员 PVE 的现有普通攻击。

对局可选根字段 `basic_followup: {"grace_ms":150}`。宽限是 `step_ms` 的整数倍，范围为 0～1000 ms，0 仅保留首个可执行固定步。仅机制 53 允许声明。未配置时沿用原普攻门禁。普攻前摇、间隔、射程、速度与伤害仍取现有配置。

已提交一击且只剩其自身冷却时，可以发送原 `attack` 缓冲下一击。仍在准备、技能活跃、技能后摇或撤离读条时，沿用原门禁。缓冲时按现有最近敌人、射程与视线规则选取目标，冻结 NPC 身份代次和本次请求 ID。同成员保留最新有效输入，拒绝和重传不替换。排队不设新冷却，不创建弹道，也不占用技能准备。

Rust 在冷却结束后的首个固定步尝试释放。最晚消费时刻为该步加配置宽限，等号可消费。若到截止仍被动作占用则清除。释放与提交分别重验同一目标的身份、存活、敌对、射程及视线。目标失效立即拒绝，沿用本人 `action_rejected`，不改选目标。通过后使用原普攻准备和提交事务，从提交时位置与瞄准发射普通弹道并开始新冷却。飞行仍沿用原碰撞与命中语义。

停止或移动不清队列。有效新技能准备接管该待执行槽，失败输入保留。取消、后台、失联、重连、死亡与离场清理本人的旧意图。排队时拒绝开始撤离，取消后沿用既有撤离门禁。原首发与冷却继续有效。

本人协议 6 快照可选 `basic_followup`，包含请求 ID、目标代次、最早释放与最晚消费时刻。公共成员状态和其它成员的私有视图无该队列。Node 与 H5 沿用 `attack`。手动指定目标、前摇内同普攻缓存、自动追击和技能冷却跟进分别验收。

| ID | 验收 |
|---|---|
| BA01 | 配置、宽限与固定步边界严格校验，机制 52 与未配置行为兼容。 |
| BA02 | 已提交后的整段冷却可排队，前摇拒绝，最新有效替换，固定步和截止等号正确。 |
| BA03 | 释放与提交重验目标身份、射程和视线，失败无新弹道与冷却，成功只提交一击。 |
| BA04 | 幂等、技能接管、停止/取消、重连、终局和成员隔离，私有 full/delta 坏帧原子拒绝。 |
| BA05 | 普通 Node 和真实 H5 四人验证下一击提交，八人验证取消后仅首发与独立结算。 |
| BA06 | 同候选 Rust/Node、格式/Clippy、空缓存离线交付与机制 52 包外回归。 |
