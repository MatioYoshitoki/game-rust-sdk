# SDK-5-1 通用定时状态与防御修正

状态：**ST01～ST12受控验收通过**（2026-11-04）。SDK0.4.0/机制19；旧0.3.1包保持不变。证据见[执行记录](../evidence/SDK-5-1-status-2026-11-04.md)与[逐项映射](../checklists/SDK-5-1-acceptance.json)。

对应 [剩余工作 M03](../checklists/sdk-requirements-gap.md)，原需求 F-03，依赖 F-02/F-04 的现有动作/命中与 F-07/F-11/F-13/F-14 的既有闭环。[来源行为 §4.4](../../rust-match-kernel-v1.1/behavior.md)明确实例身份、开始/截止时间、重复策略、来源分组及到期撤销；本批只实现其中可独立验收的有限切片。

## 目标与边界

建立可供玩家和怪物复用的定时状态实例：**合法施法提交/弹道接触 → Rust 施加状态 → 后续真实伤害使用防御修正 → 刷新或忽略重复 → 到期恢复 → 终局/重连/复位/关闭正确处理**。用现有 PVE 回归场景的外置配置变体验证，不新增具名地图玩法或第二款游戏。

- 首个注册效果只修正 `DEF`，使用有类型的 `timed_defense_modifier`；允许正/负修正。防御提升不是吸收盾。
- 重复策略只支持 `refresh`、`ignore`，固定单层；按 `source_scoped` 选择是否分来源。`stack`、独立多层计时、其它属性、减速/控制、驱散、吸收盾、DOT/HOT、任意事件/表达式及完整旧状态目录均不在本批。
- 沿用一个玩家主技能和现有怪物弹道；不新增玩家技能槽/自身目标技能输入，也不提供直接施加/清除状态的公开命令。
- Rust 拥有定义编译与实例、时序、有效 DEF、清理和输出。Node/H5 只转交原操作、持久原业务、展示权威状态；不得发送状态完成/改 DEF 等事实。

## 配置与版本

本节为本批已实现的字段契约；后续扩展须单独定义版本和预期。

1. 在 schema 4 / 协议 3 的 PVE 配置中使用机制版本 **19**；schema 1～4、机制 1～18 和协议 1/2/3 的原解释保留。不为此变更资产/结果正文或恢复 schema。公开Rust DTO已增加字段，按既有0.x源码兼容策略提升为 **0.4.0**；当前支持信息由sdk_info或--sdk-info提供。
2. 新增 `pve.status_definitions`，最多 16 项，ID 唯一。每项为 `{id, mechanism, duration_ms, modifier_bps, duplicate_policy, source_scoped}`；ID 1～64 UTF-8 字节、无控制字符；mechanism 仅上述枚举；duration_ms 为 `step_ms..min(terminal_ms,3600000)`；modifier_bps 为整数 `-10000..100000`；重复策略只接受 refresh/ignore；source_scoped 必须为 bool。未知字段/效果/策略、缺字段、坏引用或版本不足启动失败。
3. 新增配套 `pve.status_rules`：`max_active_per_entity` 为 1～32，`defense_bonus_cap_bps` 为 0～100000。定义非空时规则必填，无定义不接受效果绑定。上限是有界资源/数值校验，不读取固定地图 ID。
4. 仅根 `skill` 和当前基础/额外怪物模板 `combat.projectile` 可声明 `on_commit_self_statuses` / `on_hit_target_statuses`，各为不重复的状态 ID 数组、最多 2 项，缺省为空。前者在动作正式提交时施加给施法者，后者在弹道合法接触并走完本次伤害/反击/死亡链后施加给仍存活的命中目标。普攻、区域技、治疗、重击等不新增状态触发绑定。
5. 两个钩子是有限已注册触发，不是可配置事件名/回调；本批新增引用必须全部可检查。持续时间、倍率、上限和绑定均由接入方配置初始化，不按技能或状态名字分支。

实施补充（2026-11-04）：为控制全量发布大小，全部预留实体（含玩家）的数量乘 max_active_per_entity 不得超过128；超出在加载阶段返回 CONFIG_STATUS_PUBLICATION_BUDGET。移除事件按原因聚合实例 ID，避免关闭时逐状态事件挤占已冻结业务输出。实例身份区分 participant/monster，并包含代和遭遇轮次，防止名字冲突。

## 运行语义

### 实例、重复与有效防御

- 实例身份包含稳定 instance_id、definition_id、来源实体 ID/代、目标实体 ID/代、applied_at_ms、expires_at_ms；怪物目标/来源必须包含当前生成/遭遇轮次身份。新实例 ID 在本局不复用，不能只用显示名去重。
- 合并键为目标身份 + definition_id；source_scoped=true 时再加来源身份。false 时同定义跨来源合并；refresh 更新为本次来源及本次起止时刻，保留 instance_id；ignore 保留原来源、参数及截止时刻，返回明确忽略事件，不偷偷延长。
- 存续区间为 `[applied_at_ms, expires_at_ms)`。按当前逻辑时刻先完成到期处理，再接受同刻动作/命中和属性计算。非步长整数倍期限在第一个到达/越过期限的处理点移除；定时处理和输入处理共用这条顺序，读取属性/快照不能刷新时间或重复触发事件。
- 有效防御从基础值推导，不直接累计改写原属性：`sum_bps = 所有有效 DEF 状态的 modifier_bps 之和`，`bounded = clamp(sum_bps,-10000,defense_bonus_cap_bps)`，`effective_def = floor(base_def × (10000+bounded)/10000)`。使用足够宽整数和装载期范围/产量检查。10000 是万分比单位，正修正合计上限由配置给出；不能把一次 buff 写进永久账户。
- PVE 所有既有物理伤害路径（普攻/弹道/范围/重击/反击/站位反噬等实际经过防御的路径）统一读取目标有效 DEF；原始伤害预算、暴击、金属性、最小伤害及死亡链保持所选旧配置语义。施加状态的这次命中先按旧状态结算，之后的命中才看到新修正；闪避/保护/阻挡/无合法接触不施加，合法零 HP 伤害接触可施加，致死目标不施加。

### 动作事务与容量

- 动作接受时固定本次配置定义/绑定；正式提交前取消不施加、不扣成本。提交时先预检全部 self 绑定可原子容纳，再提交原成本/CD与 self 状态；容量不足则本次动作以明确失败事件结束，不产生弹道/新 self 状态，不扣成本或建立新 CD。不能先施加一半再失败。
- `on_hit_target_statuses` 发生在已提交的独立命中之后：一次预检整组新状态槽，失败时整组不施加，发带原因的拒绝事件；已有伤害及成本保留，不重放命中或回滚战斗。refresh/ignore 使用已有槽，不因实体已满而被当成新增槽拒绝。
- 相同输入重试、同一弹道重复处理和重复传输回执不能再施加/延长一次。多个同刻命中按现有确定顺序处理；事件、实例和发布字节预算须纳入峰值校验，关键输出装不下时沿用明确故障/关闭契约，不静默丢状态事实。

### 生命周期和输出

- 同 World 前后台/断线/换代不清除定时状态，逻辑时间照常推进；重新就绪后的快照显示当前实例与剩余截止，不能通过刷新页面延长增益或提前解负面状态。
- 目标死亡/移除/换代、怪物真正归位重置、整组遭遇复位时清理其状态。本批状态在来源死亡/移除/换代或真正归位重置时也结束；后台/短线不算来源失效。来源清理按实例中固定身份匹配，不能清掉新代施加的状态；未来需要死亡后持续的效果须新增明确能力。
- 撤离/死亡终局不再接纳新状态；World 关闭前清理全部实例，关闭后不保留战斗定时器。只冻结原积分/物品/结果/资产责任，不把临时状态发为永久成长或库存。
- 新能力快照为玩家和怪物提供可省略的 `statuses` 列表及 `effective_def`；按稳定 instance_id 排序，展示定义、来源/目标代和权威起止时刻。新增施加/刷新/忽略/拒绝/移除事件，移除原因区分 expired、target_invalid、source_invalid、reset、closed；一次结束只发一次。具体 Rust DTO 需与这份语义同批更新。
- 机制 1～18 配置不出现新字段/事件，不增加 RNG 消费，历史金额和状态发布语义保持。新状态不会进入旧 IoState；进程重启只恢复已冻结资产责任，不重建状态/World。若恢复校验需新摘要，只能存最小业务证明并显式升级契约，不能暗中持久化战斗状态。
