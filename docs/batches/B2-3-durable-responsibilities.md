# B2-3 本地持久责任账与服务重启恢复

日期：2026-11-03。用户已授权实现。本批先用本地 SQLite 验证真实事务和强制退出后的收尾；不恢复战斗 World，不签收生产库存服务。执行证据见 [验收记录](../evidence/B2-3-durability-2026-11-03.md)。

## 范围与中断口径

- Rust 冻结原业务 ID、载荷、尝试和提交证明，输出不含 World 的 I/O 检查点；宿主先持久保存整批输出与责任，再执行库存事务或通知页面。
- SQLite 在同一事务中保存库存余额、寿元、修为、原请求、幂等提交凭据、fencing 和人工核对证明。查询不到记录仍不是未提交证明；取得文件独占权后，才可隔离已退出旧进程的未提交尝试。
- 服务启动先恢复当前所有者的实例责任，再开放 HTTP。恢复只创建 Closed 的责任账；原 World、动作和计时器不复活。
- **已有持久终局责任**：按原 ID、原金额查询或履行；已提交不再发奖。**没有持久终局责任的中断局**：核实原入场，已扣费则退还原 5 份玄铁与 1 年寿元；未提交则结束准入。未冻结的战利品和修为不结算。
- 已转人工的责任继续保留原核对身份；只有已有持久提交证明才可自动回填结果，否则仍显示待核对，并阻止创建新局。
- H5 重新打开后恢复结果、余额、闭环进度和核对入口；仍打开的页面也可识别服务恢复代。旧 HTTP 连接不能关闭、输入、确认或核对新代实例，其他所有者不能读取它。

## 验收标准

| 标准 | 必须观察到的结果 |
|---|---|
| D01 入场边界 | 保存意图后、SQL 提交前、SQL 提交后、Rust 收据处理后强杀；未提交不扣费，已提交只扣一次并只补偿一次 |
| D02 战斗中断 | 活跃局强杀，恢复 World=0；确认入场退还，寿元归还，无额外战利品/修为 |
| D03 终局边界 | 排空未落盘、意图落盘、SQL 提交前后、回执后、最终结果落盘后分别强杀；按上述冻结边界处理，不重算、不重复奖励 |
| D04 补偿边界 | 补偿已提交未送达回执时再次强杀，重启查询同一原 ID，补偿计数仍为 1 |
| D05 人工边界 | 待核对重启仍未决；人工 SQL 提交前后、回执后强杀，修正和凭据一起提交，重复重启只履行一次 |
| D06 重启幂等 | 多次重启资产不变、输出身份不碰撞、查询数量有界；Rust 至少 100 次恢复验证 |
| D07 视图与身份 | 原 cookie 读到原结果/待办，闭环完成显示 5/5；World=0；旧连接拒绝，其他所有者不可见 |
| D08 失败封闭 | 检查点、余额校验或配置身份损坏，启动失败且不开放 HTTP，不重置或修改原资产；第二进程不可写同一账本 |
| D09 回归 | 原 B1、H5 等距/性能、连接恢复和 I/O 超时证据重新绑定当前源码并通过 |

## 运行边界

默认文件为 `.local/h5-lab.sqlite`，`--state /绝对路径/lab.sqlite` 可指定文件；停止服务后须保留数据库及其 WAL/SHM 文件。使用 Node 内置 SQLite，当前运行环境为 Node 22.23.3。端口 0 且未指定状态文件时使用隔离临时账本供回归测试。

每个验证实例仍有独立的初始 100 份玄铁，开始新实例不代表跨局账号经济；旧实例的持久幂等记录保留。数据库使用 WAL、FULL 同步与单进程独占；本批证明本机进程崩溃与事务回滚，不证明硬盘断电、磁盘毁损、备份恢复、多机故障转移或生产数据库隔离。SHA-256 用于检测意外损坏，不是对有权修改主机者的签名保护。

验证入口：`python3 scripts/verify_durability.py`。强杀注入仅通过服务进程命令行启用，浏览器 API 不开放恢复状态写入、时钟控制或崩溃开关。
