# SDK-5-30 按下锁向蓄力

对应 R3.1/M02 及原施法生命周期的 charge 准备策略。起点 SDK 0.31.0，目标 SDK 0.32.0、协议 6、schema 7、机制 47。覆盖同 World 1～8 成员 PVE 的普通方向弹道和方向穿透弹道。

技能可选 `charge` 对象。三个必填整数字段为 `min_ms`、`max_ms`、`min_damage_bps`。最低时间至少一固定步，最高时间至少比最低时间长一固定步且不超过 5000 ms。最低威力为 1～10000 基点。配置蓄力的技能要求 `windup_ms=0`，准备移动时长以蓄力上限校验。旧机制中的该字段、null、额外键、越界以及其它技能形态均拒绝加载。

`start_charge` 使用技能 ID 和方向，接受时冻结单位方向、技能定义和世界逻辑开始时间，并分配 World 内不复用的蓄力 ID。普通 `cast` 只能施放普通配置。蓄力占用原共享准备槽，接受时检查灵力、冷却和状态容量。成员移动沿准备策略执行。 `release_charge` 使用本人私有快照中的施法 ID。最低时间前释放取消准备，最低时间等号可释放。有效释放冻结当时的持有时间，在下一次固定步按原提交顺序执行。截止时自动提交，实际蓄力时间取配置上限。主动取消、保护、后台、失联、重连和退场可以在提交前清除准备。重复、过期、旧连接和串成员 ID 沿输入和准备身份门禁拒绝或幂等处理。

提交时重验施法者实际位置并从该处创建弹道。倍率为 `min_damage_bps + floor((10000-min_damage_bps) * (held_ms-min_ms) / (max_ms-min_ms))`。原技能原始伤害先按原公式计算，再乘倍率向下取整。灵力、生命成本、冷却、后摇、状态和弹道容量共用原提交事务。提交失败没有费用或弹道。成功后，同一弹道的接触预算和结束方式按原定义执行。

本人准备视图可包含 `charge`，提供施法 ID、开始、最早释放和自动提交时间。有效释放将准备的 `commits_at_ms` 改为冻结时间。本人提交事件可包含实际持有时间和倍率。H5 发送类型明确的开始和释放意图并展示权威时间和事实。编辑瞄准、引导、再施放与其它威力曲线分批验收。

| ID | 验收 |
|---|---|
| CH01 | 主槽和末槽的严格配置门禁、旧机制兼容及公开 Action 门禁。 |
| CH02 | 提前释放、最小值等号、中间倍率、最大时间自动提交、冻结方向、实际起点和阶段移动。 |
| CH03 | 两种弹道复用原子事务。资源或容量失败、重复及取消只有一次或零次费用与效果。 |
| CH04 | 两成员同时蓄力互相隔离。准备私有投影、跨成员 ID 拒绝、重连取消未提交动作、迟到释放拒绝。 |
| CH05 | 包外四人手动释放、八人自动提交、H5 真实 4/8 页操作、费用事实及独立结算。 |
| CH06 | 同候选原有 Rust/Node 回归、Clippy、格式、离线源码和机制 46 包外消费。 |
