日期：2026-11-02。状态：冻结范围的 B1-K/B1-H 受控验收通过。来源：PRD-367 v1.3；资料包 sourceCommit `356ce494f5e40ea1a3859a4991dc10acf3e131aa`。结果见 [收尾记录](../evidence/B1-completion-2026-11-02.md)。

## 目标与证据边界

先交付一个能从创建运行到资产提交和关闭的独立 Rust 验证实例。B1-K 验收独立内核，B1-H 验收薄 Node 验证宿主。两者使用受控存储，不能签收真实数据库、现有客户端、生产地图或完整标准局。

验证场景不是新增生产模式。正式标准局的 NPC 补位、地图 PVE、复杂怪物、所有其它技能、武器和特殊模式继续属于后续批次。对应输入未支持时明确拒绝。原资料包保持只读，项目文档和代码记录当前批次的采用口径。

## 外部业务与终态

所有玩法与金额在 Rust 中计算。宿主只执行以下有限请求：LoadParticipant、CommitAdmission、CommitSettlement、QueryOperation、CompensateAdmission、ReconcileOperation。读取事实与可变世界分离，等待回执期间线程继续调度。

入场和结算各自是一个原子业务操作。B1 的结算将修为和保留库存一起提交，避免先发成长、后丢背包。生产多表映射和区域迁移接口在 G-03/G-04 的后续接入规格中补齐。

operationId 包含 matchId/incarnation 和有限业务类型；同一操作重试只改变 attemptId，冻结载荷不变。committed 包含 commitId 和递增 revision；not_committed 必须是权威且已隔离迟到写入的未提交证明，查不到记录不能充当证明；写入 unknown 先 QueryOperation。合法迟到 committed 可核对同一操作，不因当前 attempt 更大丢弃。已知成功后，迟到负面查询不能触发再次写入。

拒绝结算/补偿、查询未知或三次自动尝试耗尽时，进入明确的待核对状态，发出 OperationNeedsReconciliation 与 ReconcileOperation。只有对账请求匹配的 Reconciled 提交证明才能恢复；普通 committed 不得反转此前拒绝。核对仅履行原冻结责任，不能修改奖励或重建世界。不可核对时保留有限未决责任，不伪装完成；主动关闭仍能释放 World，后续在冻结账本处理事实。详见 [接口契约](../interfaces/independent-match-kernel.INTERFACE.md)。

关闭立即撤销 World；已有责任保留在无 World 权限的账本。未激活入场已扣费时发关联补偿；活跃实例关闭时冻结死亡结算。重复 close 不重复计算/请求。本地运行时退出后的持久责任恢复由 [B2-3](B2-3-durable-responsibilities.md) 补齐；B1 内存脚本宿主自身不承诺进程崩溃耐久性。

确定金额：成功击杀并拾取后撤离，仓库 `100−5+7=102`，修为 `floor((10+30)×0.75)=30`。同样持有 7 个时死亡，掉落 `floor(7×0.5)=3`，保留 4，仓库 `100−5+4=99`，修为 `floor(10×0.75×0.5)=3`。入场寿元只扣一次，失败且未激活时原数补偿；itemsGained 不参与任何金额。
