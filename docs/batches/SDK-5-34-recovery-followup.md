# SDK-5-34 后摇跟进施法

对应 R3.1/M02 及原需求的手动动作跟进窗口。目标 SDK 0.36.0，协议 6，schema 7，机制 51。本批覆盖同 World 1～8 成员 PVE 的普通方向弹道技能，从一次成功施法的固定后摇跟进另一技能。

对局配置可选 `skill_followup: {"window_ms":150}`。窗口是与 `step_ms` 对齐的正整数，至少一个固定步，至多 1000 ms。仅机制 51 允许显式声明。未配置时沿用原即时输入门禁。普通方向弹道作为前后两段，蓄力、引导、再施放和穿透组合另行验收。准备期跟进、同技能连发、普攻缓存、后摇取消与道具队列各自分批。

在前一技能后摇尚未结束、下一可执行固定步距离当前逻辑时间小于或等于窗口时，接受另一普通方向技能的原 `cast`。以该步为新准备的开始，实际发射仍由所选技能的准备时间控制。接受时验证方向、起点、灵力、自身状态容量，并确认该技能冷却在释放步已结束。每名成员保留最新一条通过检查的跟进，旧输入重传或拒绝不覆盖已有意图。技能定义来自对局冻结配置，队列保存请求 ID 和单位方向。排队不扣费，不提前写冷却或创建效果。

释放步先重验后摇、冷却、起点和资源等准入门禁，通过后进入原准备事务。到提交步按当前起点和资源重验，原子扣费、写冷却并生成真实弹道。释放步等于排队截止时仍有效，超期或重验失败直接丢弃并发布本人 `action_rejected`，不延后执行。期间移动与停止沿用原策略；取消、后台、失联、重连或终局清除待执行意图。已有后摇和在途弹道沿原生命周期处理。等待跟进时拒绝开始撤离读条，取消后可按原撤离条件尝试。

本人协议 6 快照可选 `followup`，包含前一技能、最早释放步和可空的排队意图。公共成员状态、其他成员的私有视图均不包含本人的队列。Node 继续提交原 `cast`，H5 用权威状态展示可跟进窗口和当前排队技能。

| ID | 验收 |
|---|---|
| FU01 | 配置版本、窗口形态、固定步与边界严格校验，未开启与机制 50 保留原门禁。 |
| FU02 | 窗口内与等号接受，过早、同技能和冷却超限拒绝；最新有效输入替换，方向冻结。 |
| FU03 | 释放与真实提交分别重验，准备和移动按原语义，费用、冷却、弹道各提交一次。 |
| FU04 | 取消、停止、重连、过期及终局，成员隔离与私有 full/delta 原子解码。 |
| FU05 | 普通 Node 与真实 H5 四人验证最新跟进生效，八人验证取消后仅首发；两组均有独立结算。 |
| FU06 | 同候选 Rust/Node 回归、Clippy/格式、离线交付和机制 50 包外回归。 |
