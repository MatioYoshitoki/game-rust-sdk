# SDK-5-61 多人指定友方即时治疗

对应 R3.1、R3.3/M02/M04，以及原行为规格 §4.3、§5.1 的严格单位锚点。目标 SDK 0.63.0、机制 78、schema 7、协议 6。多人 PvE 增加 `ally_heal` 技能机制。接入方沿用 `cast_unit` 并传入同一 World 内另一名成员的 `id` 和 `generation`。配置 `range` 和 `heal`，治疗量支持固定 `amount`（1～1000000）或目标最大气血万分比 `max_hp_bps`（1～10000），二者必选其一。

接受和提交都重验原目标身份、存活、就绪、保护、距离和视线。目标失效时拒绝本次动作，保持资源及冷却，原目标身份始终锁定。正常提交仅扣施法者费用并登记施法者冷却。读取目标最大气血和提交时有效的目标受治疗倍率，向下取整后按目标气血缺口裁剪。满血时实回为 0，溢出舍弃。本批的友方即时治疗为单次效果。

施法者先收到 `action_committed`，随后施法者和目标分别收到同一个 `heal_resolved` 结果，`heal_kind` 为 `ally_skill`，保留来源和目标身份。施法者的前摇快照使用 `pending_action.ally_target`。其他成员照常通过共享快照看到气血变化。

| ID | 验收 |
|---|---|
| AH01 | 机制 78 校验配置、金额和射程。拒绝旧机制、非法金额、附加状态或溢出转盾字段。机制 77 的自身即时治疗保持。 |
| AH02 | 只能显式选同局另一名就绪存活且未受保护的成员。接受及提交验证身份代次、射程和视线。失效后不改选、不收费、不开始冷却。 |
| AH03 | 只恢复目标，按目标上限和有效倍率取整、截断；满血实回 0。施法者独立付费，治疗事件只到施法者和目标，结果中的来源和目标准确。 |
| AH04 | 普通时钟下，Node 和 H5 分别跑通四人固定量和八人比例量样例，验证目标先扣气血后被治疗、事件隔离和退出结算。四人目标缺 160，实回 120。八人目标缺 360，实回 300。 |
| AH05 | 同一交付包通过仓库外空缓存离线接入、机制 77 自身即时治疗兼容复验、Rust 和 Node 回归。 |
