# SDK-5-87 自身技能威力加成

对应 R3.3/M04 和原行为规格 §4.1、§4.2。目标 SDK 0.89.0、机制 104、schema 7、协议 6。自身技能可在 `on_commit_self_statuses` 绑定 `timed_attribute_modifier / skill_power_bonus`，正向 `modifier_bps` 为 1～100000，按来源分组并采用 `refresh`。持续时间与强度由配置初始化，有效实例的加成相加。

成员伤害技能物化攻击预算时，Rust 先计算 `floor(当前有效 ATK × (10000 + 加成合计) / 10000)`，再按技能 `damage_bps` 计算原始伤害。两次整数阶段按顺序执行，中间量以 u64 计算并饱和到 u32。普通、单位、穿透弹道及三种区域计划共用这条预算路径。引导技能在提交时冻结攻击预算，后续子弹道使用该预算。普攻使用其自身 ATK 预算。

攻击预算在提交时读取当前有效状态，状态的刷新、精确到期和来源退出沿用状态生命周期。客户端观察施法成员的私有威力状态和既有伤害事实。Node 和 H5 通过基础普攻、有效期间的技能、有效期间的普攻及到期后的技能四次攻击验证闭环。

| ID | 验收 |
|---|---|
| SP01 | 合法自身技能威力状态通过机制 104 校验；拒绝旧机制、非法强度、重复策略、道具及其他投放位置。 |
| SP02 | 验证威力加成先于技能倍率的取整顺序、加成叠加、饱和与精确到期，普攻和其他来源按各自预算处理。 |
| SP03 | 六种伤害技能及引导预算在提交时冻结，覆盖刷新、成员隔离、私有归属和来源退出清理。 |
| SP04 | Node 和 H5 四人伤害为 66 → 100 → 66 → 66，八人为 66 → 133 → 66 → 66，每位成员各准入并结算一次，技能费用与普攻回灵按配置核验。 |
| SP05 | 同一交付包通过仓库外空缓存离线接入、机制 103 忽略护甲复验及 Rust 和 Node 回归；历史数值边界逐项保持。 |
