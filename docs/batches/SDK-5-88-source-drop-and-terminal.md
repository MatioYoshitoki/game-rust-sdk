# 原场景 S20 和 S28 补验

本次继续 DELIVERY-01 的原场景验收，覆盖丢弃失败的库存原子性，以及绝对期限触发的多人结算。

- **S20** 使用原场景的初始格、修订号、数量和请求时刻。原场景未声明物品来源，验收夹具把该格映射为已在局内且具备丢弃资格的堆叠，由现有 `drop_item` 入口执行。原 `no_legal_point` 覆盖映射为不可走的测试网格，走实际落点检查。失败时物品、净拾取账、修订号、地面资源和资源编号保持。相同库存和指令在原合法网格上成功生成一次地面资源，扣减对应库存。生产背包槽位协议、战备物品归属与 75px 落点纠偏继续归 R4.4 与 R4.1。
- **S28** 通过现有双成员准入、协议 6 发布和内存宿主账本执行。用普通自身技能获得伤害免疫，再用前后台输入进入保护。在原 915000 ms 期限前一逻辑步，两名成员存活。期限当刻，两名成员分别收到终局快照并进入死亡结算。World 关闭后，待确认结算仍由各自的账本跟踪。分开交付两笔回执，要求每人只入账一次、对局只关闭一次。真实客户端、数据库与传输环境继续按 R6 验收。

两项补验使用 SDK 0.102.0 的运行时代码，验收夹具和结果保存在工作区。已交付的 core-39 包保留自己的验收记录。[本次验收证据](../evidence/SDK-5-88-source-drop-terminal-2026-11-09.json)
