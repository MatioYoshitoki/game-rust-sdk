# SDK-5-15 移动弹道重复命中最小闭环

2026-11-05；先冻结需求与验收，再实现。目标crate0.18.0 / 机制33 / schema4 / 协议3 / 单人PVE；沿原两技能槽、最多两发玩家穿透弹道。扩展已注册piercing_projectile，复用通用ContactBudget身份/时间/总预算，不新增地图或武器专属逻辑。

## 配置与时间规则

piercing_projectile增加可省略repeat_interval_ms。显式提供时仅≥33/schema4/PVE、主副槽均可，为0～60000整数；不能null、负数、小数、额外字段或其它技能携带该字段。原ttl_ms/max_hits及所有数值/绑定仍必经原严格校验。省略时保持原每身份每发一次及旧规范化/输出形状；显式0也每身份一次，正数为该发弹、该World的{id,generation}上次成功直接接触时刻到本次接触的最小逻辑毫秒间隔。参数在接受时随技能冻结。

本次固定步now≥last_hit_at_ms+repeat_interval_ms时可再次接触，等值合法。使用Rust实际固定步逻辑时刻；与移动step_ms、区域tick_interval_ms和DOT/HOT周期独立。正间隔可小于step_ms，但同一步每身份最多尝试一次；非整步间隔在下一可接触固定步生效。它只给接触资格，不创建周期伤害：当前移动段仍须真实扫掠到目标；走出再入不清历史，错过的间隔不补跳、不按壁钟/前端帧计算、不因重连重置。新代为独立身份。

## 接触、预算与提交

继续沿整段扫掠、路径t/ID/代次排序、墙同距优先截断、每接触前资格/轮次重验。只有原直接命中链真实成功才刷新该身份时间并消耗一次全弹max_hits；全盾吸收/0HP损失计一次，闪避/失效/阻挡/未到间隔均不消耗、不刷新时钟或施加hit效果。其它候选继续扫描。重复命中仍读取当前DEF/盾/闪避，冻结提交后的直接攻击量；合法附带状态按既有refresh/ignore/容量策略处理，附带DOT/反击等不再扣接触预算。击杀/掉落只发生一次，不向死亡/新轮目标补收益。

预算仍1～128次总成功接触，含首次和重复；历史按身份保存最新成功时刻，独立身份≤used_hits≤128，同身份重复不增加历史槽，多弹独立。预算0立即结束，不再尝试后续目标/状态；射程端点、墙、TTL截止排除、创建步不移动沿SDK-5-14。SP/self容量/两发在途容量原子提交，成本/CD/共享后摇只处理一次，重复命中不再次扣费/开CD。失败免扣且不部分施加状态。

移动/取消输入/后台保留已提交弹道及计时，准备阶段原取消规则保持。同World重连保留方向/位置/射程/TTL/已用预算/最新身份时间/资格，不重复创建/扣费/重放已接受动作。死亡/终局/关闭/实际任一遭遇换轮结束全部在途新弹，不退款/跨轮伤害；100次关闭和峰值责任回收继续验证。重启仅恢复原Create/hash/金额/operation ID责任，不恢复临时弹道、重复时钟或战斗。

## 输出与接入

仅显式配置该字段的弹道：PiercingProjectileView输出repeat_interval_ms，contacts[].hit_at_ms表示最新成功时刻，正间隔附加next_eligible_at_ms=hit_at_ms+interval（资格门槛，不承诺未来命中）；0不输出下一资格时刻。PiercingHit增加可省略hit_at_ms，记录本次Rust接触时刻。已有used_hits/remaining_hits和Started/Ended继续发布权威事实。旧1～32及机制33省略字段的配置、视图/事件不新增这些字段，保持每身份一次；公开DTO/事件源码消费需适配，Client六类/协议1～3/恢复schema保持。

Node只发方向意图，H5点选/触摸方向并显示Rust的重复间隔、最新身份时刻/下一资格和总预算，不计算伤害/碰撞/计时。两套包外配置主副互换：A显式0逐目标一次，B正间隔同一身份多次并耗尽预算，观察真实伤害/状态/击杀/拾取及撤离/死亡结算；提供纯触屏双终局、灵力/容量/非法意图拒绝、带重复历史重连与三处强杀各两次恢复。接触效果可接回原普攻完成后续清怪，必须实际证明重复弹造成伤害/击杀及一次掉落。

精确重复已接受输入仅原请求去重；若旧连接隔离该重复，则验证新代并禁止换序号重发已接受操作。只有明确尚未接受的拒绝可按新连接重试。普通Node等待submit_input.ok.status.logical_ms之后的新快照再按权威准备/CD继续。所有验收绑定同源候选，不重写历史证据。
