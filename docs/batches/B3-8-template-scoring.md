# B3-8 配置化模板击杀计分

日期：2026-11-03。状态：S01～S08受控验收通过。基线B3-7为317项唯一Rust；新增36项Rust与21项浏览器/进程场景，最终353项唯一Rust及16组完整回归通过。

## 最小闭环与范围

独立b3-8场景：普通狼+精英验证狼→阶段守将→真实击杀累计模板积分→解锁容器→显式破解/开箱/拾取→撤离或死亡→冻结修为与逐物品责任→重启/核对原责任。沿用现有战斗、波次、Boss阶段、掉落和资产机制，不增加精英/Boss战斗被动或特殊技能。

机制是“实际死亡一次记账，按模板累计积分，再按配置转换修为”；普通/精英/Boss身份不在Rust内决定倍率。新验证配置分别设置10/30/100积分；这是显式验证数值，不宣称完整来源Boss分类/倍率已实现。三杀积分140，撤离floor((140+30)×0.75)=127修为，死亡floor(140×0.75×0.5)=52修为。所有分值、转换系数、撤离加分及死亡倍率均配置初始化。

## 配置与兼容

schema仍2，mechanism_version=7增加可选 `pve.kill_score` 和 `pve.additional_templates[id].kill_score`。各字段为0～1000000整数，缺省继承root kill_score；显式0不回退默认。字段出现要求机制版本≥7，旧八raw/hash不改。新能力仅PVE启用；B1原单目标/旧PVE继续原计分和责任正文，不附加新视图/结算字段。

kill_credit保持原语义：true计一次旧计分击杀且累计有效积分；false不计旧计分击杀、有效积分0（显式非零override拒绝），仍计实际死亡并可按配置掉落/完成目标。kill_credit=true且积分0合法，实际/计分击杀计数照常。无积分不代表无击杀/无物品，不从积分或修为推断这些状态。

新版本校验所有模板有效分值和整个有限生命周期的总积分≤u32上限，包含全部未来波次、静态及可重生守护代，不只看首波或同屏峰值；修为使用此加权积分上界校验，包含系数0与死亡倍率可能>1的情况。继承值、非整数/负数/超界/能力门禁均拒绝非法数据。

## 权威状态、视图与时序

1. 旧World.kills/PveView.kills仍表示kill_credit=true的计分击杀，避免旧配置/输入/恢复口径变化。新PveView可选scoring区分实际死亡kills、credited_kills、累计kill_score、当前战果若撤离/死亡的修为预览；预览由Rust计算，不提前发奖。MonsterView新版本可选kill_score显示当前实例有效分值。
2. 每模板记录实际死亡次数（base+additional共≤17种）。只在活怪HP首次归零时记账；miss/0伤害、非致死伤害、阶段变化、回血、开始/完成归位、遭遇/波完成、开箱和拾取不加分。新守护代独立死亡可再次计分，旧代/尸体/重复输入不能重记。
3. 新版本事件KillScored包含怪物/模板身份、本次分值、累计积分和实际死亡计数；每次实际死亡一次，即使0分也可核对。阶段不参与计分；不同World独立，模板只读共享，刷新/连接换代保留当前记录，旧连接隔离，关闭/死亡后停止新战斗记分。
4. 新结算可选scoring冻结 {kills,credited_kills,kill_score,templates:[{template_id,kills}]}，仅新能力必填；模板列表按ID排序、去重、正次数且受当前逻辑时间的最大生成次数约束。重复记账不依赖RNG、不改变原掉落随机序列。结算事件携带同一scoring，H5可在恢复后显示冻结战果。

## 结算与恢复

修为在累计全部积分后按原公式一次floor，不逐只取整；撤离加分只在撤离结果中加入一次，死亡仍按原倍率。外部库存只执行冻结正文，六类Client能力不扩展，不提供积分/击杀写入口。

新责任恢复严格要求scoring：实际数/计分数/积分须与各模板次数及原配置一致，修为须精确等于原积分转换结果；掉落上界按实际模板死亡次数和原容器周期校验，不再从修为反推击杀。零积分/零系数/不计分模板的真实掉落也能合法恢复。未知模板、重复/乱序/零次数、超代数、矛盾计数/积分/修为与非法掉落均拒绝。该摘要是原有受保护账本/冻结请求的一部分，不构成外部任意改写世界或伪造战果的授权。

旧机制责任省略scoring并沿原校验；新旧字段不可跨机制混用。配置换版后旧局仍绑定原raw/hash，提交前后强杀、丢回执、拒绝/人工核对及重复重启保持原operationId和完整正文，不按新积分重算。无持久终局的中断只退入场，不保存/恢复积分或World来发奖。
