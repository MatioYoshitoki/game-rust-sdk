# 原始施法场景的领域绑定

延续 SDK-5-88 / DELIVERY-01 的原需求验收。S10、S11、S12 共享同一份原始场景基线。测试从资料包读取原 A/B 身份、原技能和生命周期、输入与给定时间。场景适配只用于测试；目标死亡和宿主眩晕是原定义允许注入的已解析领域事实，客户端无法注入。世界坐标等距平移到非负网格，不改变距离和方向。

- S10：0 ms 使用方向技能，120 ms 宿主眩晕，推进到 180 ms。要求灵力 100、该次技能创建运行时对象 0、已接收技能中断 1 次。
- S12：0 ms 选择 B 作为友方目标，60 ms B 死亡，推进到 150 ms。要求不换目标、不治疗、不扣灵力，且只结束这一次准备。Rust 对已接收准备在最后一次目标复核失败时用动作 ID 关联 `action_rejected/invalid_target`；领域断言可通过这个明确归属观察原语义，不能把未接收的客户端错误算作中断。
- S11：原资料要求同一时刻真实输入与重试就产生一次提交和一次费用。先在实际协议入口测量 0 ms 的现有行为。固定步在下一步才发生的提交不充当原断言；若即时语义确实缺失，再通过明确的可信配置补能力，并保留旧配置的固定步行为。

S20 和 S28 分别依赖丢弃放置、绝对终局，沿原工作包执行。原域场景验收与配置全量投放、生产系统验收分别记录。

SDK 0.102.0 已补 `self_status.commit_on_accept`，仅接受无前摇、无引导的自身技能，缺省仍由固定步提交。开启后普通输入完成既有校验，立即执行同一原生提交路径；费用、冷却、拦截、私有事件和发布均沿现有逻辑。验收时使用原技能的 30 灵力、原 `r1` 和序列 1，在同一逻辑时刻重送，要求实际灵力由 100 变 70，提交和费用各一次，普通旧配置同刻仍处于准备。非法组合、未知或空值冷装载拒绝。

S10、S11、S12 已通过 [0.102.0 同源验收](../evidence/SDK-5-88-core-39-2026-11-09.json)。S28 的 [补充领域验证](../evidence/SDK-5-88-S28-native-probe-2026-11-09.json) 使用同一运行时代码和单独测试扩展。
