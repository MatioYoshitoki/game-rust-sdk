# SDK-5-46 按最大属性比例恢复

对应 R3.1/M02。目标 SDK 0.48.0、机制 63、schema 7、协议 6。新增通用的自身气血和灵力比例恢复。原始玉泉散的两个基础比例均为 2000 万分比，样例用这个比例验证闭环。品质倍率和附带状态由后续工作单独处理。

机制 63 的 `member_item_use` 可配置 `heal_max_hp_bps` 和 `restore_max_spirit_bps`，各接受 1～10000 的整数。每项属性可选固定量或比例量，两者互斥。不同属性可使用不同方式，条目至少配置一项恢复。旧机制继续按各自版本接受固定量，拒绝比例字段。

每项实际恢复量为 `min(当前缺口, floor(最大属性 × 比例万分值 / 10000))`。最大值以用药时本人权威快照对应的上限为准，乘法使用宽整数。先分别取整和截断，再沿用已有的一次消耗、一次库存修订和冷却提交。两项实际值均为 0 时返回 `INVALID_STATE`，背包、属性和冷却保持原值。本人用药事件继续发布实际值，双恢复某项为零时照常发布。

| ID | 验收 |
|---|---|
| RR01 | 验证版本门禁、1～10000 的整数边界、单项和双项比例、跨属性混用固定量、同属性冲突及空效果拒绝。 |
| RR02 | 按最大属性取整，覆盖比例上限、宽整数、缺口截断、只一项生效及取整为零。 |
| RR03 | 校验失败和两项为零时不消耗。成功只扣一份、改一次修订并启动一次冷却，重试不重复提交。 |
| RR04 | 实际恢复量和背包修订仅按现有权限发布，重连保留冷却，退出结算剩余净拾取量。 |
| RR05 | 普通时钟 Node 和 H5 分别跑通四人双比例与八人仅灵力有缺口，核对实际数值、页面和结算。 |
| RR06 | Rust 和 Node 回归通过。同一交付包可在空 Cargo 缓存离线构建，机制 62 的固定量双恢复样例可在新宿主运行。 |
