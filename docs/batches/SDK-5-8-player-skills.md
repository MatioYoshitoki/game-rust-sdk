# SDK-5-8 配置化双技能最小闭环

2026-11-04；**先冻结规格，现已实现并通过受控验收**。目标crate **0.11.0**、机制 **26**，schema4/协议3、单人PVE。补齐M02的有限多技能调度，复用已注册弹道和状态效果。

## 配置、输入与兼容

1. 保留必填skill主技能，新增可省略additional_skills数组。本批最多一个附加项，即总计1～2技能；字段若显式存在须恰有一个对象，null/空数组/非数组/多项拒绝。仅机制26/schema4/PVE允许该字段，旧版本携带即拒绝。旧原文和规范化输出不新增空字段。
2. 每项复用原SkillConfig：id、projectile机制、前摇/后摇/CD、灵力成本、倍率、距离/速度/半径和self/hit状态绑定。ID在玩家技能中唯一且满足原约束，每项数值/未知字段/机制、状态引用/绑定规则都严格校验。所有参数来自配置；不新增即时自身技能、单位/地面目标或任意脚本。
3. 沿用Cast {skill_id,direction}，Rust按ID分发；在可接纳动作的状态下未知ID为Unsupported，非法方向/载荷沿原严格校验。不新增槽位切换状态或客户端HP/CD设置入口。
4. 机制1～25的动作、冷却、事件和JSON形状不变，包括原允许用新动作取消后摇的策略；机制26显式启用下述共享约束。普通攻击仍是独立动作，旧skill_ready_at_ms继续表示主技能CD。

## 动作与冷却

- 一名角色只有一个准备中的动作。接受时冻结选中的技能定义/ID、瞄准与原遭遇轮次；提交时沿原边界读取有效ATK并冻结弹道，状态绑定只来自该技能。后续施放另一个技能不改变在途弹道的攻击量、范围、速度或绑定。
- 每技能独立ready_at，提交成功才扣该技能成本并设置其CD、角色共享后摇。灵力池共用；旧主技能别名与主技能实际CD一致，副技能不覆盖主技能CD。未提交取消/后台/死亡/满槽拒绝不扣成本或启动CD。
- 机制26在pending存在或now<recovery_until时拒绝新的普攻/任意技能；now等于期限可接纳。移动/导航可沿原移动规则进行，但不得清掉后摇或绕过准备；CancelAction、前后台和重连也不缩短已提交后的后摇/CD。取消准备只清当前准备，不回滚已提交弹道、效果、成本或CD。
- CD=0/后摇=0按合法配置执行，仍受单pending和固定步/原队列预算约束。多技能共享状态槽和全局发布预算，不因技能数增加容量。重复输入/回执不重复扣费、提交或施加状态。
- 遭遇实际复位换轮时取消尚未提交动作（不扣费/开CD），只启动后又取消的复位倒计时保留同轮准备；在途弹道仍按原轮次限定命中。终局/关闭中止未提交动作并释放World；同World重连保留已提交技能CD/后摇，旧连接拒绝。重启只履行冻结资产责任，不恢复战斗、准备动作、CD表或按新参数重算旧金额。

## 输出与前端

机制26 Snapshot新增可省略player_skills，有序提供 {skill_id,ready_at_ms}（主技能在前）；pending_action仅在准备中出现，提供skill_id（普攻为null）和commits_at_ms。ActionCommitted新增可省略skill_id，仅机制26的技能提交时输出。旧事件的skill布尔和成本保持，旧1～25不输出新字段。公开DTO/枚举为0.11.0源码变更，六类Client、协议1～3及资产/恢复schema保持。

Node/H5从配置获取两项技能参数，只转交意图/展示权威CD、准备/恢复和资源状态。H5提供两个按钮及第二技能快捷键，旧页面仍用原单按钮。重启Closed展示清除player_skills/pending_action等临时字段，不伪装成可继续战斗。

本批只支持已有方向弹道及既有状态绑定，不签收更多技能数量、严格单位/地面/自身目标、多技能AI槽、引导/蓄力/再施放、武器家族、多人或完整技能目录。D-03/D-05及生产门禁不变，不扩新地图或第二款游戏。
