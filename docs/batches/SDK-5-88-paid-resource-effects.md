# 同模块：实际已付成本返还与耗尽载体

2026-11-09，PA01～PA20，继续归 SDK-5-88 / DELIVERY-01 / R3.1～R3.3。先冻结规格，再在隔离候选实现；不改变正在交付复验的 0.99.0。

来源为 realm-technique-loadout 的丹转：8秒内前三次普通功法先付清消耗，再返还30%实际灵力消耗；用尽后3秒无法恢复灵力。factor_realm_core_turn 的3000bps/3000ms与定义最大3份分别绑定源行。原普通功法清单、永久成长及完整境界技能的投放另按原归属签收，不按该原ID选择Rust算法。

通用范围：

- 增加成员技能初次提交后的原生已付灵力事实，amount为这次原子提交实际扣除的灵力。旧SkillCommitted保持零量及自身上下文；拒绝、准备取消/被截断、普攻、引导后续跳和再施放不伪造初次提交事实。它继承本次真实动作和规范技能来源，装备资格/动作筛选沿既有规则。
- 增加有界按该事实金额比例恢复灵力的效果。先通过原技能费用/最低生命/CD/目标/容量检查并扣费，后处理恢复，不以未来返还抵扣准入；bps为1～10000。宽整数只取整一次，当前缺口/有效上限/恢复封锁实时生效，记录实际返还与未用余量。限定已付成本事实，不能把伤害量冒充消耗；配置不能请求Node报价。
- 显式计数载体增加可选零层策略keep/remove，缺省keep保持0.98行为。remove必须从正层初始化，最后一份消费时正常移除并产生Consumed结束，允许复用既有有限status_ends在耗尽后投放恢复封锁。私有零层策略随真实实例保存，克隆预检、转移、刷新、清理一致，不新增客户端可写字段。
- 一次已付事实至多执行各匹配触发器一次，条件消费、概率/ICD/动作/步预算复用。完整付费后，按消费前金额返还；最后一份耗尽的结束叶子在原结束调度边界执行，不能先封锁本次应得返还。自然到期、驱散、死亡/退出不冒充耗尽。
