# 穿透普攻与终态结算

本组属于 DELIVERY-01 与 R3.4 的交叉验收。`basic.piercing` 可为已有普攻入口配置一条有限穿透弹道，声明 `plan_id` 和 `max_hits`。距离、速度、半径和寿命复用已有普攻配置。沿线扫掠和每目标代次限命中一次使用现有穿透预算与发布格式。

`basic.settle_on_end` 显式启用原生普攻结束结算。普攻完成前摇并成功释放后，投送未结束期间同一成员可以移动、施法，下一次普攻仍受门禁。已有下一击缓存可以等待。最后一个计划结束时，启动一次完整普攻冷却，按 `params.basic_spirit_on_hit` 最多回灵一次。冷却沿用已有攻速与行动延迟时钟。配置缺省沿用释放时启动冷却和逐次接触回灵。

原表的回灵量为 2，按一次有效直接接触取得资格。有效接触完全被护盾吸收时沿用 SDK 原有命中口径。落空、闪避、无效或免伤目标和周期效果不给资格。已成功释放的落空动作仍启动冷却，前摇取消和提交失败不启动。来源保护时撤销该动作的回灵资格，重连不能补发，已释放动作仍保留冷却责任。

| 验收项 | 预期 |
|---|---|
| 多目标 | 一次普通攻击的两次接触落在不同逻辑步。第一段后灵力保持，第二段结束时只回 2 点；终态吸血与普攻同用动作身份。 |
| 冷却与缓存 | 同一成员投送期间不能释放第二次普攻。终态写入一次冷却，已缓存下一击按真实冷却重新排程。队友独立。 |
| 失败与清理 | 覆盖落空、前摇取消、护盾、回灵封锁与上限、保护恢复和退场；状态清理不赠送灵力，不能借恢复连接规避已释放冷却。 |
| 兼容与容量 | 普通客户端使用已有攻击指令和弹道事件。错误计划 ID、越界命中数和历史容量在冷加载拒绝。旧配置保持原时序。 |

样例用原飞剑基础前摇、速度、距离、间隔及原回灵量，配两目标穿透验证通用机制。各器型的分段系数、留剑召回、扇形波面与专用效果按完整武器工作包验收。

样例在 120 ms 释放，150 ms 和 180 ms 各命中一个目标。第二次命中耗尽弹道预算，回灵 2 点并开始 700 ms 冷却。下一击缓存从投送期间的暂定时点更新为 900 ms，这是 880 ms 冷却就绪后的第一个固定步。用 `cargo test --offline --locked --lib basic_delivery` 复验。[SDK 0.105.0 验收记录](../evidence/SDK-5-88-basic-delivery-2026-11-09.json)
