# SDK-5-47 恢复道具品质倍率

对应 R3.1/M02，关联 R4.4/M10 的品质身份。目标 SDK 0.49.0、机制 64、schema 7、协议 6。本批沿用按物品 ID 堆叠的模型。同一配方的不同品质可注册为独立物品 ID，各自在 `member_item_use` 配置 `quality_multiplier_bps`。背包、掉落和结算以该 ID 区分品质。实例装备、动态品质和品质生成归后续资产机制。

倍率接受 1～40000 的整数，10000 表示 1 倍，省略时为 1 倍。机制 58～63 拒绝新字段并继续使用原算法。倍率由冻结的对局配置绑定，客户端沿用 `use_item` 提交物品 ID 和本人库存修订。

同一倍率作用于此道具已配置的气血和灵力效果。固定量用 `floor(固定量 × 倍率 / 10000)`，比例量用 `floor(最大属性 × 基础比例 × 倍率 / 100000000)`。乘完后只取整一次，再按各属性缺口截断。结果均为零时返回 `INVALID_STATE`。成功只消耗该 ID 的一份、改一次修订并按现有规则启动独立或共享冷却。事件发布本人实际恢复量，结算按物品 ID 记录剩余净拾取量。

玉泉散原配置的基础比例为 20%，说明区间为 14%～30%。样例用 0.7 倍和 1.5 倍覆盖这两个端点。倍率值和物品名来自样例配置。

| ID | 验收 |
|---|---|
| QR01 | 验证机制门禁、默认 1 倍、整数边界和错误值拒绝。 |
| QR02 | 验证固定量、比例量和混合配置，覆盖一次取整、宽整数、缺口截断及取整为零。 |
| QR03 | 只扣被使用的品质 ID 一份，库存修订和冷却仅提交一次，重复输入和冷却期内用药不重复消耗。 |
| QR04 | 两种品质可同局拾取并按独立 ID 结算。重连保留本人冷却，用药事件仅本人收到。 |
| QR05 | 普通 Node 与 H5 验证四人 1.5 倍和八人 0.7 倍。两房均拾取两种品质、消耗其中一份并按 ID 结算。 |
| QR06 | Rust 和 Node 回归通过。同一交付包通过空缓存离线构建，机制 63 比例恢复样例可在新宿主运行。 |
