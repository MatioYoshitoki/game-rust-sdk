# 原生动作终态的本人计数

继续 SDK-5-88 / DELIVERY-01。复核原 `combat-engine.DESIGN` 的动作级 `afterAttack`，以及原 `effect_yishen_seed` 中本人加道种、排除提供功法、每次动作最多一层的行。原万剑阶段的加剑意也指向本人；资料没有提供一个明确要求对代表目标执行终态效果的已绑定配置。当前保留代表目标作为事实，不把它当成可执行目标。

在已有 `action_total` 扩展唯一已核实的缺口：直接 `damage_dealt` 完整结算后给动作归属者的现有同源计数器加层。配置只允许本人效果和本人计数范围。原数值由内容表提供；不按游戏、技能或阶段 ID 判断。已有每步预算、动作收尾、错误代次、退场和状态政策复用。阈值叶子仍按原有非递归规则，沿本次原生动作及来源归类。

验收：

- 三次实际接触期间不提前加层；最后一个原生子计划结束后，本次只加一层，阈值叶子只执行一次。动作事件记录实际合计和接触数。
- 零伤害、周期/派生、来源退出或无当前本人计数器不得凭空生成层数。目标计数、目标修改和承伤模式禁止复用这条规则。
- 排除技能按可信技能筛选。目标身份仍可用于审计，同一动作的重复输入不会产生额外收益。
- 原道种/剑意完整技能成长与不同武器投放另逐项绑定；本组只验收已定义的通用机制和所用原始行。

另核对了 `factor_knockback`：原可执行引用是渡劫风刃的区域进入触发，要求沿源到目标方向位移 200 像素并校验落点；滑移速度倍率 3 属于客户端表现。这一项回链 R3.4 的世界位移计划，不能用减速、定身或瞬移替代。
