# SDK-5-58 恢复道具溢出治疗转护盾

对应 R3.3/M04 及原需求 §4.3。目标 SDK 0.60.0、机制 75、schema 7、协议 6。本批以多人 PvE 的即时气血恢复道具作为显式转换入口。在 `member_item_use` 可配置 `overheal_shield`，通过 `status_id` 引用一个 `refresh` 策略的吸收盾，并用 `conversion_bps` 配置 1～10000 万分比。此入口使用单一护盾转换配置，道具可同时恢复气血和灵力。

先按已有的道具品质和可选受治疗倍率计算整数气血回复量，再按气血缺口得到实际回复。只有超出缺口的部分参与转换，向下取整后补入该状态的护盾余额。状态的 `shield_bps` 决定该盾的上限，`shield_cap_bps` 决定目标的总上限。实际新增护盾大于零时创建或刷新实例，保留该实例已有余额，沿用普通护盾的吸收、到期和清理规则。

实际气血回复、灵力回复或护盾新增至少一项大于零才消费道具并启动冷却。护盾有新增量但无状态槽时，整次用药以容量不足拒绝。沿用本人 `item_used` 和 `shield_granted` 事件分别记录实回和实授。

| ID | 验收 |
|---|---|
| OH01 | 机制 75 接受气血或双恢复道具显式绑定。旧机制、非法比例、错误盾引用、叠加其他用药状态绑定均拒绝。 |
| OH02 | Rust 覆盖品质及受治疗倍率后的溢出、转换取整、单盾和总上限、旧盾余额保留及实际新增时刷新。 |
| OH03 | 覆盖满血仅授盾、容量不足和零收益时的原子拒绝，以及护盾吸收和成员隔离。 |
| OH04 | 四人及八人房在 Node 和 H5 中完成击杀、拾取、用药、护盾到期及退出结算。满血四人房实回 0、授盾 100，受伤八人房实回 360、授盾 100。 |
| OH05 | 同一发布包通过仓库外离线接入、机制 74 NPC 封锁兼容复验、Rust 和 Node 回归。 |
