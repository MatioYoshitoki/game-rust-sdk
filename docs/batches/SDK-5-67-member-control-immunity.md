# SDK-5-67 定时控制免疫

对应 R3.2/M03/M04 及原行为规格 §4.4。目标 SDK 0.69.0、机制 84、schema 7、协议 6。成员可用 `self_status` 技能在提交时施加 `timed_control` 的 `control_immunity` 状态，按配置时长、来源分组和 `refresh` 管理。沿用已有技能成本、冷却、目标容量和私有状态契约。

免疫生效期间，NPC 弹道新施加或刷新的沉默被拒绝，原伤害和同次命中的其他已注册状态照常结算。拒绝的沉默不占状态槽、不打断主动技能。已有沉默沿原期限结束。到达免疫截止时刻后，新沉默恢复按既有规则处理。

受影响成员收到私有 `status_rejected`，原因是 `IMMUNE`，保留来源、目标和被拒绝的状态定义。免疫状态沿用刷新、到期和退场清理。本批覆盖已注册的 NPC 弹道沉默。首控次数、控制缩时、驱散及其它控制按各自规格验收。

| ID | 验收 |
|---|---|
| CI01 | 机制 84 接受合法自身技能免疫，拒绝旧机制、错误状态策略、非自身技能、命中和道具绑定。 |
| CI02 | 生效时拒绝沉默施加与刷新，保留伤害和同次其他效果。拒绝不占槽、不打断或阻止原技能提交。 |
| CI03 | 验证刷新、截止时刻、已有沉默期限、退场清理，以及免疫与拒绝只进入本人视图。 |
| CI04 | Node 和 H5 在四人、八人房验证主动施加免疫、第一发 NPC 弹道造成伤害且沉默被拒、受保护的技能提交、免疫到期后的第二发弹道正常沉默及退出结算。 |
| CI05 | 同一交付包通过仓库外空缓存离线接入、机制 83 NPC 沉默兼容复验、Rust 和 Node 回归。 |
