# SDK-5-42 恢复道具冷却

对应 R3.1/M02。目标 SDK 0.44.0，协议 6，schema 7，机制 59。同一 PVE World 的 1～8 名成员可对已配置的恢复道具启用冷却。最小闭环是使用一份、冷却内再次请求被拒、到期后成功使用下一份、按剩余净量结算。

`member_item_use` 中每种道具可增加 `cooldown_ms`。该字段限机制 59，取值为 1～60000 毫秒且是对局固定步长的整数倍。省略时采用原即时使用规则。继续使用 `use_item` 和本人最新库存修订。

冷却属于同一 World 中的成员与道具 ID。Rust 仅在成功恢复并扣一份时，按本次提交的逻辑时间启动冷却。若当前逻辑时间小于截止时间，使用返回 `INVALID_STATE`，生命、库存修订和截止时间均保持。等于或晚于截止时间时可以再次校验和使用。满血、错修订、无净份额和重复请求继续遵守原使用规则。

本人 full/delta 可携带 `item_cooldowns`，每项包含 `item_id` 和 `ready_at_ms`，仅发布尚未结束的冷却。离开库存的道具仍保留该成员的冷却。转移后接收者按自己的冷却判断。同局重连沿用原逻辑时间和截止时间。成员离场时清除其冷却，金融重启继续恢复已冻结的结算责任。

| ID | 验收 |
|---|---|
| IC01 | 新字段机制门禁、形状、固定步长及上限边界，机制 58 兼容。 |
| IC02 | 成功才启动冷却，冷却内拒绝且无部分变更，等于截止时间时成功。 |
| IC03 | 不同道具和成员独立。转移、重新拾取和同局重连保持原成员冷却。 |
| IC04 | 请求幂等，私有 full/delta、错误载荷校验和提前离场清理，结算只入账剩余净量。 |
| IC05 | Node 和 H5 验证四人房到期后二次使用，八人房同伴独立使用及结算。 |
| IC06 | 同候选 Rust 和 Node 回归、格式与 Clippy、空缓存离线构建及机制 58 包外兼容。 |
