# SDK-5-39 自动选敌短追击

对应 R3.1/M02 及原需求的智能轻触与显式锁定双指令距离。目标 SDK 0.41.0，协议 6，schema 7，机制 56。同 World 1～8 成员 PVE 的现有 `attack` 输入可选自动选敌短追击。

在已有 `basic_pursuit` 内可配置 `auto_max_range`。该值须有限、大于普攻射程且不超过显式锁定追击的 `max_range`，允许两个上限相等。字段出现时必须为数值，仅机制 56 可声明。两种追击共用配置时限。机制 55 和未声明自动范围的对局沿用原规则，既有配置和客户端输入兼容。

`attack` 先沿用射程内选敌和冷却缓冲规则。没有射程内候选且配置自动范围时，选范围内最近的可见存活、未归位敌方 NPC。等距按实体 ID 排序。选定后复用 SDK-5-38 的资格校验和扫掠路径检查。目标或路径校验失败时拒绝该请求。没有候选返回 `INVALID_TARGET`；忙碌或冷却中拒绝射程外追击，保留原排队规则。

受理冻结目标代次、原请求 ID 和该请求的范围上限。每步重验同一目标、视线、范围、碰撞和截止时间。超距、目标失效、碰墙、超时、主动取消或连接切换结束原动作。推进中不会换目标。进射程后沿用原动作进入锁移动前摇并重验后提交；追击与失败阶段不结算费用、弹道或冷却。显式 `attack_unit` 继续使用配置的锁定范围。自动与锁定追击使用同一私有 `basic_pursuit` 投影及同一套取消和清理。

| ID | 验收 |
|---|---|
| AP01 | 自动范围、等号、字段形状和机制 55/56 门禁，未启用时保留既有行为。 |
| AP02 | 优先处理射程内普攻和排队；射程外选最近可见 NPC，等距稳定，固定目标和请求 ID 后命中一次。 |
| AP03 | 两种范围分别生效，覆盖目标换代、移出自动范围、阻挡、忙碌/冷却、超时和主动取消。失败无费用、弹道或冷却。 |
| AP04 | 重复请求、成员隔离、重连清理及现有私有 full/delta 投影。 |
| AP05 | 普通 Node 与真实 H5 验证四人自动追上发射、八人自动范围拒绝后用显式锁定追击并取消，分别结算。 |
| AP06 | 同候选 Rust/Node 回归、格式/Clippy、空缓存离线交付与机制 55 包外回归。 |
