# SDK-5-19 配置化1～8成员容量

2026-11-05；先冻结本规格与MC01～MC10，再实现；当前声明范围已签收，见[执行记录](../evidence/SDK-5-19-member-capacity-2026-11-05.md)及[机器证据](../../artifacts/sdk-5-19/acceptance.json)。起点0.20.0/协议4/schema5/机制35，目标0.21.0/协议5/schema6/机制36。主要工作包R2.2，沿用R2.1实体关系和R2.3私有全量切片；不增加地图专属机制。

原来源`resolved-matchmaking`标准maxPlayers=8、minPlayers=1；本批只验证提供固定完整名单后的1～8名真实成员，不接匹配队列、自动补NPC或模式规则。巡锋等匹配机器人是参战成员，不能把现有PVE怪物计作机器人占位。标准完整匹配/机器人、16/24模式容量和生产负载仍开放。

## 范围与公开契约

- 新schema6/机制36配置使用严格`members`块：`capacity`为1～8整数，`spawns`长度恰capacity，其余部署期限、每成员发布预算和共享弹道预算沿原字段。名单成员数必须恰capacity，全部为必需成员。容量在构建目录时初始化、创建后冻结；不接纳追加/替换/缺席自动缩容。
- 每个出生点合法可达，任意两点满足玩家足迹不重叠，拒绝NaN/越界/阻塞或重复点。输出容量至少`64×capacity`且不少于128；预算不足构建失败，不接受后再挤掉成员。
- CreateV5沿用已有成员字段/身份/每成员金融责任和全量DTO；新版本只扩展成员数量。公开Rust新增有类型CreateV5；协议5继续使用已有`*_v4`输出标签和金融检查点结构，标签复用必须明示，宿主不得据标签猜成员数。旧CreateV4仍严格两人，旧schema5仍只接受two_members；协议/配置/字段混用在I/O前拒绝。
- 能力沿SDK-5-18有限PVE白名单：一个World、普通NPC/方向弹道/自身ATK或DEF/整数资源及有限结算。所有游戏数值/ID/布局仍由配置初始化；只推广通用成员表和预算，不为1/4/8人数各写玩法实现。
- 事实、库存、成本、动作/CD、连接/序列、ready、发布、离线与终局均逐成员独立。公共成员表和NPC/资源共享。全部必需席位原子入场成功、实际sent且ready后只共同激活一次；一席失败/缺席关闭准备局并按原责任逐人核对/补偿。
- 任意一人终局/离线/未知金融I/O不暂停其它成员；最后一名退出可操作集合、绝对终局或可信close释放唯一World，金融账继续核对。全体及聚合来源上限、成员映射、原配置/hash/操作身份在恢复时校验，不恢复战斗现场。
- 协议5每份可信资产事实最多32行（旧协议4保持128行），资产ID沿原64 UTF-8字节限制；超限在应用事实前拒绝，恢复同样核对。此有界事实预算使最大八席责任可经256KiB JSONL创建/恢复，不静默丢弃未知资产。
- 私有发布按成员限流/coalescing；一个慢接收者不占尽其它人的预算。Node只认证/排队/传输/持久执行冻结事务，H5只发意图与显示Rust数据。
