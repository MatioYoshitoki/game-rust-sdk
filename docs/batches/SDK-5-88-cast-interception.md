# 同模块：最终提交拦截与已确认的来源规则

2026-11-09，CI01～CI20，继续 SDK-5-88 / DELIVERY-01 / R3.1～R3.3。按用户确认的[免控与封息裁定](../decisions/SDK-5-88-cast-interception-policy.md)和[吞元乘区裁定](../decisions/SDK-5-88-resource-steal-stack-mode.md)实施。保持正在包外复验的0.100.0不变，先在隔离候选实现。

通用 `combat_rules.cast_interceptions` 由状态定义ID索引，使用显式技能筛选和目标profile策略。标记为来源隔离、单份、非周期的纯载体；无属性收益、控制标志、窗口、盾、派生结束或递归。只在已有技能通过最终目标、资源、容量和源资格检查后、实际扣费/CD/效果前读取本次施法者的活跃标记。成员和已存在的NPC弹道施法共用入口；不新增NPC客户端动作，不按境界、地图或技能ID硬编码。

每次实际提交尝试选择一个合格标记，优先最早到期、施加时刻、稳定实例ID。源/目标用真实代次与敌对关系；普通普攻、后续跳、再施放、无效/取消准备和不匹配技能不消耗。定时免控消费标记后允许原技能正常支付和提交，不追加状态；一次性首控免疫沿已有一次性耗尽规则，持续免控保留。非免控 `interrupt` 原子消费标记并施加配置的有害后续状态，取消本次未提交事务，不扣HP/SP、不写技能冷却、不创建主效果。`allow_and_apply` 消费标记、施加不改变资源上限且不打断当前施法的数值后续状态，再正常提交。预检基于消费后的状态，失败保留标记与原技能事务。后续状态按既有政策、来源、容量和缩时处理，明细按来源/持有者接收。

原绑定：5秒标记；普通目标700ms沉默；首领profile允许提交并施加1200ms/25%移速降低；控制免疫消费锁并放行且无附加。普通功法范围由可信技能筛选给出。吞元基数10%与每层相对+10%使用明确 `multiply_base`，0～3层为10/11/12/13%，仍在消费前冻结；HP夺取管线单独未决。
