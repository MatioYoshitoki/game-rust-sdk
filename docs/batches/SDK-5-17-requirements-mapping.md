# SDK-5-17 原需求能力映射与工作包冻结

2026-11-05；运行时基线0.19.0/机制34。本批对应R1.1～R1.3，仅做逐项映射、能力归并、规格门槛和下一实现批冻结。原资料与历史验收保持；不改变crate/协议/机制版本，不把映射视作行为通过。

## 交付范围

- 对498个来源内容项，以kind/id及原始JSON Pointer唯一定位，登记完整字段与子行为、当前可复用能力、局限/数值界限、P/M/I分类、待裁定规则、对应工作包和有效证据。
- 对48场景的given/when/then及50算术向量的原input/expected逐项登记，明确现有相近证据、精确执行入口、缺口与前置；本批不新执行原场景或向量，不把相似测试标成原断言通过。
- 归并有限原生能力族；已有原生能力只做配置适配，缺触发/几何/目标/公式/生命周期才补机制。不能把一个map/skill/factor ID当成一个处理器。
- 提供待确认语义台账与受影响条目/工作包；D-03/D-05不代用户裁定。未知字段、special及描述/结构差异保持needs_spec，不编造实现规则。
- 根据实际映射与路线依赖，冻结SDK-5-18的有限实现范围、边界、明确验收ID及版本/接入约束；本批不开始运行时代码实现。

## 映射口径

分类记录在子行为上：P是可用机制的合法配置切片，M是缺SDK能力或规格，I是缺精确执行/实际接入证据。同一条内容可同时包含P/M/I，整项只有当所有子行为与前置通过才能签收。现有能力证据必须有代码/配置定位、真实已通过的测试或报告；只能支持其声明的受控子集。

每个来源对象的顶层字段均记录审查去向；嵌套的实际效果/状态/技能、运行计划、触发、公式/质量/派生、几何和生命周期另以精确路径登记。纯名称/图标/美术字段标为接入方展示数据，不当作SDK缺机制。参数目录虽有值但算法不明时保留规格缺口；数值超当前能力上限须单独记录，不直接放宽上限。
