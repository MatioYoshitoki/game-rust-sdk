# SDK-5-49 恢复道具状态品质配置

对应 R3.1/M02 和 R3.2/M03。目标 SDK 0.51.0、机制 66、schema 7、协议 6。不同品质沿用独立物品 ID。道具可通过 `on_use_self_status_overrides` 为 `on_use_self_statuses` 已绑定的状态配置该品质的 `modifier_bps` 和 `duration_ms`。每项覆盖必须同时提供两个值，省略整个覆盖字段时使用状态原定义。

本批支持重复策略为 `refresh` 的攻击或防御定时修正。强度沿用既有状态边界 `-10000..=100000`，时长沿用 `[step_ms, min(terminal_ms, 3600000)]`。覆盖映射为 1～2 项，键须属于本道具的状态绑定。机制 65 及以前拒绝覆盖字段。其他状态类型继续使用原定义。

同一成员依次使用不同品质时，共用同一个逻辑状态及实例 ID。最新一次成功用药同时替换强度与时限，截止为本次施加时刻加该品质配置的时长。低品质也可以刷新高品质并缩短截止。容量预检按原状态身份执行。恢复、消耗、修订、冷却、私有发布和重连规则沿用 SDK-5-48。

样例沿用赤髓丸同一状态的低品质 `+15%` 和高品质 `+39%`。原资料对应时长为 20 秒和 35 秒，验收样例配置为 4.5 秒和 7.5 秒以便观察到期。四人房先低后高，八人房先高后低。

| ID | 验收 |
|---|---|
| SQ01 | 验证版本、结构、引用、类型和强度时长边界，未覆盖绑定沿用原定义。 |
| SQ02 | 两种品质按配置改变实际属性和截止时间，先低后高与先高后低均刷新同一实例。 |
| SQ03 | 满值或校验失败不刷新。成功用药只扣该品质一份、改一次库存修订，重复请求不改截止。 |
| SQ04 | 本人收到施加、刷新和到期状态，队友不泄露。同局重连保留最新时限，按独立 ID 结算。 |
| SQ05 | 普通 Node 和 H5 跑通四人和八人不同顺序，核对两次恢复、实际属性、同实例及截止变更、到期与结算。 |
| SQ06 | Rust 和 Node 回归通过。空 Cargo 缓存离线交付与机制 65 默认状态兼容验证通过。 |
