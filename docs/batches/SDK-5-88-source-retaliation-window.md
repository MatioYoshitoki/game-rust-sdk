# 九阙封脉与受击反制窗口

本组归 DELIVERY-01。宿主以自身状态为载体配置 `combat_rules.status_retaliations`，选择反制概率、逐攻击来源的冷却、目标数上限、反制状态、驱散数量及可选到期状态。SDK 记录每个载体实例实际反制过的攻击者及代次。客户端沿用原施法、状态和伤害协议。

| 验收项 | 预期 |
|---|---|
| 五阶段 | 同一个瞬发自身技能消耗 4000000 灵力，冷却 60 秒，后摇 80 ms。8 秒载体按可信阶段选择。原表概率 40%，反封 2 秒，入门同来源冷却 5 秒，熟练起为 4 秒。 |
| 受击 | 普通敌对直接伤害实际扣血或消耗护盾且持有者存活时，按配置尝试反制。攻击来源、持有者和当前载体身份均由 Rust 裁决。失败、免控和目标记录达到上限时保留已有记录，成功才开始同来源冷却。 |
| 进阶 | 精通起反制成功后驱散该攻击者最多一个可驱散增益。大成起窗口内减伤 25%。圆满在达到期限的首个 World 步对已成功反制且仍有效的原代次攻击者施加 30% 减速，持续 2 秒。 |
| 生命周期 | 同源刷新开启新的记录窗口。同一 World 重连沿用原状态时钟和私有记录。持有者退出、死亡、载体移除及关局清除记录。到期效果遵守既有状态结束预算并跳过失效的攻击者代次。 |
| 配置 | 严格校验载体、反制与到期状态、冷却、概率、目标上限和驱散数量。旧配置沿用原伤害及状态路径。 |

原因子将反制挂在 `beforeBeAttack`。本组在实际伤害或护盾吸收结算后反制，持有者须存活。原规则对空命中及致死命中的处理待复核。反伤、周期伤害与独立资源转移沿用各自的结算路径。

样例以沉默表达原表的「封脉」，具体控制类型待复核。样例采用 SDK 的每实例 32 来源上限，常驻成长和真意另行验收。

将样例的 `skill` 加入基底的 `additional_skills`，把状态定义与各战斗配置表按 ID 合入，并为宿主事实配置足够的最大灵力和单次费用上限。可信阶段从 0 起算，依次对应原表的五阶段。 [配置样例](../../examples/combat-host/source-xianwang-jiufeng.json) · [验收基底](../../examples/combat-host/mastery-stages.json)
