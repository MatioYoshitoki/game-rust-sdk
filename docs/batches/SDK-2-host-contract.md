# SDK-2 接入契约与最小宿主

本批先冻结范围与验收，再实现。依据 PRD v1.33；使用现有样例验证 SDK 接入，跨游戏验收另行排期。

## 交付范围

1. 提供接入指南，逐项说明六个 Client 方法、配置初始化、输出与两类回执、身份、关闭及错误责任。
2. 审计公开 API、配置能力与游戏业务耦合，列出当前限制和后续兼容方案。协议 1 和现有冻结责任保持可读，本批不调整资产语义。
3. 明确开发期 Rust crate 与 JSONL 适配器的交付方式、版本维度和升级要求。
4. 增加独立 Cargo 消费方 `examples/minimal-host`，仅依赖公开 API，使用普通运行时时钟与现有配置。通过创建、读取事实、扣费、加入、发送全量、就绪、主动离开、死亡结算、关闭完成最短接入闭环。主动离开的结果由 Rust 判定。
5. 样例内存业务适配器按原 operation ID/冻结正文幂等处理，数量直接采用 Rust 请求；业务事实从独立 JSON 初始化。通过本地脚本玩家接收快照后才回报 Sent。样例只演示进程内责任；持久化接入继续遵守既有检查点、事务与 fencing 契约。

本批交付以接入链路为范围。完整战斗/撤离与持久重启已有 B1/B2 专项覆盖；第二款游戏、通用资产协议重构、发布仓库、生产存储、网络鉴权和容量门禁另行验收。

## 验收标准

| 编号 | 场景与通过条件 |
|---|---|
| SDK2-01 | 独立消费方可通过精确版本的 path dependency 构建；源码仅引用 `match_kernel` 公开 API，关闭 replay 特性；普通时钟完成入场、就绪、离开结算，最终一次扣费/结算、一个 Closed、World=0、未决操作=0。重复 Create/Input/业务回执/Close 不重复生效。 |
| SDK2-02 | 结算已提交但首次返回 Unknown，Rust 输出原业务查询，宿主查回同一提交证明；结算仅一次，未决清零。宿主不自行补发结算或返回未提交。 |
| SDK2-03 | 存储明确拒绝入场，账户不扣费、不发结算，关闭且无未决；拒绝被视为正常业务结果。 |
| SDK2-04 | 扣费后、CombatReady 前关闭，按原入场请求补偿一次，账户回到初值，不生成死亡奖励，未决清零。 |
| SDK2-05 | 首份全量发送 Failed，宿主不提交其 CombatReady；接收替代全量并返回 Sent 后才就绪，最终正常收尾。 |
| SDK2-06 | 错误 config_hash 创建被拒绝，且无业务输出；同一 Runtime 随后可用正确配置创建并完成闭环。 |
| SDK2-07 | 将消费方复制到仓库外临时目录，仅以 path dependency 引用 SDK；自有清单仅一个自定义默认别名，仍能构建运行，无 `b1` 别名依赖。配置 ID/hash 从已加载目录取得。 |
| SDK2-08 | 替换账户初始属性和库存 JSON，无需改源码即可完成闭环；宿主按原请求扣费/结算，机器证据记录场景、配置哈希、账本计数与最终责任数。接入指南覆盖游戏耦合、错误策略与版本兼容边界。 |

验收入口：`python3 scripts/verify_sdk_2.py`。实际执行记录绑定源码和配置哈希，未运行项保持待验。
