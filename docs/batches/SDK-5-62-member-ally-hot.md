# SDK-5-62 指定友方持续治疗

对应 R3.1、R3.3/M02/M04 及原行为规格 §4.3、§4.4、§5.1。目标 SDK 0.64.0、机制 79、schema 7、协议 6。沿用 `ally_heal` 和 `cast_unit`，通过 `hot_status` 指向一个已注册的 `periodic_heal` 定义，和即时治疗字段 `heal` 二选一。持续时间、每跳间隔和最大气血比例由状态定义提供。定义采用 `refresh` 和 `source_scoped: true`，友方 HOT 的溢出量舍弃。

同一 World 的另一名成员是唯一合法目标。接受和提交都重验身份代次、存活、就绪、保护、距离和视线。提交时预检目标状态容量。失败保持施法者费用与冷却。成功提交后将状态施加到目标，首跳等待配置间隔。每跳以施加时冻结的目标最大气血比例为基础，读取当时有效的目标受治疗倍率，向下取整后按气血缺口裁剪。施加后沿用已有周期节拍，距离和视线只用于施法，任一成员处于保护时消耗节拍并实回 0。

状态实例按目标、定义、来源实体分组。同来源重新施加保留实例身份并重置节拍，不同来源在同一目标上独立运行。状态快照只进目标的私有视图。施加、刷新、每跳和移除事件只发给来源和目标。来源退场立即移除其状态，原因是 `source_invalid`。目标退场立即移除挂在该目标上的状态，原因是 `target_invalid`。其他来源在其他有效关系上的状态继续按原节拍运行。

| ID | 验收 |
|---|---|
| AT01 | 机制 79 接受来源分组的刷新 HOT，拒绝旧机制、错误定义、非法重复策略、转盾及同时配置即时治疗。 |
| AT02 | 验证目标身份、距离和视线重验及目标状态容量。失败不扣费、不写冷却。 |
| AT03 | 验证目标每跳倍率、取整和缺口裁剪，保护跳过，双来源独立与同来源刷新。状态归目标，事件只发给来源和目标。 |
| AT04 | 普通时钟 Node 和 H5 验证四人同目标双来源，首轮各实回 110，P00 退出仅清其状态，P02 后续继续实回 110。八人验证首跳实回 100，目标退出后来源收到清理事件且没有后续跳，最终各成员结算一次。 |
| AT05 | 同一交付包通过仓库外空缓存离线接入、机制 78 指定友方即时治疗兼容复验、Rust 和 Node 回归。 |
